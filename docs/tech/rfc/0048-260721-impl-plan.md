# 48 - Implementation Plan

Companion to RFC 0048 (`0048-260721-client-connection-lifecycle.md`). Executes the whole
RFC, both phases, as **one commit in a single push** on branch
`sy-4493-robust-session-state-management-for-the-console` (PR #2612). Verification is
batched at the end; no per-workstream gates. Every file:line below was verified against
the branch during planning research.

# 0 - Ordering

Workstreams land in dependency order inside the one commit: x -> client -> pluto ->
console -> tests alongside each layer. Nothing is left half-wired; the commit is the
green boundary.

# 1 - Workstream X: breaker primitives

`x/ts/src/breaker/breaker.ts`:

1. Add `maxInterval` (cap on interval growth) and `jitter` (0-1 fraction) to
   `Config`/`breakerConfigZ` (`:52-63`), applied in `wait()` (`:33-40`): clamp
   `interval` after `mult(scale)`, add uniform jitter to the sleep. Defaults preserve
   current behavior (no cap, no jitter) so existing users are untouched.
2. Support `maxRetries: Infinity` cleanly (never-give-up default for the machine).
3. Spec: cap and jitter behavior in `breaker.spec.ts`.

# 2 - Workstream A: client/ts

## A1 - The machine (`src/connection/`)

New `machine.ts` replacing `checker.ts`; barrel `index.ts:10` re-exports the package.
Names: `connection.Machine`, `connection.State`, `connection.reasonZ`
(`"unreachable" | "auth" | "incompatible"`). State shape per RFC 5.0 (variant is the
standard status variant set; source the variant type from `@synnaxlabs/x`'s status
module if exported there, else define `variantZ` locally with the standard five values).
Surface: `state` (copy), `onChange(handler): Destructor`,
`await waitFor(predicate, timeout?)` (internal spine of `connect()`),
`reauthenticate(credentials)`, `retryNow()` (breaker reset), `stop()`.

Absorbed from `Checker` (`checker.ts:114-187`): the `/connectivity/check` probe,
clock-skew measurement via `ClockSkewCalculator` (`:127-141`), version compat + one-time
warn (`:142-168`). Killed: the observer array without unsubscribe (`:195-197`), the
never-assigned `"connecting"` status (`:21`), the 4-enum.

Transitions per RFC 5.0's table. Heartbeat cadence: adaptive, slow interval while
`success` with stream live, breaker-driven while degraded.
`warning -> error(unreachable)` fires when the first breaker budget exhausts; probing
continues on capped jittered backoff (never give up; a finite `retry.maxRetries` config
bounds it, per RFC principle 7). Warn-only version drift stays a fact + toast;
`error(incompatible)` is wired but unproduced today (no hard-rejection path exists; the
reason exists for when the server gains one).

## A2 - Wiring in the Synnax constructor (`src/client.ts:132-271`)

Construction order (the injection-order constraint from research):

1. Transport built at `:144`; machine constructed immediately after, before any
   middleware registration, taking `transport.unary`, resolved retry/cadence params, and
   `clientVersion`.
2. Short-circuit middleware registered on the **unary path only** at the `:149` site,
   closing over the machine: when
   `state.variant === "error" && state.reason === "unreachable"`, throw `Unreachable`
   immediately, skipping `unaryWithBreaker`'s retry loop
   (`freighter/ts/src/unary.ts:38-73`). It MUST exempt the machine's own probe target
   (`/connectivity/check`) by `ctx.target` match, or the probe can never heal the state.
   `warning` does not short-circuit (RFC 5.2a).
3. Auth (`:170-171`): `auth.Client` gains an outcome observer (ctor param) and a
   `setCredentials()` used by `reauthenticate`. It reports definitive login failure
   (`auth/auth.ts:118-119`, non-`RETRY_ON` errors, `MAX_RETRIES` exhaustion) and login
   success. The machine is the only consumer.
4. The cache `openStreamer` closure (`:152-168`): thread the resolved `retry` config
   into `HardenedStreamer.open` (the `undefined` at `:158`), and surface `onDrop` to the
   machine alongside the existing `onOpen`/`onReopen`.
5. After domain-client construction ends (`:270`, all cache tables exist, satisfying
   `cache.ts:77/:92`), the machine starts: first heartbeat, then, for `cache: true`, the
   internal stream bring-up (`cache.ensureStreaming()` called from inside the client
   only). `cache: false` runs the machine minus the stream feeder; `success` = authed +
   reachable.
6. `close()` (`:273-276`): `machine.stop()` + cache close; final state `disabled`.

The `connectivity` field (`:84`), `static connectivity` (`:109`), and
`newConnectionChecker` (`:287-293`) die. `checkConnection` (`:284`) survives with its
current signature, reimplemented as a one-shot probe (its consumers:
`useConnectModal.tsx:96`, `List.tsx:82`). New public property:
`client.connection: connection.Machine`.

## A3 - Doors

Instance `connect(opts?: { timeout?: TimeSpan })` on `Synnax`: awaits first `success`;
idempotent; rejects typed (`AuthError` subtype, incompatible, `Unreachable` after
budget/timeout); does not close. Module-level `connect` in `client.ts` beside
`checkConnection`: `new Synnax(params)` + instance connect; closes the client before
rejecting. Barrel: add to the `@/client` re-export block (`src/index.ts:19-26`); no name
collision exists.

## A4 - HardenedStreamer (`src/framer/streamer.ts:208-314`)

Add optional `onDrop` hook (fires when `read`/`update` fails and the reconnect loop
begins, `:273-281`, `:292-302`). Default breaker becomes never-give-up with capped
interval (replacing the 5000x1s constant, `:224-228`) unless a config is passed. Other
callers (`control/client.ts:23`, `pluto/src/telem/client/ client.ts:130`) pass no
hooks/config and keep working; their reconnect behavior changes only in that the
interval now caps instead of staying flat 1s forever.

## A5 - Consumers of the old surface inside client/ts

- `connection.spec.ts` rewritten as the machine spec (see Tests).
- `client.spec.ts:16-145` (`checkConnection` block adapts; `newConnectionChecker` block
  dies).
- ~14 domain spec files calling `client.cache.ensureStreaming()` in `beforeAll`
  (ranger:367,580; schematic:324; role:110; access:165; label:93,164;
  ontology:236,621,643; channel:375; table:630; lineplot:71,82; log:51) migrate to

## C2 - The takeover surface

New `feature/auth/ConnectionGuard.tsx` (in the auth feature, not cluster: it reuses
`Login` and `LoginNav`, and sibling-feature imports are banned). Two branches keyed on
the typed reason: `auth` at any warmth renders `<Login/>` itself (revised in review: a
separate credential form was Login with a different submit handler); cold `loading` or
`error(unreachable)` renders a full-screen takeover reusing `LoginNav`
(`feature/auth/LoginNav.tsx:17-30`) and `Cluster.List`
(`platform/cluster/list/List.tsx`) with cluster name/address, typed failure message,
live retry status from `state.retry` (attempt, next probe), and actions [Retry now ->
`client.connection.retryNow()`, Edit connection -> `useConnectModal`, Choose another
cluster -> cluster list (select dispatches as today), Log out].

`Login` serves both initial login and auth recovery: it preselects the active cluster,
prefills its username, and shows the live connection status when a client exists. Submit
stays intent-only (`Session.Cluster.set` + `select`), reusing the active session key so
the workspace survives; because a same-credentials resubmit changes no params and the
machine parks on auth errors, submit also nudges `client.reauthenticate(creds)` when
targeting the active cluster.

Mount: `app/window/Primary.tsx` inside `<Auth.Guard>` (`:46`), wrapping the
`<Project.Guard>` subtree (`:47-59`). Takes over when `error(auth)` at any warmth (the
user must act; nothing new can load; blocking is honest), or when cold
(`state.epoch === 0`; disk hydration does not exist yet, RFC §7) and `variant` is
`loading` or `error(unreachable)`. Cold `loading` is grace-gated (500ms of continuous
loading before the takeover mounts, children rendered meanwhile) so a fast connect never
flashes the takeover; `error(unreachable)` shows it immediately since escalation
outlasts any grace. `app/window/Secondary.tsx:24-32` mounts the same takeover (cold
means child windows have nothing renderable either); it renders without the main-window
chrome (`nav={false}`).

`Login.tsx` slims to intent-selection only: `Guard.tsx:15-16` still swaps in `<Login/>`
when no cluster is selected; the throwaway-client submit (`:84-92`) dies; selecting a
cluster + submitting credentials dispatches `set`/`select` and lets the
provider-constructed client's machine take over (the takeover surface shows `loading`
progress if first contact is slow).

# 6 - Verification gate (single, at the end)

1. Restart the test core: `pkill synnax; ./core/synnax start -mi` (fresh core before the
   full suite).
2. From root: `pnpm test:client`, `pnpm test:pluto`, `pnpm test:console`,
   `pnpm check-types`, `pnpm lint`, `pnpm madge`, prettier check.
3. Manual smoke in the dev console (user-run): cold start against a dead port ->
   takeover with live retry status; start core -> self-heal into the workspace; stop
   core mid-session -> badge degrades, cached panels intact; wrong persisted password ->
   auth takeover -> re-login lands back in place.

# 7 - Gotchas encoded from research

- The short-circuit middleware must exempt the probe target, or `error (unreachable)`
  can never heal.
- The machine must exist before middleware registration but starts only after domain
  construction (`client.ts:270`), so tables exist before streaming.
- `status.Variant` sourcing for client/ts must avoid a pluto dependency; verify the x
  export at implementation and define locally if absent.
- `HardenedStreamer`'s other two callers get the capped-interval default; do not thread
  machine hooks into them.
- `InvalidTokenError`/`ExpiredTokenError` are not barrel-exported; the auth observer
  works on the error instances internally, no new exports needed.
- Console credential persistence happens only on successful re-auth (user-initiated),
  never as a machine side effect.

# 8 - Compatibility

Breaking for external client consumers: `connectivity`/`Checker`/ `newConnectionChecker`
removed, `connection.State` reshaped, `connect` added, streamer reconnect defaults
changed (capped interval). Lands in the same release train as RFC 0046's client surface
rework; external consumers migrate once. Python/C++ clients unchanged (RFC §7).
