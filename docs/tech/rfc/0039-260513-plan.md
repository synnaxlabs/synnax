# Arc Function-Call Infrastructure: Implementation Plan

> **Companion to**
> [RFC 0039: Arc Function-Call Unification](0039-260513-arc-function-call-unification.md).
> This document is the action-oriented execution guide for an AI session implementing
> the RFC. The RFC carries design rationale; this plan tells you what to do, in what
> order, and how to verify each step. Where this plan and the RFC disagree, **the RFC
> wins**: update the plan to match.

## 0 - Quick Recap

Arc's type system today carries two parameter arrays on every function signature:
`Config` (read by the flow analyzer for the `{...}` brace block) and `Inputs` (read by
the expression analyzer for the `(...)` parens form). `ExecBoth` symbols mirror the same
list into both fields. The flow analyzer disambiguates wire-fed value from pure
activation via the heuristic `upstreamIsTrigger := Exec == ExecBoth && len(Config) > 0` —
which now lives in three sites with two divergent forms (the two flow.go sites key on
`len(Config) > 0`; `text/analyze.go` keys on `sym.AST == nil`). The `ExecBoth` symbols
today are `time.now`, `status.set`, and every user-defined function.

This refactor collapses both arrays into a single `Inputs` list. The `ExecBoth`
heuristic is replaced by an explicit `Trigger TriggerBinding` field on `Symbol` that
names which param (if any) receives the upstream wire's value in flow context.
User-facing Arc syntax is unchanged.

See [RFC §3](0039-260513-arc-function-call-unification.md#3---the-problem) for why the
split became debt and
[RFC §4](0039-260513-arc-function-call-unification.md#4---proposed-design) for the
unified design.

## 1 - Decision Summary (settled with user)

| Question                          | Decision                                                                                            |
| --------------------------------- | --------------------------------------------------------------------------------------------------- |
| Scope                             | Full unification at the type level                                                                  |
| Unified field name                | Keep `Inputs` (not rename to `Params`)                                                              |
| Wire-fed-param tracking           | Symbol-level `Trigger TriggerBinding` field                                                         |
| Optional params                   | `Optional bool` field on `Param` is a stub; every param is required in this RFC                     |
| Surface syntax                    | Unchanged. `name(...)`, `name{...}`, and `wire -> name{...}` all keep working                       |
| Wire-format compatibility         | Breaking. Codec migration translates pre-vN persisted programs into the unified shape               |
| Trigger-as-argument future syntax | Out of scope. The structural foundation must not preclude any firing-semantics policy               |
| Staging                           | One big PR with a review-and-evaluate gate after Phase 8                                            |
| Codec version stamp               | `vN` placeholder. The exact target version is fixed once the major release this ships with is named |

## 2 - Target Type Shape

Regenerated from `schemas/arc/types.oracle`:

```go
type FunctionProperties struct {
    Inputs  Params `json:"inputs"  msgpack:"inputs"`
    Outputs Params `json:"outputs" msgpack:"outputs"`
    // Config field removed. No replacement.
}

type Param struct {
    Name     string `json:"name"     msgpack:"name"`
    Type     Type   `json:"type"     msgpack:"type"`
    Value    any    `json:"value"    msgpack:"value"`
    Optional bool   `json:"optional" msgpack:"optional"` // Stub (RFC §8.1); set false everywhere
    // Internal-only AST field (json:"-") added by hand for diagnostics.
}
```

Param ordering is preserved as the user declared it; the migration appends the old
`Config` list before the old `Inputs` list to keep WASM ABI offsets stable.

## 3 - Target Symbol Shape

```go
type TriggerBinding struct {
    // Target names the param that receives the upstream wire's value in flow
    // context. Empty means the wire is pure activation (no value bound).
    Target string
}

var TriggerOnly = TriggerBinding{}
func TriggerInput(name string) TriggerBinding { return TriggerBinding{Target: name} }

type Symbol struct {
    // ... existing fields ...
    Trigger TriggerBinding
}
```

**Trigger.Target invariant:** if non-empty, must name an existing param on the same
symbol's Inputs list. Enforced by a unit test in
[arc/go/stl/stl_test.go](../../../arc/go/stl/stl_test.go) that walks every registered
symbol across the stdlib and service-layer resolvers and asserts the target resolves.
The failure mode (target points at a deleted/renamed param) surfaces at `go test` time.
Resolvers initialize as static literals; there is no runtime constructor to hook a
startup check into.

## 4 - Target Trigger Assignments

The per-symbol Trigger assignments, including the stdlib / service-layer split and the
mixed-shape symbols that need concat-then-trigger, live in
[RFC §4.1](0039-260513-arc-function-call-unification.md#41---explicit-trigger-binding).
That table is the source of truth; this plan does not duplicate it.

ExecWASM-only symbols (`math.pow`, `series.*`, `string.*`, `state.*`, `error.panic`)
leave `Trigger` at the zero value; the runtime never consults `Trigger` for symbols that
can't appear in flow context, and the registration test accommodates an empty target.

User-defined functions are auto-assigned in `function.go`:
`TriggerInput(<first parens-block param>)` if a parens block is present, else
`TriggerOnly`. No per-symbol audit needed.

## 5 - Implementation Sequence

The implementation runs in two halves separated by a **review-and-evaluate gate**.
Phases 0-8 are all hand-written productive code. Phases 9-13 are mechanical (schema
sync, full codegen, integration). The gate exists so the reviewer can read the
hand-written diff in isolation before generated noise enters.

### Phase 0: Snapshot pre-refactor types for migration

Mechanical move. Lock the current shape under a version stamp so the Phase 8 migrator
has a stable "from" shape to reference.

Copy four current generated files into the migration directories:

- `arc/go/types/types.gen.go` → `arc/go/types/migrations/vN/types.gen.go`
- `arc/go/types/codec.gen.go` → `arc/go/types/migrations/vN/codec.gen.go`
- `arc/go/ir/types.gen.go` → `arc/go/ir/migrations/vN/types.gen.go`
- `arc/go/ir/codec.gen.go` → `arc/go/ir/migrations/vN/codec.gen.go`

Frozen; never regenerates. The oracle will regenerate these in Phase 10 alongside a
`migrate_auto.gen.go` that does 1:1 field mapping; the manual snapshot exists so Phase 8
can reference the frozen pre-refactor shape while writing hand-written merge logic
before the gate.

### Phase 3: Analyzer collapse

The main payoff. See
[RFC §4.2](0039-260513-arc-function-call-unification.md#42---unified-call-analyzer) for
the `call.Analyze` signature and
[RFC §4.4](0039-260513-arc-function-call-unification.md#44---flow-analyzer-collapse) for
the upstream-handling collapse.

- `arc/go/analyzer/call/call.go` (new): `Argument` struct and `Analyze` function. **No
  `Form` parameter.** Whether each arg matches by name or index is derivable from
  `args[i].Name != ""`.
- `arc/go/analyzer/expression/expression.go`: replace `validateFunctionCall(...)` with
  `call.Analyze(...)`. Delete the body of `validateFunctionCall`.
- `arc/go/analyzer/flow/flow.go`: replace `validateFuncConfig(...)` with
  `call.Analyze(...)`. Delete the body. Replace the `upstreamIsTrigger` heuristic and
  the three-branch `prevIDNode` / `prevExpr` / `prevFuncNode` block with a direct
  `fn.Trigger` consult per RFC §4.4.
- `arc/go/analyzer/flow/expression.go`: same `call.Analyze` replacement at routing-table
  sites.
- `arc/go/analyzer/function/function.go`: collapse the brace-block and parens-block
  declaration walkers into one pass that appends both into a single `Inputs` slice. The
  parens-block first param (if any) becomes `Trigger.Target`. The "optional after
  required" rule applies independently within each grammar block. Collapse
  `addConfigToScope` and `addInputsToScope` into one scope-add pass over `Inputs` (the
  symbol `Kind` distinction stays via the block the param came from; track it locally).
- `arc/go/analyzer/resolve.go`: drop Config substitution loop.

### Phase 4: Downstream consumers

- `arc/go/compiler/compiler.go`: `slices.Concat(i.Config, i.Inputs)` → `i.Inputs`.
- `arc/go/compiler/expression/compiler.go`: already reads `funcType.Inputs`; verify no
  Config reads remain.
- `arc/go/graph/analyze.go`: merge Config+Inputs bindParams; IR node construction emits
  a single Inputs list.
- `arc/go/text/analyze.go`: `Config:` field assignments → `Inputs:`; delete the
  `upstreamIsTrigger` special case.
- `arc/go/runtime/node/state.go`: iterate `Inputs` directly for edge alignment.
- `arc/go/ir/function.go` and `arc/go/ir/node.go`: drop the Config rendering branch from
  `Type()` and string output. IR rendering still distinguishes the brace vs parens
  blocks at print time, but the source-of-truth is the unified Inputs list plus the
  symbol's `Trigger`.

### Phase 5: Stdlib, LSP, service layer

The most visible win. Each stdlib symbol gains exactly one `Trigger:` line.

**Stdlib symbol declarations:**

- `arc/go/stl/{time,stable,channel,authority,math,constant,op,series,selector,strings,stateful,errors,wasm}/*.go`:
  collapse `Config:` and `Inputs:` field assignments into a single `Inputs:`. Add
  explicit `Trigger:` per symbol per the audit table in Section 4. For mirror-trick
  `ExecBoth` symbols (`time.now`, `status.set`), the duplicate list deduplicates to a
  single `Inputs:` list.
- Factory call sites that read `cfg.Node.Config.ValueMap()` or
  `cfg.Node.Config.Get(...)`: become `cfg.Node.Inputs.ValueMap()` and
  `cfg.Node.Inputs.Get(...)`.
- `arc/go/stl/wasm/wasm.go`: any `len(Config)` becomes `len(Inputs)` (or whatever the
  WASM ABI surface needs from the unified list).

**Stdlib test invariants (`arc/go/stl/stl_test.go`):**

- DELETE the existing "ExecBoth structural contract" mirroring test (the
  Inputs-mirrors-Config invariant is no longer expressible).
- ADD: `AnalyzeArguments` hooks are only attached to `KindFunction` symbols.
- ADD: `Trigger.Target`, if non-empty, names an existing param on the symbol's Inputs.

**LSP:**

- `arc/go/lsp/hover.go`: render the unified Inputs list. Show `Trigger.Target` in hover
  output where set.
- `arc/go/lsp/completion.go`: propose named-config keys from the same Inputs list.

**Service layer (the visible win):**

- `core/pkg/service/arc/status/status.go`:
  - Declare the `newSetSymbolType` param list once; assign only to `Inputs`.
  - Drop the dual hook registration; register a single `AnalyzeArguments` hook (see
    [RFC §4.3](0039-260513-arc-function-call-unification.md#43---unified-hook) for the
    collapsed body).
  - Set `Trigger: TriggerOnly`.
  - `cfg.Node.Config.ValueMap()` → `cfg.Node.Inputs.ValueMap()`.

New tests required by this change (added in the appropriate test files):

- `call.Analyze` shared validation: argument count, type, name resolution, unknown-name
  detection, duplicate-name detection, verified once against both parens and brace
  surface forms.
- Trigger consult: flow call to a `TriggerOnly` symbol does not type-check the upstream;
  flow call to a `TriggerInput("x")` symbol type-checks the upstream against the `x`
  param's type and rejects mismatches.
- Trigger invariant: the `stl_test.go` walker fails when a symbol declares
  `Trigger.Target = "missing_param"`. Add a negative-case fixture proving the walker
  catches it.
- `status.set` collapse: the `AnalyzeArguments` hook fires correctly for both
  `status.set(..., "errpr")` and `status.set{variant="errpr"}`, emitting one diagnostic
  per call site.

### Phase 8: Codec migration logic

Hand-write the merge logic that auto-generated `migrate_auto.gen.go` (produced by Phase
10 codegen) cannot infer.

**IR side (required hand-written work):**

- `arc/go/ir/migrations/vN/migrate.go`: provide `MigrateFunction` and `MigrateNode`
  overrides that wrap the auto-mapper and merge the old `Config + Inputs` lists into the
  unified `Inputs` list. Append old `Config` before old `Inputs` to preserve the WASM
  ABI ordering the compiler concat already produces today. For stdlib `ExecBoth` symbols
  where `Config == Inputs` (the mirror trick), detect the duplicate and dedupe to a
  single list.
- `arc/go/ir/migrations/vN/migrate_test.go`: round-trip pre-vN IR JSON / msgpack / proto
  through the migrator and assert the resulting IR Type-shape matches what a fresh
  declaration in the new shape produces.

**Types side:**

The types-side migration directory contains only the codec snapshot from Phase 0. No
hand-written `migrate.go` is needed because the auto-mapper can do everything the types
side needs (no Config-to-Inputs merge: types are referenced by IR, not stored
independently in persisted Arc programs).

**Note:** Phase 8's `migrate.go` calls `AutoMigrateFunction`, which doesn't exist until
Phase 10 codegen produces `migrate_auto.gen.go`. The branch does not compile from
**Phase 1 onward**: every analyzer/compiler/stdlib reader of `.Config` breaks the moment
Phase 1 removes the field, and stays broken until Phase 5 finishes converting them.
That's intentional: the gate is timed to "the hand-written productive diff is done," not
to "the branch builds." Phases 9-10 close the loop via schema sync and codegen.

## 7 - Risks and Open Questions

1. **Pluto direct IR construction.** Some tile components may construct `ir.Node` with
   `config:` literals. Phase 13 grep finds them; the migration is mechanical.
2. **WASM ABI ordering.** WASM offsets in
   [arc/go/stl/wasm/wasm.go](../../../arc/go/stl/wasm/wasm.go) depend on the order the
   compiler concat already produces (`Config` first, then `Inputs`). The Phase 8
   migration appends in that same order, so offsets stay stable. The Phase 8 round-trip
   test verifies byte-equal IR for the same source.
3. **Hook ctx type-assertion.** Today's hooks switch on the concrete
   `acontext.Context[T]` type. The unified `AnalyzeArguments` keeps `ctx any` for this
   PR (smallest diff). A `DiagBearer` interface would be cleaner long-term but is out of
   scope.
4. **Codec version bump.** The exact `vN` value is fixed once the major release this
   refactor ships with is named. Search `git log` of `arc/go/ir/codec.gen.go` for past
   bump triggers if the convention is unclear.
5. **`paramsEqual` semantics.** Single-line `Equal`/`paramsEqual` update against the
   single Inputs list; easy to miss in code review. Flag explicitly when reviewing
   Phase 2.
