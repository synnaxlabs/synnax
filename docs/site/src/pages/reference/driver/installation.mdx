The Synnax Driver can also run as a separate binary on its own machine. This lets one
Synnax deployment integrate data acquisition hardware from many host machines.

### Prerequisites

#### Supported Hardware & Software

The Synnax Driver supports the cRIO-904x and cRIO-905x families of controllers running
NI Linux Real-Time 2024 Q1 and later.

#### NI-DAQmx Programming Mode

Data acquisition hardware connected to the cRIO must be configured to use the NI-DAQmx
real-time programming mode.

To change the programming mode, use NI Measurement & Automation Explorer (NI MAX). For
detailed instructions, see the
[NI CompactRIO User Manual](https://www.ni.com/docs/en-US/bundle/ni-compactrio/page/programming-modes.html)
and the
[NI-DAQmx on CompactRIO](https://www.ni.com/en/shop/compactrio/what-are-compactrio-controllers/what-is-compactrio-with-ni-daqmx-.html)
guide.

#### SSH Access

The Driver is installed over an SSH connection to the cRIO. You can disable SSH after
installation, but keeping it enabled makes updates and management easier.

#### Network Available Synnax Core

The Driver must be able to reach a Synnax Core over the network. Make sure you have a
[Core running](/reference/core/quick-start) and its connection parameters on hand.

### Install and Run the Driver

Download the latest binary:

<DriverDownloadURL os="linux" />

Move the binary into a directory on your `PATH`. Most of our users use `/usr/local/bin`:

<DriverMoveCommand os="linux" />

Give the binary execute permission. You may need `sudo` for this command:

```bash
chmod +x /usr/local/bin/synnax-driver
```

If running `synnax-driver` returns "command not found", make sure the directory you
chose is on your `PATH`.

Install and start the Driver as a systemd service:

```bash
sudo synnax-driver install
sudo synnax-driver start
```

The `install` command copies the binary to `/usr/local/bin` if it is not already there,
creates a `synnax` system user, and registers the `synnax-driver` service.

To verify the installation, run:

```bash
synnax-driver version
```

You should see the following output:

### Install and Run the Driver

Download the latest Synnax Driver executable for Windows:

<DriverDownloadURL os="windows" />

After downloading, move the `synnax-driver.exe` file to a location on your system, such
as `C:\Program Files\Synnax\`.

To make the Driver accessible from any command prompt, add the directory to your
system's `PATH`:

1. Open the Start menu and search for "Environment Variables"
2. Click "Edit the system environment variables"
3. Click the "Environment Variables" button
4. Under "System variables", find and select "Path", then click "Edit"
5. Click "New" and add the directory containing `synnax-driver.exe`
6. Click "OK" to save

To verify the installation, open a new PowerShell terminal and run:

```powershell
synnax-driver version
```

The Driver runs in the foreground on Windows. Start it with:

```powershell
synnax-driver start --standalone
```

## <Step step="2" level="h2">Connect to the Synnax Core</Step>

To connect to a Core, you need its address, port, username, and password. Run the
`synnax-driver login` command, with `sudo` on Linux:

```bash
synnax-driver login
```

The command prompts for the Core's connection parameters, checks that the Core is
reachable, then logs in and saves the credentials:

```
synnax-driver login
Host [localhost]: 10.0.0.45
Port [9090]: 9090
Secure (Y/N) [N]: N
I20260915 10:12:04.118427 41820 login.cpp:32] connection established.
Username: synnax
Password:
I20260915 10:12:09.601240 41820 login.cpp:43] successfully logged in!
I20260915 10:12:09.602113 41820 login.cpp:48] credentials saved successfully!
I20260915 10:12:09.602150 41820 login.cpp:50] start driver: synnax-driver start -s
```

### Connecting to a Secure Core

Answer `Y` to the `Secure` prompt when the Core uses TLS. The Driver verifies the Core's
certificate against the operating system's trust store, so a certificate from a public
authority such as Let's Encrypt needs no further setup. Connect using the host name the
certificate was issued for, not an IP address.

A Core started with `--auto-cert` serves a self-signed certificate. Install its CA
certificate on the Driver's machine by following the
[installing certificates](/reference/core/installing-certificates) guide. On a machine
where you can't change the trust store, point gRPC at the CA file instead:

```bash
export GRPC_DEFAULT_SSL_ROOTS_FILE_PATH=/path/to/ca.crt
```

## <Step step="3" level="h2">Check the Driver Status</Step>

As a final step, check the Driver's status:

```bash
synnax-driver status
```

On Linux this prints the `systemctl status` of the `synnax-driver` service. On NI Linux
Real-Time it prints whether the Driver is running and its process ID:

```
Synnax Driver is running (PID: 28191)
```

On Windows and macOS the Driver runs in the foreground, so its terminal output is its
status.

## Configuration Methods

Besides the `synnax-driver login` command, the Driver reads its configuration from
command line flags, environment variables, and a configuration file.

### Precedence

Earlier sources override later ones:

1. Command line arguments (Highest)
2. Environment variables
3. Configuration file
4. Persisted state, written by `synnax-driver login` and by the Driver itself
5. Internal defaults (Lowest)

The persisted state file holds the connection parameters saved by `login` and the
identity of the rack the Driver last attached to. It lives at
`/var/lib/synnax-driver/persisted-state.json` on Linux,
`%LOCALAPPDATA%\synnax-driver\persisted-state.json` on Windows, and
`~/Library/Application Support/synnax-driver/persisted-state.json` on macOS. Use the
`--state-file` flag to move it.

### Configuration File

Pass a JSON file with the `--config` flag. Every key is optional and has the same
meaning as the flag of the same name in the [CLI reference](#cli-reference). The file
must not contain comments.

```json
{
  "connection": {
    "host": "localhost",
    "port": 9090,
    "username": "synnax",
    "password": "password",
    "secure": false
  },
  "timing": {
    "correct_skew": true
  },
  "manager": {
    "op_timeout": 60,
    "poll_interval": 1,
    "shutdown_timeout": 30,
    "worker_count": 4
  },
  "remote_info": {
    "rack_key": 0,
    "cluster_key": ""
  },
  "integrations": ["arc", "ethercat", "http", "labjack", "modbus", "ni", "opc"]
}
```

The `integrations` list replaces the default set. Omit `remote_info` to let the Driver
create a rack on first start and remember it in the persisted state file.

### Environment Variables

Every configuration key is also readable from an environment variable named
`SYNNAX_DRIVER_` followed by the key in upper case. Integrations can't be set from the
environment.

```bash
# The host of the Synnax Core.
export SYNNAX_DRIVER_HOST=localhost
# The port of the Synnax Core.
export SYNNAX_DRIVER_PORT=9090
# The username to use when logging in to the Synnax Core.
export SYNNAX_DRIVER_USERNAME=synnax
# The password to use when logging in to the Synnax Core.
export SYNNAX_DRIVER_PASSWORD=password
# Whether to connect to the Synnax Core over TLS.
export SYNNAX_DRIVER_SECURE=false
# Enable automatic clock skew correction for the Driver.
export SYNNAX_DRIVER_CORRECT_SKEW=true
# Duration in seconds before reporting stuck task operations.
export SYNNAX_DRIVER_OP_TIMEOUT=60
# Interval in seconds between task timeout checks.
export SYNNAX_DRIVER_POLL_INTERVAL=1
# Maximum time in seconds to wait for task workers during shutdown.
export SYNNAX_DRIVER_SHUTDOWN_TIMEOUT=30
# Number of worker threads for task operations (1-64).
export SYNNAX_DRIVER_WORKER_COUNT=4
# The key of an existing rack in the Core to attach to.
export SYNNAX_DRIVER_RACK_KEY=0
# The key of the Core that owns the rack.
export SYNNAX_DRIVER_CLUSTER_KEY=
```

## CLI Reference

The service commands (`install`, `uninstall`, `stop`, `restart`, `status`, and `logs`)
are only available on Linux and NI Linux Real-Time. On Linux, run them with `sudo`. On
Windows and macOS, run the Driver in the foreground with
`synnax-driver start --standalone` and stop it with Ctrl+C.

### Start

The `start` command starts the installed Driver service. With the `--standalone` flag,
it runs the Driver in the foreground, which is the only mode on Windows and macOS.

#### Example Usage

```bash
synnax-driver start
```

To run in the foreground instead:

```bash
synnax-driver start --standalone
```

### Stop

The `stop` command stops the Driver service. If the Driver is running in the foreground,
press Ctrl+C instead.

#### Example Usage

```bash
synnax-driver stop
```

### Restart

The `restart` command restarts the Driver. This is equivalent to stopping and then
starting the Driver.

#### Example Usage

```bash
synnax-driver restart
```

### Login

The `login` command saves the connection parameters for a Synnax Core. On Linux, run it
with `sudo`. If the Driver is already running, restart it to apply the new credentials.

#### Example Usage

```bash
synnax-driver login
```

The command prompts for the Core's connection parameters:

```
synnax-driver login
Host [localhost]: 10.0.0.45
Port [9090]: 9090
Secure (Y/N) [N]: N
Username: synnax
Password:
```

### Clear

The `clear` command clears the persisted state file: the connection parameters saved by
the `login` command and the cached rack identity. The next start creates a new rack. On
Linux, run it with `sudo`.

#### Example Usage

```bash
synnax-driver clear
```

### Status

The `status` command prints the Driver's status to the console.

#### Example Usage

```bash
synnax-driver status
```

### Uninstall

The `uninstall` command removes the service. The binary and the `synnax` user are kept.
On Windows and macOS, delete the binary instead.

#### Example Usage

```bash
synnax-driver uninstall
```

### Logs

The `logs` command streams the Driver's logs to the console until you press Ctrl+C.

#### Example Usage

```bash
synnax-driver logs
```

### Version

The `version` command prints the Driver's version to the console.

#### Example Usage

```bash
synnax-driver version
```
