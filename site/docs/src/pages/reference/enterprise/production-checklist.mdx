Before you use a Synnax Core for real tests, check each item below. Each item links to
the page with the steps.

<Divider.Divider x />

## Checklist

1. **Hardware and network** -> the computer meets the
   [requirements](/reference/enterprise/requirements) for your channels and sample
   rates. The firewall opens only the Core port, because the Core binds it on every
   network interface.
2. **License** -> the license is active, and you know how to renew it. If you start the
   Core with a key file, replace the file when you renew. See
   [Activate a license](/reference/enterprise/license#renew-or-replace-a-license).
3. **TLS** -> the Core serves a certificate for the name that clients use, and every
   client trusts it. See [Set up TLS](/reference/enterprise/tls).
4. **Root password** -> the Core starts with a `--password` that is not `seldon`. See
   [the root user](/reference/enterprise/users#the-root-user).
5. **Users** -> each person has their own user, with the role that has the fewest
   permissions they need. See [Users](/reference/enterprise/users).
6. **Service** -> the Core runs as a service that starts at boot, stops with `SIGINT`,
   and uses absolute paths for its data and logs. See
   [Run the Core as a service](/reference/enterprise/service).
7. **Monitoring** -> a monitor polls the health check, and an alert fires before the
   data disk fills. The Core does not start with `--debug`. See
   [Monitor the Core](/reference/enterprise/service#monitor-the-core).
8. **Backups** -> you copy the data folder on a schedule while the Core is stopped, and
   before each upgrade. The Core has no online backup. See
   [Upgrade the Core](/reference/enterprise/upgrade#before-you-upgrade).
9. **Clock** -> the computer syncs its clock with NTP. A clock that moves back more than
   24 hours stops a license with an expiry date from applying.
