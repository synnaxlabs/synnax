Most deployments use the [embedded Synnax Driver](/reference/hardware), which runs
inside the Synnax Core. This page covers the standalone Driver: a separate binary that
connects hardware on other machines to one Core.

### Prerequisites

#### Supported hardware and software

The Synnax Driver supports the cRIO-904x and cRIO-905x families of controllers running
NI Linux Real-Time 2024 Q1 and later.

#### NI-DAQmx programming mode

Data acquisition hardware connected to the cRIO must be configured to use the NI-DAQmx
real-time programming mode.

To change the programming mode, use NI Measurement & Automation Explorer (NI MAX). For
detailed instructions, see the
[NI CompactRIO User Manual](https://www.ni.com/docs/en-US/bundle/ni-compactrio/page/programming-modes.html)
and the
[NI-DAQmx on CompactRIO](https://www.ni.com/en/shop/compactrio/what-are-compactrio-controllers/what-is-compactrio-with-ni-daqmx-.html)
guide.

#### SSH access

The Driver is installed over an SSH connection to the cRIO. You can disable SSH after
installation, but keeping it enabled makes updates and management easier.

#### Network access to a Synnax Core

The Driver must be able to reach a Synnax Core over the network. Make sure you have a
[Core running](/reference/enterprise) and its connection parameters on hand.

### Install and run the Driver

Download the latest binary:

<DriverDownloadURL os="linux" />

Move the binary into a directory on your `PATH`. Most of our users use `/usr/local/bin`:

<DriverMoveCommand os="linux" />

Give the binary execute permission. You may need `sudo` for this command:

```bash
chmod +x /usr/local/bin/synnax-driver
```

If running `synnax-driver` returns "command not found", make sure the directory you
chose is on your `PATH`.

Install and start the Driver as a systemd service:

```bash
sudo synnax-driver install
sudo synnax-driver start
```

The `install` command copies the binary to `/usr/local/bin` if it is not already there,
creates a `synnax` system user, and registers the `synnax-driver` service.

To verify the installation, run:

```bash
synnax-driver version
```

You should see the following output:

### Install and run the Driver

Download the latest Synnax Driver executable for Windows:

<DriverDownloadURL os="windows" />

Move `synnax-driver.exe` to a permanent location, such as `C:\Program Files\Synnax\`.

To run the Driver from any terminal, add that directory to your system's `PATH`:

1. Open the Start menu and search for "Environment Variables"
2. Click "Edit the system environment variables"
3. Click the "Environment Variables" button
4. Under "System variables", find and select "Path", then click "Edit"
5. Click "New" and add the directory containing `synnax-driver.exe`
6. Click "OK" to save

To verify the installation, open a new PowerShell terminal and run:

```powershell
synnax-driver version
```

The Driver runs in the foreground on Windows. Start it with:

```powershell
synnax-driver start --standalone
```

## <Step step="2" level="h2">Connect to the Synnax Core</Step>

To connect to a Core, you need its address, port, username, and password. Run the
`synnax-driver login` command, with `sudo` on Linux:

```bash
synnax-driver login
```

The command prompts for the Core's connection parameters, checks that the Core is
reachable, then logs in and saves the credentials:

```
synnax-driver login
Host [localhost]: 10.0.0.45
Port [9090]: 9090
Secure (Y/N) [N]: N
I20260915 10:12:04.118427 41820 login.cpp:32] connection established.
Username: synnax
Password:
I20260915 10:12:09.601240 41820 login.cpp:43] successfully logged in!
I20260915 10:12:09.602113 41820 login.cpp:48] credentials saved successfully!
I20260915 10:12:09.602150 41820 login.cpp:50] start driver: synnax-driver start -s
```

### Connecting to a secure Core

Answer `Y` to the `Secure` prompt when the Core uses TLS. The Driver verifies the Core's
certificate against the operating system's trust store, so a certificate from a public
authority such as Let's Encrypt needs no further setup. Connect using the host name the
certificate was issued for, not an IP address.

A Core started with `--auto-cert` serves a self-signed certificate. Install its CA
certificate on the Driver's machine by following the
[installing certificates](/reference/enterprise/certificates) guide. On a machine where
you can't change the trust store, point the Driver at the CA file through its
environment instead. On Linux and NI Linux Real-Time, add the line to the
[environment file](/reference/enterprise/driver/configuration#environment-file) at
`/etc/synnax/driver.env` before you run `login`:

```bash
GRPC_DEFAULT_SSL_ROOTS_FILE_PATH=/path/to/ca.crt
```

The service and `login` read that file, so the setting applies to the login check and to
the service. For a foreground `start --standalone`, and on Windows and macOS where there
is no environment file, export the variable in the shell that runs `synnax-driver`.

## <Step step="3" level="h2">Check the Driver status</Step>

As a final step, check the Driver's status:

```bash
synnax-driver status
```

On Linux this prints the `systemctl status` of the `synnax-driver` service. On NI Linux
Real-Time it prints whether the Driver is running and its process ID:

```
Synnax Driver is running (PID: 28191)
```

On Windows and macOS the Driver runs in the foreground, so its terminal output is its
status.
