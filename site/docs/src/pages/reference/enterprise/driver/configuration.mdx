The `synnax-driver login` command sets how the Driver connects to the Core. The Driver
also reads its configuration from command line flags, environment variables, and a
configuration file.

<Divider.Divider x />

## Precedence

Earlier sources override later ones:

1. Command line arguments
2. Environment variables
3. The environment file, on Linux and NI Linux Real-Time
4. Configuration file
5. Persisted state, written by `synnax-driver login` and by the Driver itself
6. Internal defaults

The persisted state file holds the connection parameters saved by `login` and the
identity of the rack the Driver last attached to. It lives at
`/var/lib/synnax-driver/persisted-state.json` on Linux,
`%LOCALAPPDATA%\synnax-driver\persisted-state.json` on Windows, and
`~/Library/Application Support/synnax-driver/persisted-state.json` on macOS. Use the
`--state-file` flag to move it.

<Divider.Divider x />

## Environment file

On Linux and NI Linux Real-Time, the service and the `login` command read
`/etc/synnax/driver.env` and set each `KEY=VALUE` pair it names. For `login`, a variable
already in your environment wins. The file is optional. Only root can read it, so run
`login` with `sudo`.

`start --standalone` does not read the file. For a foreground run, set the variables in
your shell:

```bash
export GRPC_DEFAULT_SSL_ROOTS_FILE_PATH=/path/to/ca.crt
synnax-driver start --standalone
```

## Configuration file

Pass a JSON file with the `--config` flag. Every key is optional and has the same
meaning as the flag of the same name in the
[CLI reference](/reference/enterprise/driver/cli-reference). The file must not contain
comments.

```json
{
  "connection": {
    "host": "localhost",
    "port": 9090,
    "username": "synnax",
    "password": "password",
    "secure": false
  },
  "timing": {
    "correct_skew": true
  },
  "manager": {
    "op_timeout": 60,
    "poll_interval": 1,
    "shutdown_timeout": 30,
    "worker_count": 4
  },
  "remote_info": {
    "rack_key": 65537,
    "cluster_key": "6f2c7a1e-3b9d-4c58-9e21-0d8f5a7b3c44"
  },
  "integrations": ["arc", "ethercat", "http", "labjack", "modbus", "ni", "opc"]
}
```

The `integrations` list replaces the default set. Omit `remote_info` to let the Driver
create a rack on first start and remember it in the persisted state file.

## Environment variables

Every configuration key is also readable from an environment variable named
`SYNNAX_DRIVER_` followed by the key in upper case. Integrations can't be set from the
environment.

The Linux and NI Linux Real-Time service does not inherit your shell. It reads
`/etc/synnax/driver.env`, one `KEY=value` per line, each time it starts. Lines start
with the variable name, with no `export`. The `install` command creates the file, owned
by root with mode `600`, so only root can read the password in it. Edit it with `sudo`
and restart the service after editing it.

```bash
# The host of the Synnax Core.
SYNNAX_DRIVER_HOST=localhost
# The port of the Synnax Core.
SYNNAX_DRIVER_PORT=9090
# The username to use when logging in to the Synnax Core.
SYNNAX_DRIVER_USERNAME=synnax
# The password to use when logging in to the Synnax Core.
SYNNAX_DRIVER_PASSWORD=password
# Whether to connect to the Synnax Core over TLS.
SYNNAX_DRIVER_SECURE=false
# Enable automatic clock skew correction for the Driver.
SYNNAX_DRIVER_CORRECT_SKEW=true
# Duration in seconds before reporting stuck task operations.
SYNNAX_DRIVER_OP_TIMEOUT=60
# Interval in seconds between task timeout checks.
SYNNAX_DRIVER_POLL_INTERVAL=1
# Maximum time in seconds to wait for task workers during shutdown.
SYNNAX_DRIVER_SHUTDOWN_TIMEOUT=30
# Number of worker threads for task operations (1-64).
SYNNAX_DRIVER_WORKER_COUNT=4
# The key of an existing rack in the Core to attach to.
SYNNAX_DRIVER_RACK_KEY=65537
# The key of the Core that owns the rack.
SYNNAX_DRIVER_CLUSTER_KEY=6f2c7a1e-3b9d-4c58-9e21-0d8f5a7b3c44
```
