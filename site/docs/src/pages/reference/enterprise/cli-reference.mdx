The `synnax` command starts and manages a Synnax Core. This page lists its commands,
flags, environment variables, and configuration file keys.

<Divider.Divider x />

## Start

The `start` command starts the Synnax Core.

### Examples

#### Starting a Core

Use the `-i` and `-m` flags to start a Core in insecure mode with an in-memory data
store:

```cmd
synnax start -l localhost:9090 -im
```

### Flags

You can also set each flag with its environment variable. A flag on the command line
takes precedence over its environment variable.

<Field.List>

<Field.Item name="--listen" short="-l" type="address" default='"localhost:9090"' env="SYNNAX_LISTEN">

A reachable address and port to listen on for client connections and RPCs from other
Cores. To bind more than one address, each with its own certificate, give a list of
listeners in a [configuration file](#configuration-files). See
[Serving multiple listeners](/reference/enterprise/production#serving-multiple-listeners).

</Field.Item>

<Field.Item name="--peers" short="-p" type="list" env="SYNNAX_PEERS">

A comma-separated list of peer Cores in an existing cluster. If the list is not empty,
the Core joins the cluster by connecting to each peer in the list. If the list is empty
and the Core finds no existing cluster data, it starts a new cluster.

</Field.Item>

<Field.Item name="--data" short="-d" type="path" default='"synnax-data"' env="SYNNAX_DATA">

The folder where the Core keeps its data.

</Field.Item>

<Field.Item name="--verbose" short="-v" env="SYNNAX_VERBOSE">

Enables human-readable logging.

</Field.Item>

<Field.Item name="--insecure" short="-i" env="SYNNAX_INSECURE">

Starts the Core without TLS encryption. Do not use it in production.

</Field.Item>

<Field.Item name="--mem" short="-m" env="SYNNAX_MEM">

Keeps all data in memory. The Core writes nothing to disk, and loses all data when it
stops. Use it for tests and development, not for production.

</Field.Item>

<Field.Item name="--help" short="-h">

Prints the help message for the `start` command.

</Field.Item>

<Field.Item name="--config" short="-c" type="path" default='"/usr/local/synnax/config.yaml"' env="SYNNAX_CONFIG">

A JSON, YAML, or TOML file that sets the Core's configuration in place of flags or
environment variables. See [Configuration files](#configuration-files).

</Field.Item>

<Field.Item name="--auto-cert" env="SYNNAX_AUTO_CERT">

Generates self-signed certificates for the Core.

</Field.Item>

<Field.Item name="--certs-dir" type="path" default='"/usr/local/synnax/certs"' env="SYNNAX_CERTS_DIR">

The folder that holds the TLS certificates of the Core.

</Field.Item>

<Field.Item name="--ca-cert" type="path" default='"ca.crt"' env="SYNNAX_CA_CERT">

The CA certificate file, relative to `--certs-dir`.

</Field.Item>

<Field.Item name="--node-cert" type="path" default='"node.crt"' env="SYNNAX_NODE_CERT">

The certificate file of the Core, relative to `--certs-dir`.

</Field.Item>

<Field.Item name="--node-key" type="path" default='"node.key"' env="SYNNAX_NODE_KEY">

The key file of the Core, relative to `--certs-dir`.

</Field.Item>

<Field.Item name="--username" type="string" default='"synnax"' env="SYNNAX_USERNAME">

The username of the cluster root user. The Core applies it on every start. See
[Root user reconciliation](#root-user-reconciliation) for what happens when it changes
between restarts.

</Field.Item>

<Field.Item name="--password" type="string" default='"seldon"' env="SYNNAX_PASSWORD">

The password of the cluster root user. The configured value is the source of truth: if
the stored password is different, the Core changes it to match on the next start. See
[Root user reconciliation](#root-user-reconciliation).

</Field.Item>

<Field.Item name="--license-key" type="string" env="SYNNAX_LICENSE_KEY">

The license key to activate at start. See
[Licensing](/reference/enterprise/production#licensing).

</Field.Item>

<Field.Item name="--license-file" type="path" env="SYNNAX_LICENSE_FILE">

A file that holds the license key to activate at start.

</Field.Item>

<Field.Item name="--debug" env="SYNNAX_DEBUG">

Enables debug logging. Do not use it in production, because it writes a very large
amount of output.

</Field.Item>

<Field.Item name="--slow-consumer-timeout" type="duration" default='"2.5s"' env="SYNNAX_SLOW_CONSUMER_TIMEOUT">

The time after which the Core closes a telemetry streamer that stops receiving messages.
You rarely need to change it.

</Field.Item>

<Field.Item name="--no-driver" env="SYNNAX_NO_DRIVER">

Disables the Driver embedded in the Core. Use it to run Synnax without device
integrations.

</Field.Item>

<Field.Item name="--stop-on-stdin-close" env="SYNNAX_STOP_ON_STDIN_CLOSE">

Stops the Core when its standard input closes. Use it when a parent process starts the
Core and holds its standard input, so that the Core stops if the parent exits. Do not
set it for a Core that runs as a service, because a service has no standard input.

</Field.Item>

<Field.Item name="--disable-integrations" type="list" env="SYNNAX_DISABLE_INTEGRATIONS">

The device integrations to disable. All integrations are enabled by default. The options
are `arc`, `ethercat`, `labjack`, `modbus`, `ni`, and `opc`.

</Field.Item>

<Field.Item name="--enable-integrations" type="list" env="SYNNAX_ENABLE_INTEGRATIONS">

The device integrations to enable, when you want only some of them. All integrations are
enabled by default. The options are `arc`, `ethercat`, `labjack`, `modbus`, `ni`, and
`opc`.

</Field.Item>

<Field.Item name="--task-op-timeout" type="duration" default='"60s"' env="SYNNAX_TASK_OP_TIMEOUT">

The time after which the embedded Driver reports a task operation as stuck. Use it to
debug tasks that block.

</Field.Item>

<Field.Item name="--task-poll-interval" type="duration" default='"1s"' env="SYNNAX_TASK_POLL_INTERVAL">

The time between task timeout checks in the embedded Driver.

</Field.Item>

<Field.Item name="--task-shutdown-timeout" type="duration" default='"30s"' env="SYNNAX_TASK_SHUTDOWN_TIMEOUT">

The longest time the embedded Driver waits for task workers when it shuts down. After
this time, it detaches workers that are stuck.

</Field.Item>

<Field.Item name="--task-worker-count" type="int" default="4" env="SYNNAX_TASK_WORKER_COUNT">

The number of worker threads for task operations in the embedded Driver, from 1 to 64.

</Field.Item>

<Field.Item name="--log-file-path" type="path" default='"./synnax-logs/synnax.log"' env="SYNNAX_LOG_FILE_PATH">

The file where the Core writes its logs.

</Field.Item>

<Field.Item name="--log-file-max-size" type="int" default="50" env="SYNNAX_LOG_FILE_MAX_SIZE">

The largest size of a log file, in MB, before the Core starts a new one.

</Field.Item>

<Field.Item name="--log-file-max-backups" type="int" default="5" env="SYNNAX_LOG_FILE_MAX_BACKUPS">

The number of old log files to keep before the Core deletes them.

</Field.Item>

<Field.Item name="--log-file-max-age" type="int" default="30" env="SYNNAX_LOG_FILE_MAX_AGE">

The number of days to keep old log files before the Core deletes them.

</Field.Item>

<Field.Item name="--log-file-compress" env="SYNNAX_LOG_FILE_COMPRESS">

Compresses old log files on disk.

</Field.Item>

<Field.Item name="--disable-channel-name-validation" env="SYNNAX_DISABLE_CHANNEL_NAME_VALIDATION">

Lets channels have any name, including special characters and spaces. By default, a
channel name can contain only letters, digits, and underscores, and cannot start with a
digit.

</Field.Item>

</Field.List>

### Configuration files

Synnax will also read configuration files in JSON, TOML and YAML formats. The values set
in these configuration files take the lowest precedence and will be overridden by any
environment variables or command line flags.

By default, Synnax reads the configuration file at `/usr/local/synnax/config.yaml`. To
use a different file, set the `--config` flag or the `SYNNAX_CONFIG` environment
variable.

#### Multiple listeners

The `listen` key takes either form. A single address (as above) binds one listener over
the node certificate paths. A list of objects binds one listener per entry, each with
its own address and certificate. The list form works in configuration files only, not as
a flag. See
[Serving multiple listeners](/reference/enterprise/production#serving-multiple-listeners)
for the full deployment model.

```yaml
listen:
  - address: core01.example.com:9090
    cert:
      source: file
      cert: /usr/local/synnax/certs/driver.crt
      key: /usr/local/synnax/certs/driver.key
    advertise: true
  - address: node01.example-tailnet.ts.net:9091
    cert:
      source: tailscale
    name: console
```

### Root user reconciliation

Every time a Core starts, it reconciles the configured `--username` / `--password`
against the existing cluster state. The configured credentials are the source of truth:
the Core makes the state match config, rather than asking the operator to log in and
update things by hand.

#### Recovering a forgotten root password

Because the configured password is the source of truth, you can recover a forgotten root
password by editing the Core's configuration (config file, environment variable, or
`--password` flag) and restarting the Core. The stored password will be rotated on
startup. Non-root users change their passwords through the API as normal. Only the root
user's password is set by configuration.

#### Demoted users

When a username change demotes the previous root user, that user keeps their `Owner`
role and their original credentials. They can still log in with full permissions; they
just no longer hold the immutable root-user flag. To fully remove them, an `Owner` can
delete the demoted user through the API.

## Service (Windows only)

The `service` command manages Synnax as a Windows Service. These commands are only
available on Windows and require administrator privileges.

When running as a Windows Service, Synnax will:

- Start automatically when Windows boots (if configured)
- Receive proper shutdown signals for graceful termination
- Log events to the Windows Event Log
- Automatically restart on failure

### service install

Installs Synnax as a Windows Service. Server configuration flags are stored in the
service configuration and used when the service starts.

#### Examples

Install with default settings (auto-start enabled, insecure mode):

```cmd
synnax service install --insecure
```

Install with custom data directory and listen address:

```cmd
synnax service install --listen 0.0.0.0:9090 --data C:\ProgramData\Synnax\data --insecure
```

Install without auto-start:

```cmd
synnax service install --auto-start=false --insecure
```

### service uninstall

Removes the Synnax Windows Service. This will stop the service if it is running and
remove it from the system.

```cmd
synnax service uninstall
```

### service start

Starts the installed Synnax Windows Service.

```cmd
synnax service start
```

### service stop

Stops the running Synnax Windows Service.

```cmd
synnax service stop
```

### service status

Shows if the Synnax Windows Service is installed and running. It also shows the data
directory, the log file location, and the listen address.

```cmd
synnax service status
```
