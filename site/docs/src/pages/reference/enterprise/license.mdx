A Synnax Core without a license key runs with a limit of 50 channels. To use more,
[contact Synnax Labs](https://www.synnaxlabs.com/#contact) for a license key, then
[activate it at start](#activate-at-start). The Core accepts numeric keys and signed
keys issued through your organization's Synnax account.

Signed license keys can be bound to the computer they were issued for. The key holds the
fingerprint of that computer, which comes from its network hardware addresses. The Core
checks the key on its own and needs no internet access. Only the portal, where you get
the key, needs internet access, and you can use it from any computer.

To activate or replace a license, log in as a user with the **Owner** role.

## Activate from the Console

The Console shows an activation screen when a signed license has expired and no longer
covers the Core. A Core in the free tier opens your projects instead; use
[activate at start](#activate-at-start) to give it a key.

1. Log in to the Core. The Console shows **This Core's license has expired**.
2. Click **Copy fingerprint**.
3. Click **Get a key**, and log in to your Synnax account.
4. Select the license, enter a **Machine name**, and paste the fingerprint into **Host
   hashes**.
5. Click **Activate and download license key**. Your browser downloads a `.lic` file.
6. In the Console, click <Icon.Attachment /> and select the `.lic` file, or paste the
   key.
7. Click **Activate**.

The Console opens your projects. The Core stores the key, so it stays active after a
restart.

## Activate at start

Use this method for a Core that no one logs in to, or a Core started with `--mem`, which
keeps nothing between runs. For a numeric key, set `SYNNAX_LICENSE_KEY` before you start
the Core, or pass `--license-key`. Numeric keys do not need a fingerprint.

For a signed key from the portal:

1. Start the Core. Its log prints the fingerprint:
   `no active license on this Core. Host fingerprint: ...`
2. On the portal, activate the license with that fingerprint, as in steps 3 to 5 above.
3. Start the Core with the key file:

   ```bash
   synnax start --listen=synnax.example.com:9090 \
     --license-file=/usr/local/synnax/synnax.lic
   ```

   Or put the key in the `SYNNAX_LICENSE_KEY` environment variable. The `--license-key`
   flag also works, but it shows the key in the process list. When both a key and a file
   are given, the key wins.

<Note.Note variant="warning">
  The Core activates the key from the flag, file, or environment variable at every
  start. If that key expires or belongs to a different computer, the Core does not
  start, even when it stored a newer key. When you renew a license or move a Core,
  replace the key file or variable too.
</Note.Note>

If the Core refuses the key, it stops with an error such as "the license was not issued
for this machine" or "invalid license".

## Check the license

Run the "Show license info" command. The dialog shows:

| Field           | Values                                                                  |
| --------------- | ----------------------------------------------------------------------- |
| Status          | **Active**, **Expiring**, **Expired**, or **Free**                      |
| Machines        | Runs on any machine, Bound to this machine, or Bound to another machine |
| Channels        | **Unlimited**, or the number of channels for each Core                  |
| Expires or Term | The expiry date, or **Perpetual**                                       |

When the license is about to expire, the Core badge in the status bar shows a warning
too.

To read the license from a script, log in, then call the retrieve endpoint:

```bash
TOKEN=$(curl -s -X POST https://synnax.example.com:9090/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"synnax","password":"seldon"}' | jq -r .token)
curl -s -X POST https://synnax.example.com:9090/api/v1/license/retrieve \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" -d '{}'
```

The response has `state` (`ok`, `missing`, or `expired`), `warning`, `fingerprint`, and
`license`.

## Renew or replace a license

The Console shows the activation screen only when the Core refuses requests. To put a
new key on a running Core:

1. On the portal, open the menu of the machine and select **Download license key**.
2. Replace the key file or the `SYNNAX_LICENSE_KEY` value with the new key, then restart
   the Core.

When a Core holds more than one key, it uses a key that applies to the computer, and the
newest of those.

### Move a Core to a different computer

A license allows a fixed number of machines. To move a Core:

1. On the portal, open the menu of the old machine and select **Release seat**.
2. Activate the license for the new computer, then give the Core the new key.

### Docker

The fingerprint comes from the network hardware (MAC) addresses of the computer. Docker
gives each new container a random address, so a recreated container no longer matches a
bound key. Start the container with a fixed, locally administered address:

```bash
docker run --name synnax --mac-address 02:5a:00:00:00:01 ...
```

The license is bound to the `--mac-address`, so keep the same address when you recreate
or upgrade the container. With `--network host`, the container uses the addresses of the
host instead. On Kubernetes, ask Synnax Labs for a license that runs on any machine.

## Expiry

An expired numeric key falls back to the free 50-channel limit after its grace period.
Signed keys follow these rules:

1. **7 days before the expiry date** -> the Console warns: "license expires on ..."
2. **Up to 14 days after the expiry date** -> the license still applies, with a warning
   that names the end of the grace period.
3. **After the grace period** -> a license with a version cap still covers Core versions
   up to the cap. Otherwise the Core refuses requests and the Console shows **This
   Core's license has expired**.

The Core checks the term when it starts and when a key is activated. A Core that keeps
running keeps its license state until its next restart. If the system clock is more than
24 hours behind the last time the Core recorded, the Core cannot check the term and
treats a license with an expiry date as expired.

### Channel limit

A Core with no key has a limit of 50 channels. A license can change that limit. Virtual
channels do not count. Past the limit, creating a channel fails with "using more
channels than allowed by the license", and channels created past the limit cannot be
read.
