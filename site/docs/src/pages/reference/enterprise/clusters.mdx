<Note.Note variant="warning">
  Clusters of more than one node are experimental. A cluster has no failover: when a
  node stops, its data is not available until it starts again. For production, run one
  Core.
</Note.Note>

A Synnax Core is one node. Several nodes can join into a cluster, which clients reach
through any node.

<Divider.Divider x />

## What each node holds

- **Metadata** -> channels, ranges, users, the license, and other metadata are copied to
  every node. A change on one node reaches the others within a few seconds.
- **Data** -> the samples of a channel stay on the node where the channel was created.
  When a client writes or reads a channel through a different node, that node forwards
  the request. A channel cannot move to a different node.

When a node stops, no node can read or write its channels.

<Divider.Divider x />

## Start a cluster

1. On the first node, create the CA and start the Core:

   ```bash
   synnax start --listen=core01.example.com:9090 --auto-cert
   ```

2. Copy `ca.crt` and `ca.key` from the certificate folder of the first node to the same
   folder on each other node. Every node must use the same CA.
3. On each other node, start the Core with the address of a running node in `--peers`:

   ```bash
   synnax start --listen=core02.example.com:9090 --auto-cert \
     --peers=core01.example.com:9090
   ```

Each `--listen` host must be a name that the other nodes can reach. Nodes get their IDs
when they join. A node reads `--peers` only on its first start, with an empty data
folder.

The license must cover the fingerprint of every node, because each node checks its own.
Ask Synnax Labs for a license for all the computers in the cluster.

<Divider.Divider x />

## Limits

- A node cannot be removed from a cluster. The data on it goes with it.
- Nodes of different versions are not supported. To upgrade, stop every node, upgrade
  every node, then start them all.
- A login on one node is valid only on that node.
- Writes to channels on more than one node are not one transaction.
- Every node keeps a full copy of the metadata.
