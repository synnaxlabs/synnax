Synnax Enterprise is a standalone Synnax Core that your team deploys. Your team connects
to it with the Synnax Console, the client libraries, and standalone Synnax Drivers, and
each person logs in as a user. To compare Enterprise with Synnax Desktop, see
[Synnax editions](/reference/get-started/editions).

Do the steps below to install a Core, start it, and connect the Console to it. Select
your operating system to start.

<Divider.Divider x />

## <Step step={1} level="h2">Install the Core</Step>

The Core stores all sensor and actuator data. Devices, Consoles, and control sequences
communicate through it.

<Platform.Tabs client:load>

<Fragment slot="Docker">

### Docker

<Note.Note variant="warning">
  A Core in a Docker container cannot access devices that connect to the host machine.
  To connect data acquisition devices with the Driver, install the Core directly on the
  host operating system.
</Note.Note>

Pull the latest image from Docker Hub:

```bash
docker pull synnaxlabs/synnax:latest
```

</Fragment>

<Fragment slot="Linux">

### Linux

Download the latest binary:

<DownloadURL os="linux" />

Move the binary to `/usr/local/bin`:

<MoveCommand os="linux" />

Make the binary executable. If you do not have the necessary permissions, use `sudo`:

```bash
chmod +x /usr/local/bin/synnax
```

Make sure that `/usr/local/bin` is in your `PATH`. To add it for the current terminal
session only, run:

```bash
export PATH=$PATH:/usr/local/bin
```

To add it permanently, run:

```bash
echo 'export PATH=$PATH:/usr/local/bin' >> ~/.bashrc
```

For `zsh`, use `~/.zshrc` instead of `~/.bashrc`. If an earlier version of Synnax is in
your `PATH`, remove it to prevent conflicts.

Verify the installation:

```bash
synnax --version
```

You should see:

## <Step step={2} level="h2">Start the Core</Step>

<Platform.Tabs client:load>

<Fragment slot="Docker">

```bash
docker run -p 9090:9090 synnaxlabs/synnax --listen=localhost:9090 --mem --insecure
```

The `-p 9090:9090` option maps port 9090 on the host to port 9090 in the container.

</Fragment>

<Fragment slot="Linux">

```bash
synnax start --listen=localhost:9090 --mem --insecure
```

</Fragment>

<Fragment slot="macOS">

```bash
synnax start --listen=localhost:9090 --mem --insecure
```

</Fragment>

<Fragment slot="Windows">

```powershell
synnax start --listen=localhost:9090 --mem --insecure
```

</Fragment>

</Platform.Tabs>

This command starts a Core with these flags:

<table>
  <thead>
    <tr>
      <th>Flag</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`--listen=localhost:9090`</td>
      <td>The address that the Core listens on.</td>
    </tr>
    <tr>
      <td>`--mem`</td>
      <td>Keep all data in memory. Use this for learning and development.</td>
    </tr>
    <tr>
      <td>`--insecure`</td>
      <td>Run without TLS.</td>
    </tr>
  </tbody>
</table>

With `--mem`, the Core loses all data when it stops. For persistent storage and other
flags, see the [Core CLI reference](/reference/enterprise/cli-reference). To deploy a
Core for production use, see [Deploy to production](/reference/enterprise/production).

To stop the Core, press `Ctrl+C` in the terminal.

## <Step step={4} level="h2">Connect the Console and log in</Step>

The Console includes a connection named **Local** to a Core at `localhost:9090`. It is
in the list of Cores in the login window. When the Core from step 2 is reachable, the
status of **Local** is **Connected**.
