A PagerDuty alert task watches the [statuses](/reference/alarms/statuses) that you
choose, and opens or resolves PagerDuty incidents when they change. The Synnax Core runs
the task and sends the events, so the computer that runs the Core needs internet access
to `events.pagerduty.com`. The task follows the standard
[task lifecycle](/reference/hardware/tasks#task-lifecycle).

<Divider.Divider x />

## Prerequisites

1. A [PagerDuty](https://www.pagerduty.com/) account.
2. A PagerDuty service with an Events API v2 integration. In PagerDuty, open
   **Services** -> **Service Directory**, select the service, then **Integrations** ->
   **Add Integration** -> **Events API v2**.
3. The 32-character integration key, also called the routing key.
4. The [statuses](/reference/alarms/statuses) to send. Create them first, so that you
   can select them in the task.

## Create an alert task

<Client.Tabs exclude={["cpp", "typescript"]}>
  <Fragment slot="console">

1. Run the "Create PagerDuty alert task" command from the
   [command palette](/reference/get-started/ui-overview#search-and-command-palette).
2. Enter the **Routing key**.
3. Leave **Connect from** set to the Core.
4. Click **Add alert**. Under **Trigger**, select the **Status** to watch.
5. Optional: turn on **Treat error as critical**, and fill in **Component**, **Group**,
   and **Class** under **Incident**.
6. Add an alert for each status, then configure and start the task.

<Text.Text slot="summary" level="p"><Icon.Play /> Create and run an alert task</Text.Text>

```python
import synnax as sy

client = sy.Synnax()

STATUS_KEY = "engine-1"
client.statuses.set(
    sy.Status(
        key=STATUS_KEY,
        name="Engine 1",
        variant="success",
        message="Engine 1 is healthy",
    )
)

alert_task = sy.pagerduty.AlertTask(
    name="Engine alerts",
    routing_key="<your-32-character-integration-key>",
    auto_start=False,
    alerts=[
        sy.pagerduty.Alert(
            status=STATUS_KEY,
            errors_critical=True,
            component="engine-1",
            group="engines",
            class_="engine-failure",
        ),
    ],
)
client.tasks.configure(alert_task)

with alert_task.run():
    # Opens an incident
    client.statuses.set(
        sy.Status(
            key=STATUS_KEY,
            name="Engine 1",
            variant="error",
            message="Engine 1 is down",
            description="Connection to the controller lost",
        )
    )
    sy.sleep(5)
    # Resolves the incident
    client.statuses.set(
        sy.Status(
            key=STATUS_KEY,
            name="Engine 1",
            variant="success",
            message="Engine 1 recovered",
        )
    )
    sy.sleep(3)
```

## How the task sends events

| Status variant    | PagerDuty                                                         |
| ----------------- | ----------------------------------------------------------------- |
| Error             | An `error` event, or `critical` with **Treat error as critical**. |
| Warning           | A `warning` event.                                                |
| Info              | An `info` event. It also opens an incident.                       |
| Success           | Resolves the incident.                                            |
| Loading, Disabled | Nothing.                                                          |

- PagerDuty groups events by status key, so a later change updates the same incident.
- The summary of the event is the status message, followed by `: ` and the description
  when there is one. The source is the status name, and the details are the status
  details.
- The task sends only changes that happen while it runs. It does not send the current
  value of a status when it starts.
- Deleting the task or a status does not resolve open incidents. Set the statuses to
  **Success** first.
- When PagerDuty rejects an event, the task shows an error and keeps running.

## Configuration reference

### Task

| Parameter     | Type    | Required | Default | Description                                         |
| ------------- | ------- | -------- | ------- | --------------------------------------------------- |
| `routing_key` | string  | Yes      | -       | The 32-character Events API v2 integration key.     |
| `alerts`      | array   | Yes      | -       | The [alerts](#alert). At least one must be enabled. |
| `auto_start`  | boolean | No       | `false` | Starts the task when you configure it.              |

### Alert

| Parameter         | Type    | Required | Default | Description                                                        |
| ----------------- | ------- | -------- | ------- | ------------------------------------------------------------------ |
| `status`          | string  | Yes      | -       | The key of the status to watch.                                    |
| `disabled`        | boolean | No       | `false` | Leaves the alert out of the task.                                  |
| `errors_critical` | boolean | No       | `false` | Sends **Error** as `critical` instead of `error`.                  |
| `component`       | string  | No       | `""`    | The part of the system, such as `"engine-1"`.                      |
| `group`           | string  | No       | `""`    | A group of components, such as `"engines"`.                        |
| `class`           | string  | No       | `""`    | The kind of event, such as `"engine-failure"`. `class_` in Python. |
