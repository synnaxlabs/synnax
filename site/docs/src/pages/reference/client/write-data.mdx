This guide covers how to write data to Synnax channels. Use a writer for live data
acquisition. Use historical writes to backfill data or to import data from files. Every
write must obey the [rules of writes](#the-rules-of-writes).

<Divider.Divider x />

## Writing with writers

A **writer** sends [frames](/reference/client/series-and-frames#frames) of data to
Synnax for one or more channels. Use writers for live data acquisition, control
sequences, and real-time data processing. For historical data, a writer can send large
frames with millions of samples. For live data, a writer sends small frames with one to
a few dozen samples per channel, many times over a long period.

Many writers can be open at the same time, and each writer can have a different job. For
example, one writer sends sensor values from a device. Another writer sends commands to
the actuators of a device. The schematics in the Console also use writers to send
commands when an operator clicks a valve.

<Diagram>
  <Image id="concepts/writes/writer" extension="svg" themed={false} />
</Diagram>

Each writer controls one transaction. You open a writer, write frames to it, and commit
the data to make it available for reads. You can commit a writer many times. Each commit
adds to the data of the previous commit. After the last commit, you close the writer.

### Opening a writer

To open a writer, use the <Client.Var py="open_writer" ts="openWriter" /> method with a
start timestamp and a list of channels. The start timestamp is the time at or just
before the first sample. Before the writer opens, Synnax checks that each channel exists
and that no stored data overlaps the start timestamp.

<Client.Tabs exclude={["cpp","console"]}>

  <Fragment slot="python">

```python
# Python's context manager is recommended
with client.open_writer(
    start=sy.TimeStamp.now(),
    channels=["time", "temperature"],
) as writer:
    for i in range(100):
        writer.write({
            "time": sy.TimeStamp.now(),
            "temperature": i * 0.1,
        })
        sy.sleep(0.1)
    writer.commit()
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
const writer = await client.openWriter({
  start: TimeStamp.now(),
  channels: ["time", "temperature"],
});

try {
  for (let i = 0; i < 100; i++)
    await writer.write({ time: TimeStamp.now(), temperature: i * 0.1 });
  await writer.commit();
} finally {
  await writer.close();
}
```

  </Fragment>
</Client.Tabs>

These examples write 100 samples to the `temperature` channel, approximately 100 ms
apart, and commit the writes at the end. A writer can stay open for hours or days and
write millions of samples.

<Note.Note variant="info" className="compact">
  For more writer options, see [auto-commit](/reference/client/advanced/auto-commit),
  [auto-index](/reference/client/advanced/auto-index), and [control
  authority](/reference/control/authority).
</Note.Note>

### Writer modes

A writer has one of three modes. Set the mode with the `mode` argument when you open the
writer.

- `persist` -> Synnax stores the data, but does not send it to streamers. Use this mode
  to write historical data that does not show the current state of the hardware.
- `stream` -> Synnax sends the data to streamers, but does not store it. Calls to
  `commit` have no effect. Use this mode for data that you need only in real time.
- <Client.Var py="persist_stream" ts="persistStream" /> -> Synnax stores the
data and sends it to streamers. This is the default mode.

For example, to open a writer that only stores data:

<Client.Tabs exclude={["cpp","console"]}>

  <Fragment slot="python">

```python
writer = client.open_writer(
    start=sy.TimeStamp.now(),
    channels=["time", "temperature"],
    mode="persist",
)
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
const writer = await client.openWriter({
  start: TimeStamp.now(),
  channels: ["time", "temperature"],
  mode: "persist",
});
```

  </Fragment>
</Client.Tabs>

### Writing data

The `write` method accepts several argument formats. Use the one that best fits your use
case.

<Client.Tabs exclude={["cpp","console"]}>

  <Fragment slot="python">

```python
# Write a single sample for a channel
writer.write("temperature", 25.5)

# Write multiple samples for a channel
writer.write("temperature", [25.5, 26.0, 26.5])

# Write a single sample for several channels
writer.write({
    "time": sy.TimeStamp.now(),
    "temperature": 25.5,
})

# Write multiple samples using lists or numpy arrays
import numpy as np
start = sy.TimeStamp.now()
writer.write({
    "time": [start, start + sy.TimeSpan.SECOND],
    "temperature": np.array([25.5, 26.0], dtype=np.float32),
})

# Write using a list of channels and corresponding series
writer.write(
    ["time", "temperature"],
    [timestamps, temperatures],
)

# Write a pandas DataFrame
import pandas as pd
df = pd.DataFrame({
    "time": [sy.TimeStamp.now(), sy.TimeStamp.now() + sy.TimeSpan.SECOND],
    "temperature": [25.5, 26.0],
})
writer.write(df)

# Write a Synnax Frame
frame = sy.Frame({ "time": timestamps, "temperature": temperatures })
writer.write(frame)
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
import { Frame, Series, TimeSpan, TimeStamp } from "@synnaxlabs/client";

// Write a single sample for a channel
await writer.write("temperature", 25.5);

// Write multiple samples for a channel
await writer.write("temperature", [25.5, 26.0, 26.5]);

// Write a single sample for several channels
await writer.write({
  time: TimeStamp.now(),
  temperature: 25.5,
});

// Write multiple samples using arrays
const start = TimeStamp.now();
await writer.write({
  time: [start, start.add(TimeSpan.seconds(1))],
  temperature: [25.5, 26.0],
});

// Write using a list of channels and corresponding series
await writer.write(["time", "temperature"], [timestamps, temperatures]);

// Write a Frame with typed arrays (high-performance)
const now = TimeStamp.now();
await writer.write(
  new Frame({
    [timeChannel.key]: new Series({
      data: new BigInt64Array([now.valueOf(), now.add(TimeSpan.seconds(1)).valueOf()]),
    }),
    [tempChannel.key]: new Series({
      data: new Float32Array([25.5, 26.0]),
    }),
  }),
);
```

  </Fragment>
</Client.Tabs>

### Writing variable-length data

Strings, JSON, and bytes are written through the same writer API as fixed-width samples.
The channel's data type determines how the writer encodes each value.

<Client.Tabs exclude={["cpp","console"]}>

  <Fragment slot="python">

```python
with client.open_writer(
    start=sy.TimeStamp.now(),
    channels=["event_time", "event_log"],
) as writer:
    writer.write({
        "event_time": [sy.TimeStamp.now(), sy.TimeStamp.now() + sy.TimeSpan.SECOND],
        "event_log": ["startup complete", "tank pressurized"],
    })
    writer.commit()
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
const writer = await client.openWriter({
  start: TimeStamp.now(),
  channels: ["event_time", "event_log"],
});
try {
  await writer.write({
    event_time: [TimeStamp.now(), TimeStamp.now().add(TimeSpan.seconds(1))],
    event_log: ["startup complete", "tank pressurized"],
  });
  await writer.commit();
} finally {
  await writer.close();
}
```

  </Fragment>
</Client.Tabs>

JSON channels accept and return native objects. Bytes channels accept any Python `bytes`
value or TypeScript `Uint8Array`. Variable-length channels can share a writer with
fixed-width channels and a common index, so a single `write` call can commit timestamps,
numeric samples, and string or JSON annotations together.

### Auto-commit

A commit makes written data available for reads. By default, a writer has auto-commit
on, so Synnax commits each write immediately. This is correct for real-time data that
does not need to be applied as one unit. To commit a batch of writes as one unit, turn
off [auto-commit](/reference/client/advanced/auto-commit) and call `commit` yourself.

### Closing a writer

When you finish writing, always close the writer. This closes network connections and
releases other resources. If you do not close a writer, other writers can be blocked
from writing to the same channels. Data that you did not commit is lost. Closing a
writer also gives control of its channels to the writer with the next highest
[authority](/reference/control/authority), if one exists.

<Client.Tabs exclude={["cpp","console"]}>

  <Fragment slot="python">

```python
writer.close()
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
await writer.close();
```

  </Fragment>
</Client.Tabs>

Using structured cleanup patterns ensures the writer is always closed, even if an
exception is thrown.

<Client.Tabs exclude={["cpp","console"]}>

  <Fragment slot="python">

```python
# Python's context manager is the recommended approach
with client.open_writer(
    start=sy.TimeStamp.now(),
    channels=["time", "temperature"],
) as writer:
    # Write data here

# Alternatively, use a try/finally block
writer = client.open_writer(
    start=sy.TimeStamp.now(),
    channels=["time", "temperature"],
)
try:
    # Write data here
finally:
    writer.close()
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
// TypeScript's try/finally block is the recommended approach

const writer = await client.openWriter({
  start: TimeStamp.now(),
  channels: ["time", "temperature"],
});

try {
  for (let i = 0; i < 100; i++)
    await writer.write({ time: TimeStamp.now(), temperature: i * 0.1 });

  await writer.commit();
} finally {
  await writer.close();
}
```

  </Fragment>
</Client.Tabs>

## Historical writes

Historical writes are useful for backfilling data, ingesting data from files, or writing
data at specific timestamps that have already passed.

<Note.Note variant="warning" className="compact">
  These patterns should NOT be used for live writing to Synnax. Opening and closing
  transactions for each sample has severe performance implications. For live data
  writing, always use a Writer as described above.
</Note.Note>

### Writing to a channel

<Client.Tabs exclude={["console", "cpp"]}>

  <Fragment slot="python">

```python
start = sy.TimeStamp.now()
times = [
    start,
    start + 1 * sy.TimeSpan.MINUTE,
    start + 2 * sy.TimeSpan.MINUTE,
    start + 3 * sy.TimeSpan.MINUTE,
    start + 4 * sy.TimeSpan.MINUTE,
]
temperatures = [55, 55.1, 55.7, 57.2, 58.1]

# Write the timestamps to the index
time_channel.write(start, times)

# Write the data to the channel
temp_channel.write(start, temperatures)
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
const start = TimeStamp.now();
const timestamps = new BigInt64Array([
  start.valueOf(),
  start.add(TimeSpan.seconds(1)).valueOf(),
  start.add(TimeSpan.seconds(2)).valueOf(),
  start.add(TimeSpan.seconds(3)).valueOf(),
  start.add(TimeSpan.seconds(4)).valueOf(),
]);
const temperatures = new Float32Array([20.0, 20.1, 20.2, 20.3, 20.4]);

// Write the timestamps to the index first
await timeChannel.write(start, timestamps);

// Then write the data
await tempChannel.write(start, temperatures);
```

  </Fragment>

</Client.Tabs>

#### Index and data alignment

Notice how the two arrays are aligned using the common `start` timestamp. This tells
Synnax that the first sample in the `temperatures` array is associated with the first
timestamp in the `timestamps` array.

Synnax raises a `ValidationError` if the index channel does not have a timestamp for
each sample in the data channel. See [Rule 1](#rule-1).

### Writing multiple data channels

It's common to have multiple data channels that share the same index. For example, a
weather station might record temperature, humidity, and pressure all at the same
timestamps.

#### Single time index

When writing a single sample to multiple channels at the same instant, use a dictionary
with scalar values.

<Client.Tabs exclude={["console", "cpp"]}>

  <Fragment slot="python">

```python
now = sy.TimeStamp.now()

# Write a single sample to multiple channels
client.write(now, {
    "time": now,
    "temperature": 22.5,
    "humidity": 45.0,
    "pressure": 1013.2,
})
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
const now = TimeStamp.now();

// Write a single sample to multiple channels
await client.write(now, {
  time: now,
  temperature: 22.5,
  humidity: 45.0,
  pressure: 1013.2,
});
```

  </Fragment>

</Client.Tabs>

#### Multiple time indices

When writing multiple samples over time, use arrays for both the timestamps and data
values.

<Client.Tabs exclude={["console", "cpp"]}>

  <Fragment slot="python">

```python
start = sy.TimeStamp.now()
timestamps = [
    start,
    start + 1 * sy.TimeSpan.SECOND,
    start + 2 * sy.TimeSpan.SECOND,
    start + 3 * sy.TimeSpan.SECOND,
    start + 4 * sy.TimeSpan.SECOND,
]
temperatures = [22.5, 22.6, 22.8, 23.1, 23.0]
humidities = [45.0, 45.2, 45.1, 44.8, 44.9]
pressures = [1013.2, 1013.3, 1013.1, 1013.0, 1012.9]

# Write all channels in a single call
client.write(start, {
    "time": timestamps,
    "temperature": temperatures,
    "humidity": humidities,
    "pressure": pressures,
})
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
const start = TimeStamp.now();
const timestamps = new BigInt64Array([
  start.valueOf(),
  start.add(TimeSpan.seconds(1)).valueOf(),
  start.add(TimeSpan.seconds(2)).valueOf(),
  start.add(TimeSpan.seconds(3)).valueOf(),
  start.add(TimeSpan.seconds(4)).valueOf(),
]);
const temperatures = new Float32Array([22.5, 22.6, 22.8, 23.1, 23.0]);
const humidities = new Float32Array([45.0, 45.2, 45.1, 44.8, 44.9]);
const pressures = new Float32Array([1013.2, 1013.3, 1013.1, 1013.0, 1012.9]);

// Write all channels in a single call
await client.write(start, {
  time: timestamps,
  temperature: temperatures,
  humidity: humidities,
  pressure: pressures,
});
```

  </Fragment>

</Client.Tabs>

All data channels use the same `start` timestamp for alignment, which tells Synnax they
share the same index. The arrays must all have the same length as the timestamps array.

## The rules of writes

Synnax rejects a write that breaks one of these rules.

### Rule 1

<Rule>Write to an index channel before or at the same time as its data channels.</Rule>

The examples in this section use two channels. `time` is an index channel, and
`temperature` is a data channel indexed by `time`:

```json
time = {
  "key": 65536,
  "data_type": "timestamp",
  "is_index": true,
}

temperature = {
  "key": 65537,
  "data_type": "float32",
  "is_index": false,
  "index": 65536,
}
```

#### Example 1: write the index and data channels together

{/* prettier-ignore-start */}

A frame that has timestamps for `time` and samples for `temperature` is
<b style="color: var(--pluto-secondary-z);">valid</b>:

{/* prettier-ignore-end */}

```json
{
  "time": [1677433720770863800, 1677433720970863400, 1677433721270868900],
  "temperature": [19.17, 19.18, 19.19]
}
```

{/* prettier-ignore-start */}

If a writer is open on both channels, a frame without `time` breaks Rule 1. This frame
is <b style="color: var(--pluto-error-z);">invalid</b>:

{/* prettier-ignore-end */}

```json
{
  // The time channel is missing.
  "temperature": [19.17, 19.18, 19.19]
}
```

#### Example 2: write the data channel after the index channel

A writer on only the `time` channel writes this frame:

```json
{
  "time": [1677433720770863800, 1677433720970863400, 1677433721270868900]
}
```

{/* prettier-ignore-start */}

Next, a writer on only the `temperature` channel opens at `1677433720770863800` and
writes the frame below. The frame is
<b style="color: var(--pluto-secondary-z);">valid</b>, because the timestamps already
exist in `time`.

{/* prettier-ignore-end */}

```json
{
  // Timestamps already exist for each of these samples.
  "temperature": [19.17, 19.18, 19.19]
}
```

<Note.Note variant="info">
  Use this pattern to calculate values from one or more data channels and write the
  results to a new data channel with the same index.
</Note.Note>

#### Example 3: write the data channel before the index channel

{/* prettier-ignore-start */}

If you write `temperature` before `time`, you break Rule 1. The frame is
<b style="color: var(--pluto-error-z);">invalid</b>, because no timestamps exist for
the samples.

{/* prettier-ignore-end */}

```json
{
  // Synnax cannot relate these samples to timestamps.
  "temperature": [19.17, 19.18, 19.19]
}
```

### Rule 2

<Rule>
  In one frame, an index channel and all of its data channels must have the same number
  of samples.
</Rule>

In this example, `temperature` and `pressure` are both data channels indexed by `time`.

{/* prettier-ignore-start */}

A writer is open on all three channels. Each series in this frame has three samples, so
the frame is <b style="color: var(--pluto-secondary-z);">valid</b>:

{/* prettier-ignore-end */}

```json
{
  "time": [1677433720770863800, 1677433720970863400, 1677433721270868900],
  "temperature": [19.17, 19.18, 19.19],
  "pressure": [16.22, 17.22, 18.22]
}
```

{/* prettier-ignore-start */}

A series with one sample less breaks Rule 2. This frame is
<b style="color: var(--pluto-error-z);">invalid</b>:

{/* prettier-ignore-end */}

```json
{
  "time": [1677433720770863800, 1677433720970863400, 1677433721270868900],
  "temperature": [19.17, 19.18, 19.19],
  // This series is missing a sample.
  "pressure": [16.22, 17.22]
}
```

{/* prettier-ignore-start */}

A frame without one of the channels also breaks Rule 2. This frame is
<b style="color: var(--pluto-error-z);">invalid</b>:

{/* prettier-ignore-end */}

```json
{
  "time": [1677433720770863800, 1677433720970863400, 1677433721270868900],
  "temperature": [19.17, 19.18, 19.19]
  // The pressure channel is missing.
}
```

### Rule 3

<Rule>Rules 1 and 2 do not apply to virtual channels.</Rule>

[Virtual channels](/reference/channels#virtual-channels) do not store data. They do not
need timestamps or an index, so you can write to them at any time.

### Rule implications

<Rule>All channels that share an index must have the same sample rate.</Rule>

For example, one device records temperature at 10 Hz, and a second device records
pressure at 25 Hz. The samples do not have the same timestamps, so the two channels
cannot share an index.

<Rule>Command channels almost always need their own index.</Rule>

One device often samples many sensors at the same rate, so the sensor channels can share
an index. Command channels are different. You usually write to one command channel at a
time, for example to open one valve, wait, and then open a second valve. The commands do
not have the same timestamps, so they cannot share an index. Give each command channel
its own index, or use a virtual channel.

## Common pitfalls

There are several common pitfalls to avoid when writing data to Synnax. These can lead
to performance degradation and/or control issues.

### Using many individual write calls instead of a writer

When writing large volumes of data in a streaming fashion (or in batches), use a writer
instead of making individual write calls to a channel. Calls to `write` on a channel use
an entirely new transaction for each call - constantly creating, committing, and closing
transactions has a dramatic impact on performance.

<span style={{ color: "red" }}>**Avoid this pattern**</span> - Writing directly to
channels in a loop:

<Client.Tabs exclude={["cpp","console"]}>

  <Fragment slot="python">

```python
time = client.channels.retrieve("time")
temperature = client.channels.retrieve("temperature")

for i in range(100):
    ts = sy.TimeStamp.now()
    time.write(ts, ts)
    temperature.write(ts, i * 0.1)
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
const time = await client.channels.retrieve("time");
const temperature = await client.channels.retrieve("temperature");
for (let i = 0; i < 100; i++) {
  const ts = TimeStamp.now();
  await time.write(ts, ts);
  await temperature.write(ts, i * 0.1);
}
```

  </Fragment>
</Client.Tabs>

<span style={{ color: "red" }}>**Also avoid this pattern**</span> - Opening and closing
a writer for every write:

<Client.Tabs exclude={["cpp","console"]}>

  <Fragment slot="python">

```python
for i in range(100):
    # Open/close writer each iteration
    with client.open_writer(
        start=sy.TimeStamp.now(),
        channels=["time", "temperature"],
    ) as writer:
        sy.sleep(0.1)
        writer.write({
            "time": sy.TimeStamp.now(),
            "temperature": i * 0.1,
        })
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
for (let i = 0; i < 100; i++) {
  const writer = await client.openWriter({
    start: TimeStamp.now(),
    channels: ["time", "temperature"],
  });
  await writer.write({
    time: TimeStamp.now(),
    temperature: i * 0.1,
  });
  await writer.close();
}
```

  </Fragment>
</Client.Tabs>

<span style={{ color: "green" }}>**Recommended approach**</span> - Repeatedly call
`write` on a single writer:

<Client.Tabs exclude={["cpp","console"]}>

  <Fragment slot="python">

```python
# Open/close the writer once
with client.open_writer(
    start=sy.TimeStamp.now(),
    channels=["time", "temperature"],
) as writer:
    sy.sleep(0.1)
    for i in range(100):
        writer.write({
            "time": sy.TimeStamp.now(),
            "temperature": i * 0.1,
        })
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
const writer = await client.openWriter({
  start: TimeStamp.now(),
  channels: ["time", "temperature"],
});
try {
  for (let i = 0; i < 100; i++)
    await writer.write({
      time: TimeStamp.now(),
      temperature: i * 0.1,
    });
} finally {
  await writer.close();
}
```

  </Fragment>
</Client.Tabs>
