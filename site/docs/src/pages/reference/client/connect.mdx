Create a client to connect your code to a Synnax Core. The client logs in with an API
key, or with the username and password of a [user](/reference/enterprise/users) on the
Core.

<Divider.Divider x />

## Connect to Synnax Desktop

Scripts on the same computer as Synnax Desktop can connect to its Core while it runs.
Synnax Desktop saves the address of its Core in `~/.synnax/desktop.json` and an API key
in the keychain of your operating system. The Python client reads both when you give no
arguments:

```python
import synnax as sy

client = sy.Synnax()
```

When you also saved a login with [`sy login`](#log-in-once-with-sy-login), `sy.Synnax()`
uses that login, not Synnax Desktop.

To get the code for each client, click the code button in the top bar of Synnax Desktop,
or run the **Connect from code** command. The dialog shows the install command that
matches the version of Synnax Desktop, and code that you can copy. The **TypeScript**
tab gives code with the address and the API key filled in.

<Video id="client/connect/desktop" />

When you close Synnax Desktop, its Core stops, and the connected scripts lose their
connection. The API key stays the same the next time you open it. The port also stays
the same, unless another program uses it.

To stop every script that uses the key, click **Reset key** in the dialog. Open
streamers and writers stop with a
[session ended](/reference/client/troubleshooting#session-ended) error. Python scripts
that call `sy.Synnax()` use the new key the next time they start. Code that holds the
old key needs the new one. **Erase all data** also deletes the key.

## Connect with arguments

<Client.Tabs exclude={["console"]}>

  <Fragment slot="python">

```python
import synnax as sy

client = sy.Synnax(
    host="core.example.com",
    port=9090,
    username="operator",
    password="secret",
)
```

The client logs in when you create it. It raises `sy.AuthError` when the credentials are
wrong. It raises `Unreachable`, from the `freighter` package, when it cannot reach the
Core.

  </Fragment>

  <Fragment slot="typescript">

```typescript
import { Synnax } from "@synnaxlabs/client";

const client = new Synnax({
  host: "core.example.com",
  port: 9090,
  username: "operator",
  password: "secret",
});
await client.connect();
```

The client starts to connect when you create it, but it does not wait. `connect` waits
for the connection. It throws `AuthError` when the credentials are wrong, and
`DisconnectedError` when it cannot reach the Core. Without `connect`, the first request
throws the same errors.

  </Fragment>

</Client.Tabs>

To keep credentials out of a script, give no host and set the
[environment variables](#connect-with-environment-variables).

## Connect with an API key

An API key lets a script log in with no password. The client gets the permissions of the
user that owns the key. To get a key:

- **Synnax Desktop** -> the TypeScript code in the **Connect from code** dialog holds a
  key. See [Connect to Synnax Desktop](#connect-to-synnax-desktop).
- **A Core in Synnax Enterprise** -> in the Console, right-click a user in the users
  toolbar and select **Manage sign-in**. Enter a key name, then click **Create key**.
  Copy the key at once: the Core does not show it again. See
  [Users](/reference/enterprise/users).
- **`sy login`** -> the command makes a key for you and saves it. See
  [Log in once with sy login](#log-in-once-with-sy-login).

<Client.Tabs exclude={["console"]}>

  <Fragment slot="python">

```python
import synnax as sy

client = sy.Synnax(
    host="core.example.com",
    port=9090,
    api_key="syk_...",
)
```

An API key needs a host. With an API key and no host, the client raises
`sy.ValidationError`.

  </Fragment>

  <Fragment slot="typescript">

```typescript
import { Synnax } from "@synnaxlabs/client";

const client = new Synnax({
  host: "core.example.com",
  port: 9090,
  apiKey: "syk_...",
});
```

  </Fragment>

</Client.Tabs>

Give an API key or a username and password, not both. The client rejects a call that
gives both. When someone deletes or resets the key, the client fails with an
[invalid credentials](/reference/client/troubleshooting#invalid-credentials) error.

## Log in once with sy login

The `sy login` command saves an API key, so Python scripts can connect with no
arguments. It is part of the Python client. Run it in a terminal:

```bash
sy login
```

Answer the prompts. Press **Enter** to keep the default in brackets:

```
Enter your Synnax connection parameters:
Host [localhost]: core.example.com
Port [9090]:
Username [synnax]: operator
Password:
Secure connection? [y/N]:
```

When you answer `y` to the secure prompt, the command also asks for the "CA certificate
path". Enter the path to the `ca.crt` file of the Core. Leave it empty when the Core has
a certificate from a public authority.

The command connects to the Core and prints "Connection successful!". Then it makes an
API key named "Python CLI on" and the name of your computer, saves the key, and prints
"Saved an API key". In your scripts, create the client with no arguments:

```python
import synnax as sy

client = sy.Synnax()
```

The command saves the host, port, TLS setting, and CA certificate path in
`~/.synnax/config.json`. It saves the API key in the keychain of your operating system,
under the name `synnax.api_key`. It does not save your username or password, and it
deletes a password that an older version saved. In the Console, the key shows in
**Manage sign-in** for your user. When the login fails, the command prints why, saves
nothing, and exits with code 1. Run `sy login` again to change the values.

`sy login` never saves the key in a file. When the session has no keychain, the command
fails and saves nothing. See [Connect without a keychain](#connect-without-a-keychain).

With no host, `sy.Synnax()` first reads the
[environment variables](#connect-with-environment-variables), then the saved login, then
[Synnax Desktop](#connect-to-synnax-desktop). When none of them is set, it raises
`sy.ValidationError`. When you give no host and no API key, the client ignores the other
arguments.

## Connect with environment variables

When you give no host, the client reads these environment variables. They take an API
key, not a username and password.

| Variable         | Value                                                             |
| ---------------- | ----------------------------------------------------------------- |
| `SYNNAX_HOST`    | The host of the Core. Required with `SYNNAX_API_KEY`.             |
| `SYNNAX_API_KEY` | An API key. Required with `SYNNAX_HOST`.                          |
| `SYNNAX_PORT`    | The port of the Core. The default is `9090`.                      |
| `SYNNAX_SECURE`  | `true` or `1` to use TLS. The default is `false`.                 |
| `SYNNAX_CA_CERT` | The path to the CA certificate of the Core, for TLS. Python only. |

<Client.Tabs exclude={["console"]}>

  <Fragment slot="python">

```bash
export SYNNAX_HOST=core.example.com
export SYNNAX_API_KEY=syk_...
python my_script.py
```

The client uses the first source that it finds, in this order:

1. The arguments to `sy.Synnax()`, when they include a host.
2. The environment variables.
3. The login that `sy login` saved.
4. Synnax Desktop on this computer.

When only one of `SYNNAX_HOST` and `SYNNAX_API_KEY` is set, or when `SYNNAX_PORT` or
`SYNNAX_SECURE` has a value that is not valid, the client raises `sy.ValidationError`
and names the variable.

  </Fragment>

  <Fragment slot="typescript">

```typescript
import { Synnax } from "@synnaxlabs/client";

const client = new Synnax();
```

```bash
export SYNNAX_HOST=core.example.com
export SYNNAX_API_KEY=syk_...
node my_script.js
```

The client reads the variables in Node.js, Deno, and Bun. A browser has no environment
variables, so give a host there. Deno needs the `--allow-env` flag.

When you give no host, the client ignores the port, username, password, and token that
you give. The constructor throws `ValidationError` in these conditions:

- You give an API key and no host.
- You give no host, and `SYNNAX_HOST` and `SYNNAX_API_KEY` are not set.
- Only one of `SYNNAX_HOST` and `SYNNAX_API_KEY` is set.
- `SYNNAX_PORT` or `SYNNAX_SECURE` has a value that is not valid.

  </Fragment>

</Client.Tabs>

### Connect without a keychain

`sy login` keeps the API key in the keychain of your operating system. Some sessions
have no keychain that works:

- SSH sessions, and Linux computers with no desktop.
- Docker containers.
- CI jobs, cron jobs, and system services.

In these sessions, set `SYNNAX_HOST` and `SYNNAX_API_KEY` instead of running `sy login`.
When a login is saved and the keychain is not available, `sy.Synnax()` raises
`sy.ConfigurationError`. It does not connect to Synnax Desktop or to another Core.

On Linux, a keychain that is locked can wait for a password prompt that an SSH session
cannot show. If a script stops at `sy.Synnax()` over SSH, set the environment variables.

## Connect with TLS

When the Core serves TLS, set `secure` to true. For how to give the Core a certificate,
see [Set up TLS](/reference/enterprise/tls).

<Client.Tabs exclude={["console"]}>

  <Fragment slot="python">

```python
client = sy.Synnax(
    host="core.example.com",
    port=9090,
    username="operator",
    password="secret",
    secure=True,
)
```

The Python client checks the certificate of the Core, and checks that the certificate is
for the host that you connect to. A certificate from a public authority, such as Let's
Encrypt, needs no setup. When the Core uses a self-signed certificate, give the path to
its CA certificate in `ca_cert`:

```python
client = sy.Synnax(
    host="core.example.com",
    port=9090,
    username="operator",
    password="secret",
    secure=True,
    ca_cert="/path/to/ca.crt",
)
```

A Core that you start with `--auto-cert` makes its own CA certificate. Give its path in
`ca_cert`, or save it with [`sy login`](#log-in-once-with-sy-login). To find the file,
see
[Copy the CA certificate](/reference/enterprise/certificates#copy-the-ca-certificate).

  </Fragment>

  <Fragment slot="typescript">

```typescript
const client = new Synnax({
  host: "core.example.com",
  port: 9090,
  username: "operator",
  password: "secret",
  secure: true,
});
```

The TypeScript client checks the certificate of the Core. When the Core uses a
self-signed certificate, the computer must trust its CA certificate. The TypeScript
client has no CA certificate option. In a browser,
[install the CA certificate](/reference/enterprise/certificates) on the computer. For
Node.js, see [Node.js](/reference/enterprise/certificates#nodejs).

  </Fragment>

</Client.Tabs>

## Close the client

Close the client when your code is done with it:

<Client.Tabs exclude={["console"]}>

  <Fragment slot="python">

```python
client.close()
```

`close` also logs out. When the script exits without `close`, the client stops, but its
session stays open on the Core until it times out.

  </Fragment>

  <Fragment slot="typescript">

```typescript
await client.close();
```

A Node.js script does not exit until you close the client.

  </Fragment>

</Client.Tabs>

## Client options

  <Fragment slot="python">

<Field.List>

<Field.Item name="host" id="python-host" type="str">
  The hostname or IP address of the Core. With no host, the client uses the `SYNNAX_*`
  environment variables, the values that `sy login` saved, or Synnax Desktop, in that
  order.
</Field.Item>

<Field.Item name="port" id="python-port" type="int">
  The port of the Core.
</Field.Item>

<Field.Item name="api_key" id="python-api-key" type="str">
  The API key to log in with. Needs a host. See [Connect with an API
  key](#connect-with-an-api-key).
</Field.Item>

<Field.Item name="username" id="python-username" type="str">
  The username to log in with.
</Field.Item>

<Field.Item name="password" id="python-password" type="str">
  The password to log in with.
</Field.Item>

<Field.Item name="secure" id="python-secure" type="bool" default="False">
  Connect with TLS.
</Field.Item>

<Field.Item name="ca_cert" id="python-ca-cert" type="str">
  The path to the CA certificate that signs the certificate of the Core. With `ca_cert`
  and no `secure`, the client raises `ValueError`. With no path, the client trusts the
  CA certificates of the computer.
</Field.Item>

<Field.Item
  name="open_timeout"
  id="python-open-timeout"
  type="TimeSpan | float"
  default="5 s"
>
  How long to wait to open a connection. A number is seconds.
</Field.Item>

<Field.Item
  name="read_timeout"
  id="python-read-timeout"
  type="TimeSpan | float"
  default="5 s"
>
  How long to wait for a response. A number is seconds.
</Field.Item>

<Field.Item
  name="keep_alive"
  id="python-keep-alive"
  type="TimeSpan | float"
  default="30 s"
>
  How often the client pings the Core on each stream connection, such as the connection
  of a streamer or a writer. A number is seconds.
</Field.Item>

<Field.Item name="max_retries" id="python-max-retries" type="int" default="3">
  How many times to retry a request that fails to reach the Core.
</Field.Item>

<Field.Item
  name="clock_skew_threshold"
  id="python-clock-skew-threshold"
  type="TimeSpan"
  default="1 s"
>
  The largest difference between the clocks of the computer and the Core before the
  client prints a warning.
</Field.Item>

</Field.List>

  </Fragment>

  <Fragment slot="typescript">

<Field.List>

<Field.Item name="host" id="typescript-host" type="string">
  The hostname or IP address of the Core. Without it, the client reads the [environment
  variables](#connect-with-environment-variables).
</Field.Item>

<Field.Item name="port" id="typescript-port" type="number | string">
  The port of the Core.
</Field.Item>

<Field.Item name="apiKey" id="typescript-api-key" type="string">
  The API key to log in with. See [Connect with an API key](#connect-with-an-api-key).
</Field.Item>

<Field.Item name="username" id="typescript-username" type="string">
  The username to log in with.
</Field.Item>

<Field.Item name="password" id="typescript-password" type="string">
  The password to log in with.
</Field.Item>

<Field.Item name="secure" id="typescript-secure" type="boolean" default="false">
  Connect with TLS.
</Field.Item>

<Field.Item
  name="connectivityPollFrequency"
  id="typescript-connectivity-poll-frequency"
  type="TimeSpan"
  default="30 s"
>
  How often the client checks that it can reach the Core.
</Field.Item>

<Field.Item
  name="clockSkewThreshold"
  id="typescript-clock-skew-threshold"
  type="TimeSpan"
  default="1 s"
>
  The largest difference between the clocks of the computer and the Core before the
  client prints a warning.
</Field.Item>

<Field.Item name="name" id="typescript-name" type="string">
  A name for the Core, which the client shows in its connection status messages.
</Field.Item>

<Field.Item name="retry" id="typescript-retry" type="object">
  How the client retries a request that fails to reach the Core: `baseInterval` (1 s),
  `maxInterval`, `maxRetries` (5), `scale` (1), and `jitter` (0).
</Field.Item>

<Field.Item name="cache" id="typescript-cache" type="boolean" default="true">
  Keep retrieved resources in memory and update them as they change on the Core.
</Field.Item>

<Field.Item name="onRetry" id="typescript-on-retry" type="function">
  Called each time the client retries a failed request. By default, the client logs a
  warning.
</Field.Item>

<Field.Item name="onInternalError" id="typescript-on-internal-error" type="function">
  Called with cache errors that have no caller to throw to. By default, the client logs
  the error.
</Field.Item>

</Field.List>

  </Fragment>
