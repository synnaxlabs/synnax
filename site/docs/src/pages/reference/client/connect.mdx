Create a client to connect your code to a Synnax Core. The client logs in with an API
key, or with the username and password of a [user](/reference/enterprise/users) on the
Core.

<Divider.Divider x />

## Connect to Synnax Desktop

Scripts on the same computer as Synnax Desktop can connect to its Core while it runs.
Synnax Desktop saves the address of its Core in `~/.synnax/desktop.json`, with the path
of `synnax-desktop-key`, a program that prints the API key. When you give no host, the
clients read the address and run that program to get the key:

<Client.Tabs exclude={["console"]}>

  <Fragment slot="python">

```python
import synnax as sy

client = sy.Synnax()
```

When you also saved a login with [`sy login`](#log-in-once-with-sy-login), `sy.Synnax()`
uses that login, not Synnax Desktop.

  </Fragment>

  <Fragment slot="typescript">

```typescript
import { Synnax } from "@synnaxlabs/client";

const client = new Synnax();
```

The arguments and the [environment variables](#connect-with-environment-variables) that
you set come first.

This works in Node.js, Bun, and Deno. In Deno, give these flags:

```bash
deno run --allow-sys=homedir --allow-read="$HOME/.synnax" --allow-run --allow-env \
  my_script.ts
```

Without `--allow-sys` or `--allow-read`, the client cannot see Synnax Desktop and asks
for a host. Without `--allow-run` or `--allow-env`, it throws an error that names the
flag. A browser cannot read the file, so give a host. When there is no file, the
constructor throws `ValidationError`. When Synnax Desktop is closed, `connect` throws
`DisconnectedError`, as for any Core that does not answer. On Linux, the key program of
an AppImage goes away when Synnax Desktop closes, so the constructor throws
`Unreachable` from `@synnaxlabs/freighter` first.

  </Fragment>

</Client.Tabs>

To get the code for each client, click the code button in the top bar of Synnax Desktop,
or run the **Connect from code** command. The dialog shows the install command that
matches the version of Synnax Desktop, and code that you can copy. The **TypeScript**
tab gives code with the address and the API key filled in.

<Video id="client/connect/desktop" />

When you close Synnax Desktop, its Core stops, and the connected scripts lose their
connection. The API key stays the same the next time you open it. The port also stays
the same, unless another program uses it.

To stop every script that uses the key, click **Reset key** in the dialog. Open
streamers and writers stop with a
[session ended](/reference/client/troubleshooting#session-ended) error. Scripts that
create the client with no host use the new key the next time they start. Code that holds
the old key needs the new one. **Erase all data** also deletes the key.

## Connect with arguments

<Client.Tabs exclude={["console"]}>

  <Fragment slot="python">

```python
import synnax as sy

client = sy.Synnax(
    host="core.example.com",
    port=9090,
    username="operator",
    password="secret",
)
```

The client logs in when you create it. It raises `sy.AuthError` when the credentials are
wrong. It raises `Unreachable`, from the `freighter` package, when it cannot reach the
Core.

  </Fragment>

  <Fragment slot="typescript">

```typescript
import { Synnax } from "@synnaxlabs/client";

const client = new Synnax({
  host: "core.example.com",
  port: 9090,
  username: "operator",
  password: "secret",
});
await client.connect();
```

The client starts to connect when you create it, but it does not wait. `connect` waits
for the connection. It throws `AuthError` when the credentials are wrong, and
`DisconnectedError` when it cannot reach the Core. Without `connect`, the first request
throws the same errors.

  </Fragment>

</Client.Tabs>

To keep credentials out of a script, set them in the
[environment variables](#connect-with-environment-variables).

## Connect with an API key

An API key lets a script log in with no password. The client gets the permissions of the
user that owns the key. To get a key:

- **Synnax Desktop** -> the TypeScript code in the **Connect from code** dialog holds a
  key. See [Connect to Synnax Desktop](#connect-to-synnax-desktop).
- **A Core in Synnax Enterprise** -> in the Console, right-click a user in the users
  toolbar and select **Manage sign-in**. Enter a key name, then click **Create key**.
  Copy the key at once: the Core does not show it again. See
  [Users](/reference/enterprise/users).
- **`sy login`** -> the command makes a key for you and saves it. See
  [Log in once with sy login](#log-in-once-with-sy-login).

<Client.Tabs exclude={["console"]}>

  <Fragment slot="python">

```python
import synnax as sy

client = sy.Synnax(
    host="core.example.com",
    port=9090,
    api_key="syk_...",
)
```

An API key needs a host. With an API key and no host, the client raises
`sy.ValidationError`.

  </Fragment>

  <Fragment slot="typescript">

```typescript
import { Synnax } from "@synnaxlabs/client";

const client = new Synnax({
  host: "core.example.com",
  port: 9090,
  apiKey: "syk_...",
});
```

In Node.js, Deno, and Bun, the client sends its session token in the `Authorization`
header of each stream connection. A browser cannot set headers on a WebSocket, so a
browser client sends the token in the `Sec-WebSocket-Protocol` header. The client never
puts the token in the URL.

  </Fragment>

</Client.Tabs>

Give an API key or a username and password, not both. The client rejects a call that
gives both. When someone deletes or resets the key, the client fails with an
[invalid credentials](/reference/client/troubleshooting#invalid-credentials) error.

## Log in once with sy login

The `sy login` command saves an API key, so Python scripts can connect with no
arguments. It is part of the Python client. Run it in a terminal:

```bash
sy login
```

Answer the prompts. Press **Enter** to keep the default in brackets:

```
Enter your Synnax connection parameters:
Host [localhost]: core.example.com
Port [9090]:
Username [synnax]: operator
Password:
Secure connection? [y/N]:
```

When you answer `y` to the secure prompt, the command also asks for the "CA certificate
path". Enter the path to the `ca.crt` file of the Core. Leave it empty when the Core has
a certificate from a public authority.

The command connects to the Core and prints "Connection successful!". Then it makes an
API key named "Python CLI on" and the name of your computer, saves the key, and prints
"Saved an API key". In your scripts, create the client with no arguments:

```python
import synnax as sy

client = sy.Synnax()
```

The command saves the host, port, TLS setting, and CA certificate path in
`~/.synnax/config.json`. It saves the API key in the keychain of your operating system,
under the name `synnax.api_key`. It does not save your username or password, and it
deletes a password that an older version saved. In the Console, the key shows in
**Manage sign-in** for your user. When the login fails, the command prints why, saves
nothing, and exits with code 1. Run `sy login` again to change the values.

`sy login` never saves the key in a file. When the session has no keychain, the command
fails and saves nothing. See [Connect without a keychain](#connect-without-a-keychain).

When no argument or [environment variable](#connect-with-environment-variables) gives a
host, `sy.Synnax()` uses the saved login, then
[Synnax Desktop](#connect-to-synnax-desktop). The arguments and variables that you set
override its values.

## Connect with environment variables

The clients read these environment variables. They take an API key, not a username and
password.

| Variable         | Value                                                       |
| ---------------- | ----------------------------------------------------------- |
| `SYNNAX_HOST`    | The host of the Core.                                       |
| `SYNNAX_API_KEY` | An API key.                                                 |
| `SYNNAX_PORT`    | The port of the Core. The default is `9090`.                |
| `SYNNAX_SECURE`  | `true` or `1` to use TLS. The default is `false`.           |
| `SYNNAX_CA_CERT` | The path to the PEM file of the CA certificate of the Core. |

Each client takes each option from the first source that sets it: the argument, then its
variable, then its default.

| Python    | TypeScript | Variable         | Default |
| --------- | ---------- | ---------------- | ------- |
| `host`    | `host`     | `SYNNAX_HOST`    | None    |
| `port`    | `port`     | `SYNNAX_PORT`    | `9090`  |
| `api_key` | `apiKey`   | `SYNNAX_API_KEY` | None    |
| `secure`  | `secure`   | `SYNNAX_SECURE`  | False   |
| `ca_cert` | `caCert`   | `SYNNAX_CA_CERT` | None    |

<Client.Tabs exclude={["console"]}>

  <Fragment slot="python">

When no argument or variable gives a host, the saved Core comes before the default. The
saved Core is the login that `sy login` saved, else Synnax Desktop on this computer.

Two groups come whole from the first source that sets one of their options:

- The credentials: `api_key`, `username`, and `password`. A `username` and `password`
  replace the API key of a variable or of the saved Core.
- TLS: `secure` and `ca_cert`. `secure=True` with no `ca_cert` uses the CA certificates
  of the computer, even when `SYNNAX_CA_CERT` is set. A `ca_cert` with no `secure` turns
  TLS on.

To keep the API key out of your code, give the host and set only `SYNNAX_API_KEY`:

```python
client = sy.Synnax(host="core.example.com", port=9090)
```

```bash
export SYNNAX_API_KEY=syk_...
python my_script.py
```

When no source gives a host or credentials, or when `SYNNAX_PORT` or `SYNNAX_SECURE` has
a value that is not valid, the client raises `sy.ValidationError`.

  </Fragment>

  <Fragment slot="typescript">

`secure` and [`caCert`](#typescript-ca-cert) come as a pair from the first source that
sets one of them: the arguments, then `SYNNAX_SECURE` and `SYNNAX_CA_CERT`, then Synnax
Desktop. A `secure` argument with no `caCert` ignores `SYNNAX_CA_CERT`. A `caCert` or
`SYNNAX_CA_CERT` with no `secure` turns TLS on. `SYNNAX_CA_CERT` with
`SYNNAX_SECURE=false` is an error. `caCert` takes the PEM text, and `SYNNAX_CA_CERT`
takes the path of the file. A leading `~` in the path is your home directory.

To keep the API key out of your code, give the host and set only `SYNNAX_API_KEY`:

```typescript
import { Synnax } from "@synnaxlabs/client";

const client = new Synnax({ host: "core.example.com", port: 9090 });
```

```bash
export SYNNAX_API_KEY=syk_...
node my_script.js
```

The client does not read `SYNNAX_API_KEY` when you give a username, a password, or a
token. With no host from the argument or `SYNNAX_HOST`, the client fills the options
that are still missing from [Synnax Desktop](#connect-to-synnax-desktop). When no source
gives a host, when `SYNNAX_PORT` or `SYNNAX_SECURE` has a value that is not valid, or
when the file of `SYNNAX_CA_CERT` is missing, empty, or not PEM text, the constructor
throws `ValidationError`.

The client reads the variables in Node.js, Deno, and Bun. A browser has no environment
variables. In Deno, run the script with `--allow-env` to read the variables. Without it,
the client treats them as unset, so give the options as arguments. In a terminal, Deno
can ask for access first. Add `--deny-env` to stop the question.

  </Fragment>

</Client.Tabs>

### Connect without a keychain

`sy login` keeps the API key in the keychain of your operating system. Some sessions
have no keychain that works:

- SSH sessions, and Linux computers with no desktop.
- Docker containers.
- CI jobs, cron jobs, and system services.

In these sessions, set `SYNNAX_HOST` and `SYNNAX_API_KEY` instead of running `sy login`.
When a login is saved and the keychain is not available, `sy.Synnax()` raises
`sy.ConfigurationError`. It does not connect to Synnax Desktop or to another Core.

On Linux, a keychain that is locked can wait for a password prompt that an SSH session
cannot show. If a script stops at `sy.Synnax()` over SSH, set the environment variables.

## Connect with TLS

When the Core serves TLS, set `secure` to true. For how to give the Core a certificate,
see [Set up TLS](/reference/enterprise/tls).

<Client.Tabs exclude={["console"]}>

  <Fragment slot="python">

```python
client = sy.Synnax(
    host="core.example.com",
    port=9090,
    username="operator",
    password="secret",
    secure=True,
)
```

The Python client checks the certificate of the Core, and checks that the certificate is
for the host that you connect to. A certificate from a public authority, such as Let's
Encrypt, needs no setup. When the Core uses a self-signed certificate, give the path to
its CA certificate in `ca_cert`:

```python
client = sy.Synnax(
    host="core.example.com",
    port=9090,
    username="operator",
    password="secret",
    secure=True,
    ca_cert="/path/to/ca.crt",
)
```

A Core that you start with `--auto-cert` makes its own CA certificate. Give its path in
`ca_cert`, or save it with [`sy login`](#log-in-once-with-sy-login). To find the file,
see
[Copy the CA certificate](/reference/enterprise/certificates#copy-the-ca-certificate).

  </Fragment>

  <Fragment slot="typescript">

```typescript
const client = new Synnax({
  host: "core.example.com",
  port: 9090,
  username: "operator",
  password: "secret",
  secure: true,
});
```

The TypeScript client checks the certificate of the Core. When the Core uses a
self-signed certificate, give the text of its CA certificate in `caCert`:

```typescript
import { readFileSync } from "node:fs";

const client = new Synnax({
  host: "core.example.com",
  port: 9090,
  username: "operator",
  password: "secret",
  secure: true,
  caCert: readFileSync("/path/to/ca.crt", "utf8"),
});
```

`caCert` works in Node.js and Bun. In Deno, leave out `caCert` and give Deno the CA file
with `--cert /path/to/ca.crt` or `DENO_CERT`. In Deno, `SYNNAX_CA_CERT` turns on TLS,
but the client does not read the file. Set `DENO_CERT` to the same file. Deno does not
expand `~`, so give both variables an absolute path:

```bash
export SYNNAX_CA_CERT="$HOME/ca.crt"
export DENO_CERT="$SYNNAX_CA_CERT"
```

A browser cannot use `caCert`.
[Install the CA certificate](/reference/enterprise/certificates) on the computer
instead.

  </Fragment>

</Client.Tabs>

## Connect from a web page

The TypeScript client also runs in a web page. The Core accepts requests from pages on
each origin, so a page that you serve from a different host can connect to it. Each
person who opens the page can read the API key or password in its code, so do not put
them in a public page.

For a page on the same origin as the Core, such as a page behind a reverse proxy that
also forwards the routes of the Core, set `sessionCookie` to `true`. The Core then keeps
the session token in a cookie that page scripts cannot read. The cookie works only for
pages on the origin of the Core.

## Close the client

Close the client when your code is done with it:

<Client.Tabs exclude={["console"]}>

  <Fragment slot="python">

```python
client.close()
```

`close` also logs out. When the script exits without `close`, the client stops, but its
session stays open on the Core until it times out.

  </Fragment>

  <Fragment slot="typescript">

```typescript
await client.close();
```

A Node.js script does not exit until you close the client.

  </Fragment>

</Client.Tabs>
