## pip installs an old synnax version

The Python client needs Python 3.12 or later. On an older Python, `pip install synnax`
installs an old release with no error. Check the version that pip installed:

```bash
pip show synnax
```

With a version pin, pip fails instead:

```
ERROR: Ignored the following versions that require a different python version: 0.33.0 Requires-Python <4.0,>=3.12; ...
ERROR: Could not find a version that satisfies the requirement synnax==0.58.*
```

Install Python 3.12 or later from [python.org](https://www.python.org/downloads/) or
with the package manager of your operating system. Then install the client in a virtual
environment of the new Python:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install synnax
```

## externally-managed-environment

```
error: externally-managed-environment
```

Your operating system manages this Python, so pip does not install packages into it.
Install the client in a virtual environment, as the commands above show.

## sy: command not found

The Python client installs the `sy` command. The shell cannot find it when:

- **The client is in a virtual environment.** Activate the environment, or run the
  command through your environment manager, such as `uv run sy login` or
  `poetry run sy login`.
- **The pip that you used is for a different Python.** Check with `pip --version`. Then
  install with the Python that you use: `python3.12 -m pip install synnax`.
- **The scripts folder of Python is not on your `PATH`.** pip prints a warning with the
  folder when it installs the client. Add that folder to your `PATH`.

## Promise.withResolvers is not a function

```
TypeError: Promise.withResolvers is not a function
```

```
ReferenceError: WebSocket is not defined
```

The TypeScript client needs Node.js 22 or later. On an older Node.js, `connect` does not
return, and reads, writes, and streamers throw these errors. Check your version with
`node --version`, and update Node.js from [nodejs.org](https://nodejs.org).

## Synnax is not a constructor

```
SyntaxError: The requested module '@synnaxlabs/client' does not provide an export named 'default'
```

```
TypeError: Synnax is not a constructor
```

```
Error [ERR_REQUIRE_ESM]: require() of ES Module
```

The TypeScript client is an ES module with no default export. Import `Synnax` by name
with `import`, not `require`:

```typescript
import { Synnax } from "@synnaxlabs/client";
```

## Measured excessive clock skew

```
Measured excessive clock skew between this host and the Synnax Core. This host is ahead of the Synnax Core by approximately 2s.
```

The clocks of your computer and the Core differ by more than one second. Timestamps that
your code makes are then wrong by the same amount. Synchronize both clocks with a time
server, for example with NTP.

```
invalid credentials: auth error
```

The username or password is wrong. To change a saved Python login, run `sy login` again.

## No configuration file was found

```
ValidationError: No options provided and no configuration file was found. Please provide options or login via the CLI using the `sy login` command.
```

You created a Python client with no arguments, and there is no saved login. Run
`sy login`, or give the connection values to `sy.Synnax`. See
[Connect to a Core](/reference/client/connect).

## Write overlaps with existing data

```
cannot open writer because there is already data in the writer's time range
```

```
write overlaps with existing data in database
```

A channel already has samples in the time range of the write. The first error comes when
the writer opens, and the second when it commits. Write to a time range that has no
samples, or [delete the samples](/reference/client/delete-data) first.

<Divider.Divider x />

## Frame must have the same length for all series

```
frame must have the same length for all series
```

The client raises a `ValidationError`. In one write, an index channel and its data
channels need the same number of samples. See
[Rule 1](/reference/client/write-data#rule-1).

<Divider.Divider x />

## Received no data for index channel

```
received no data for index channel [time]<1> that must be provided when writing to related data channels [[temperature]<2>]
```

The write holds samples for a data channel, but not for its index channel. Add the
timestamps to the write, or turn on auto-index. See
[the rules of writes](/reference/client/write-data#the-rules-of-writes).
