## pip installs an old synnax version

With a version pin, pip fails with this error instead:

```
ERROR: Ignored the following versions that require a different python version: 0.62.0 Requires-Python <4,>=3.13; ...
ERROR: Could not find a version that satisfies the requirement synnax==0.62.*
```

<Problem.Body>
<Problem.Cause>

The Python client needs Python 3.13 or later. On an older Python, `pip install synnax`
installs an old release with no error. To see the version that pip installed, run
`pip show synnax`.

</Problem.Cause>
<Problem.Fix>

1. Install Python 3.13 or later from [python.org](https://www.python.org/downloads/) or
   with the package manager of your operating system.
2. Install the client in a virtual environment of the new Python:

   ```bash
   python3.13 -m venv .venv
   source .venv/bin/activate
   pip install synnax
   ```

</Problem.Fix>
</Problem.Body>

## sy: command not found

<Problem.Body>
<Problem.Cause>

The shell cannot find the `sy` command that the Python client installs.

</Problem.Cause>
<Problem.Fix>

- **The client is in a virtual environment** -> activate the environment, or run the
  command through your environment manager, such as `uv run sy login` or
  `poetry run sy login`.
- **The pip that you used is for a different Python** -> check with `pip --version`.
  Then install with the Python that you use: `python3.13 -m pip install synnax`.
- **The scripts folder of Python is not on your `PATH`** -> pip prints a warning with
  the folder when it installs the client. Add that folder to your `PATH`.

</Problem.Fix>
</Problem.Body>

## Promise.withResolvers is not a function

```
TypeError: Promise.withResolvers is not a function
```

```
ReferenceError: WebSocket is not defined
```

```
Error [ERR_REQUIRE_ESM]: require() of ES Module
```

<Problem.Body>
<Problem.Cause>

The TypeScript client needs Node.js 22.12 or later. On Node.js 21 or earlier, `connect`
does not return, and reads, writes, and streamers throw these errors. On Node.js 22.0 to
22.11, `require()` of the client fails with `ERR_REQUIRE_ESM`.

</Problem.Cause>
<Problem.Fix>

Update Node.js to version 22.12 or later from [nodejs.org](https://nodejs.org). To see
your version, run `node --version`.

</Problem.Fix>
</Problem.Body>

## Synnax is not a constructor

```
SyntaxError: The requested module '@synnaxlabs/client' does not provide an export named 'default'
```

```
TypeError: Synnax is not a constructor
```

<Problem.Body>
<Problem.Cause>

The TypeScript client is an ES module with no default export.

</Problem.Cause>
<Problem.Fix>

Import `Synnax` by name:

```typescript

```

</Problem.Fix>
</Problem.Body>

## Core version not supported

```
Client 0.61.0 cannot work with Core 0.60.0.
```

<Problem.Body>
<Problem.Cause>

The TypeScript client cannot read the replies of the Core, and the major or minor
version of the Core is not the same as the client. The connection status shows this
message and description. `connect` rejects with the error that the client got from the
Core, not with this text. The client keeps checking the Core, and connects again when
the Core changes. If you set a finite `retry.maxRetries`, call
`client.connection.retryNow()` after you change the Core.

</Problem.Cause>
<Problem.Fix>

Install the client version that matches the Core:

```bash
npm install @synnaxlabs/client@0.60
```

You can also [upgrade the Core](/reference/enterprise/upgrade).

</Problem.Fix>
</Problem.Body>

## Measured excessive clock skew

```
Measured excessive clock skew between this host and the Synnax Core. This host is ahead of the Synnax Core by approximately 2s.
```

<Problem.Body>
<Problem.Cause>

The clocks of your computer and the Core differ by more than one second. Timestamps that
your code makes are then wrong by the same amount.

</Problem.Cause>
<Problem.Fix>

Synchronize both clocks with a time server, for example with NTP.

</Problem.Fix>
</Problem.Body>

```

  </Fragment>

```

<Problem.Body>
<Problem.Cause>

One of these:

- The Core does not run, or the host or the port is wrong.
- A firewall blocks the port.
- `secure` does not match the Core.

</Problem.Cause>
<Problem.Fix>

1. Check that the Core runs, and that the host and the port are correct.
2. Check that no firewall blocks the port.
3. Set `secure` to true when the Core serves TLS, and to false when it does not.

</Problem.Fix>
</Problem.Body>

The session of an open streamer, writer, or iterator ended. Someone reset or deleted the
API key, or the session timed out.

</Problem.Fix>

## No OS keychain is available

```
ConfigurationError: Cannot read the login saved for core.example.com:9090. No OS keychain is available in this session. Set SYNNAX_HOST and SYNNAX_API_KEY instead.
```

<Problem.Body>
<Problem.Cause>

The Python client keeps the API key from `sy login` in the keychain of your operating
system, and this session cannot use it. This happens over SSH, in Docker, in CI, and in
cron jobs. When `sy login` cannot save a key, it prints the message without its first
sentence.

</Problem.Cause>
<Problem.Fix>

Set `SYNNAX_HOST` and `SYNNAX_API_KEY` in the session. See
[Connect without a keychain](/reference/client/connect#connect-without-a-keychain).

</Problem.Fix>
</Problem.Body>

## Synnax Desktop is not running

```
Synnax Desktop is not running. Open it and try again. To connect to another Core, give a host and a port.
```

<Problem.Body>
<Problem.Cause>

You created a client with no host, and it found the Core of
[Synnax Desktop](/reference/client/connect#connect-to-synnax-desktop). Synnax Desktop is
closed, or its Core has not started. On Linux, the key helper of an AppImage is gone
after Synnax Desktop closes, so the client cannot get the API key.

</Problem.Cause>
<Problem.Fix>

Open Synnax Desktop and wait until the workspace shows, then run the script again.

</Problem.Fix>
</Problem.Body>

## The key helper of Synnax Desktop failed

```
ConfigurationError: The key helper of Synnax Desktop failed: failed to read the Synnax Desktop API key: Synnax Desktop has saved no API key. Open Synnax Desktop to save one.
```

<Problem.Body>
<Problem.Cause>

You created a Python client with no arguments, and it ran `synnax-desktop-key` to get
the API key of [Synnax Desktop](/reference/client/connect#connect-to-synnax-desktop).
The program could not read the key from the keychain of your operating system. The text
after `failed:` tells why. A message that says `Cannot run the key helper` means that
the program at the path in `~/.synnax/desktop.json` cannot start.

</Problem.Cause>
<Problem.Fix>

Open Synnax Desktop and wait until the workspace shows, then run the script again. If
the program cannot start, update or install Synnax Desktop again. Over SSH or in a
session with no keychain, set `SYNNAX_HOST` and `SYNNAX_API_KEY` instead.

</Problem.Fix>
</Problem.Body>

## Write overlaps with existing data

```
cannot open writer because there is already data in the writer's time range
```

```
cannot start writer because there is already data in the writer's time range
```

```
write overlaps with existing data in database
```

<Problem.Body>
<Problem.Cause>

A channel already has samples in the time range of the write. The first error comes when
a writer with a `start` opens. The second comes at the first write of a writer with no
`start`. The third comes when the writer commits.

</Problem.Cause>
<Problem.Fix>

Write to a time range that has no samples, or
[delete the samples](/reference/client/delete-data) first.

</Problem.Fix>
</Problem.Body>

<Divider.Divider x />

## Frame must have the same length for all series

```
frame must have the same length for all series
```

<Problem.Body>
<Problem.Cause>

In one write, an index channel and its data channels need the same number of samples.
The client raises a `ValidationError`.

</Problem.Cause>
<Problem.Fix>

Give the index channel and each of its data channels the same number of samples. See
[Rule 1](/reference/client/write-data#rule-1).

</Problem.Fix>
</Problem.Body>

## Received no data for index channel

```
received no data for index channel [time]<1> that must be provided when writing to related data channels [[temperature]<2>]
```

<Problem.Body>
<Problem.Cause>

The write holds samples for a data channel, but not for its index channel.

</Problem.Cause>
<Problem.Fix>

Add the timestamps to the write, or turn on auto-index. See
[the rules of writes](/reference/client/write-data#the-rules-of-writes).

</Problem.Fix>
</Problem.Body>

## Stream holds more than 268435456 bytes of unread messages

```
stream holds more than 268435456 bytes of unread messages
```

<Problem.Body>
<Problem.Cause>

A TypeScript streamer got frames faster than your code read them. The client keeps
unread frames in memory, and closes the streamer when they pass 256 MB.

</Problem.Cause>
<Problem.Fix>

Read frames faster, or send fewer of them. See
[Slow the stream](/reference/client/stream-data#slow-the-stream).

</Problem.Fix>
</Problem.Body>
