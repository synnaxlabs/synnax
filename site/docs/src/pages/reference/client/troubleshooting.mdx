## pip installs an old synnax version

With a version pin, pip fails with this error instead:

```
ERROR: Ignored the following versions that require a different python version: 0.33.0 Requires-Python <4.0,>=3.12; ...
ERROR: Could not find a version that satisfies the requirement synnax==0.58.*
```

<Problem.Body>
<Problem.Cause>

The Python client needs Python 3.12 or later. On an older Python, `pip install synnax`
installs an old release with no error. To see the version that pip installed, run
`pip show synnax`.

</Problem.Cause>
<Problem.Fix>

1. Install Python 3.12 or later from [python.org](https://www.python.org/downloads/) or
   with the package manager of your operating system.
2. Install the client in a virtual environment of the new Python:

   ```bash
   python3.12 -m venv .venv
   source .venv/bin/activate
   pip install synnax
   ```

</Problem.Fix>
</Problem.Body>

## externally-managed-environment

```
error: externally-managed-environment
```

<Problem.Body>

Your operating system manages this Python, so pip does not install packages into it.

</Problem.Cause>
<Problem.Fix>

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install synnax
```

</Problem.Fix>
</Problem.Body>

## sy: command not found

<Problem.Body>
<Problem.Cause>

The shell cannot find the `sy` command that the Python client installs.

</Problem.Cause>
<Problem.Fix>

- **The client is in a virtual environment** -> activate the environment, or run the
  command through your environment manager, such as `uv run sy login` or
  `poetry run sy login`.
- **The pip that you used is for a different Python** -> check with `pip --version`.
  Then install with the Python that you use: `python3.12 -m pip install synnax`.
- **The scripts folder of Python is not on your `PATH`** -> pip prints a warning with
  the folder when it installs the client. Add that folder to your `PATH`.

</Problem.Fix>
</Problem.Body>

## Promise.withResolvers is not a function

```
TypeError: Promise.withResolvers is not a function
```

```
ReferenceError: WebSocket is not defined
```

<Problem.Body>
<Problem.Cause>

The TypeScript client needs Node.js 22 or later. On an older Node.js, `connect` does not
return, and reads, writes, and streamers throw these errors.

</Problem.Cause>
<Problem.Fix>

Update Node.js to version 22 or later from [nodejs.org](https://nodejs.org). To see your
version, run `node --version`.

</Problem.Fix>
</Problem.Body>

## Synnax is not a constructor

```
SyntaxError: The requested module '@synnaxlabs/client' does not provide an export named 'default'
```

```
TypeError: Synnax is not a constructor
```

```
Error [ERR_REQUIRE_ESM]: require() of ES Module
```

<Problem.Body>
<Problem.Cause>

The TypeScript client is an ES module with no default export.

</Problem.Cause>
<Problem.Fix>

Import `Synnax` by name with `import`, not `require`:

```typescript
import { Synnax } from "@synnaxlabs/client";
```

</Problem.Fix>
</Problem.Body>

## Measured excessive clock skew

```
Measured excessive clock skew between this host and the Synnax Core. This host is ahead of the Synnax Core by approximately 2s.
```

<Problem.Body>
<Problem.Cause>

The clocks of your computer and the Core differ by more than one second. Timestamps that
your code makes are then wrong by the same amount.

</Problem.Cause>
<Problem.Fix>

Synchronize both clocks with a time server, for example with NTP.

</Problem.Fix>
</Problem.Body>

## Cannot reach the Core

<Client.Tabs exclude={["console"]}>

  <Fragment slot="python">

```
Failed to reach cluster at core.example.com:9090
```

  </Fragment>

  <Fragment slot="typescript">

```
Cannot reach Core at core.example.com:9090
```

  </Fragment>

</Client.Tabs>

<Problem.Body>
<Problem.Cause>

One of these:

- The Core does not run, or the host or the port is wrong.
- A firewall blocks the port.
- `secure` does not match the Core.

</Problem.Cause>
<Problem.Fix>

1. Check that the Core runs, and that the host and the port are correct.
2. Check that no firewall blocks the port.
3. Set `secure` to true when the Core serves TLS, and to false when it does not.

</Problem.Fix>
</Problem.Body>

## Write overlaps with existing data

```
cannot open writer because there is already data in the writer's time range
```

```
write overlaps with existing data in database
```

<Problem.Body>
<Problem.Cause>

A channel already has samples in the time range of the write. The first error comes when
the writer opens, and the second when it commits.

</Problem.Cause>
<Problem.Fix>

Write to a time range that has no samples, or
[delete the samples](/reference/client/delete-data) first.

</Problem.Fix>
</Problem.Body>

<Divider.Divider x />

## Frame must have the same length for all series

```
frame must have the same length for all series
```

<Problem.Body>
<Problem.Cause>

In one write, an index channel and its data channels need the same number of samples.
The client raises a `ValidationError`.

</Problem.Cause>
<Problem.Fix>

Give the index channel and each of its data channels the same number of samples. See
[Rule 1](/reference/client/write-data#rule-1).

</Problem.Fix>
</Problem.Body>

## Received no data for index channel

```
received no data for index channel [time]<1> that must be provided when writing to related data channels [[temperature]<2>]
```

<Problem.Body>
<Problem.Cause>

The write holds samples for a data channel, but not for its index channel.

</Problem.Cause>
<Problem.Fix>

Add the timestamps to the write, or turn on auto-index. See
[the rules of writes](/reference/client/write-data#the-rules-of-writes).

</Problem.Fix>
</Problem.Body>
