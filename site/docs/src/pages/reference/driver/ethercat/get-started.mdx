The Synnax Driver supports reading and writing data from
[EtherCAT](https://www.ethercat.org/) devices. EtherCAT (Ethernet for Control Automation
Technology) is a real-time industrial Ethernet protocol designed for high-performance
automation and control applications.

<Divider.Divider x />

## Supported EtherCAT masters

The Synnax Driver supports two EtherCAT master implementations:

### IgH EtherCAT Master

The [IgH EtherCAT Master](https://etherlab.org/en_GB/ethercat) is a Linux kernel module
that provides deterministic, real-time EtherCAT communication.

- **Recommended for production deployments**
- Higher performance with deterministic timing
- Requires kernel module installation
- Linux only (including NI Linux Real-Time)

<Note.Note variant="info">
  For installation instructions, see the [IgH EtherCAT Master
  documentation](https://etherlab.org/en_GB/ethercat). Note that IgH requires a
  compatible network interface card.
</Note.Note>

### SOEM (Simple Open EtherCAT Master)

[SOEM](https://github.com/OpenEtherCATsociety/SOEM) is a user-space EtherCAT master
library that runs on multiple platforms.

- **Bundled with the Synnax Driver** - no additional installation required
- Cross-platform: Windows, macOS, and Linux
- Good for development, testing, and non-real-time applications
- Does not require kernel modifications

## Network interface access

EtherCAT sends raw Ethernet frames, so the Driver needs direct access to the network
interface. Connect your devices to a dedicated Ethernet port. Do not connect that port
to a switch or to your office network.

| Platform                    | What the Driver needs                                                                                                      |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Linux service               | Nothing. The service has raw Ethernet access and IgH access.                                                               |
| Linux, embedded in the Core | Run the Core as root. Without IgH, you can also start the Core from a systemd unit with `AmbientCapabilities=CAP_NET_RAW`. |
| NI Linux Real-Time          | Nothing. The service runs as root.                                                                                         |
| Windows                     | [Npcap](https://npcap.com/#download).                                                                                      |
| macOS                       | Root access, because only root can open the packet capture devices (`/dev/bpf*`).                                          |

The Core's Docker image runs as a user without these permissions, so its embedded Driver
cannot run EtherCAT tasks.

To start the Driver on Linux by hand, run it as root or give it the access that the
service has. Without IgH, the Driver needs the raw Ethernet capability:

```bash
sudo setcap cap_net_raw+ep /usr/local/bin/synnax-driver
```

With IgH, the Driver needs access to the master device (`/dev/EtherCAT0`) instead.
`sudo synnax-driver install` gives this access to the `synnax` group, so add your user
to that group, then log in again:

```bash
sudo usermod -aG synnax $USER
```

<Note.Note variant="info">
  A service installed by an older Driver does not have these permissions. To update it,
  run `sudo synnax-driver install` again.
</Note.Note>

## How the Driver runs a network

- **One bus per interface** -> All read and write tasks on a network interface share one
  bus. Starting or stopping one task does not interrupt the others.
- **Start and stop** -> The bus starts when the first task starts and stops when the
  last task stops.
- **Cycle rate** -> The bus cycles at the slowest rate that is a multiple of each read
  task's sample rate and at least each write task's rate. The rate is always between 100
  Hz and 10 kHz. For example, read tasks at 250 Hz and 1 kHz make the bus cycle at 1
  kHz.
- **Outputs** -> Each output holds the last value a write task commanded. When a write
  task stops, its outputs go to zero. An output that another running write task
  commanded keeps the last value of that task instead.
- **Lost devices** -> When a device stops responding, the bus continues to cycle and the
  Driver returns the device to operation when it responds again. Until then, every read
  task on the network drops samples and shows a warning.

## Key terminology

EtherCAT uses specific terminology that differs from other industrial protocols:

- **Master** -> The controller that manages the EtherCAT network (IgH or SOEM in
  Synnax).
- **Slave (Device)** -> An EtherCAT device on the network. This documentation uses
  "device" for clarity.
- **PDO (Process Data Object)** -> Cyclic data exchanged between master and devices.
- **TxPDO** -> Transmit PDO. Data sent FROM the device TO Synnax (sensor readings).
- **RxPDO** -> Receive PDO. Data sent TO the device FROM Synnax (control commands).
- **CoE (CAN over EtherCAT)** -> Protocol for accessing device parameters using index
  and subindex addressing.
