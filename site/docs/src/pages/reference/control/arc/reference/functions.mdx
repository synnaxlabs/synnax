A function declares inputs in parentheses, triggers in braces, and an optional output.
Functions are declared at the top level only.

```text
function = "func" name "(" params? ")" ("{" params? "}")? output?
           "{" statement* "}"
params   = name type ("=" literal)? ("," name type ("=" literal)?)*
```

```arc channels="tank_pt, tank_pt_kpa" bodies="scale"
func scale(k f64 = 1.0) {v f64} f64 {
    return v * k
}

tank_pt -> scale(k=6.895) -> tank_pt_kpa
```

| Part         | Required | Form                                                           |
| ------------ | -------- | -------------------------------------------------------------- |
| `(inputs)`   | Yes      | Parameters that a flow sets in parentheses. They can be empty. |
| `{triggers}` | No       | Parameters that values from upstream fill.                     |
| Output       | No       | `type`, `name type`, or `(name type, ...)`.                    |

A function with no parentheses is a parse error. A function declared in a function body
is a parse error too. The last braces of a declaration are the body, so `func f() { }`
has no triggers and `func f() {v f64} { }` has one.

## Inputs

A flow sets inputs in parentheses, such as `scale(k=6.895)`. A parameter type is a value
type, or `chan T` for a channel. For the values that the parentheses accept, see
[input values](/reference/control/arc/reference/flow#input-values).

An input or a trigger with `= literal` has a default and can be left out. Parameters
with defaults come last in their parentheses or braces. Otherwise the compiler fails
with `required input parameter b cannot follow optional input parameters` or
`required parameter b cannot follow optional parameters`.

A body reads a `chan` parameter, or any channel by name, to get its latest value. It
assigns to the channel to write it. See
[writes](/reference/control/arc/execution-model#writes).

```arc channels="tank_pt, press_vlv_cmd" bodies="bang_bang"
func bang_bang(sensor chan f64, cmd chan u8, low f64, high f64) {
    if sensor < low {
        cmd = 1
    } else if sensor > high {
        cmd = 0
    }
}

tank_pt -> bang_bang(sensor=tank_pt, cmd=press_vlv_cmd, low=280.0, high=300.0)
```

## Triggers

In a flow, the value from upstream fills the first trigger. The parentheses fill the
other triggers, such as `pt -> add(y=2.0)`. A function with no triggers runs on each
value from upstream, and does not use the value.

| Error                                                                                    | Cause                                                |
| ---------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| `missing required argument for parameter 'y' of func 'add'`                              | A parameter has no value.                            |
| `parameter 'x' of func 'add' is bound by both a call-site argument and an upstream wire` | The parentheses set the trigger that upstream fills. |

## Outputs

| Output        | Example                                        | Body                                          |
| ------------- | ---------------------------------------------- | --------------------------------------------- |
| None          | `func log() {v f64} { }`                       | `return` with no value only.                  |
| Unnamed       | `func double() {v f64} f64 { }`                | `return value` on all paths.                  |
| One named     | `func double() {v f64} result f64 { }`         | Assign `result`. A bare `return` is optional. |
| Several named | `func split() {v f64} (high f64, low f64) { }` | Assign one or more outputs.                   |

A function with an unnamed output must return on all paths. A `return` at the end of the
body counts, and so does an `if` with an `else` in which each branch returns. A `return`
in a `for` does not count:

```arc
func is_high() {v f64} u8 {
    if v > 500.0 {
        return 1
    }
}
// error: function 'is_high' must return a value of type u8 on all paths
```

A named output passes a value only in the calls that assign it. A flow with no routing
table passes only the first output: `split() -> out` writes only `high`. Route several
named outputs with a
[routing table](/reference/control/arc/reference/flow#custom-routing). An output that
the body never assigns gives the warning
`output 'low' is never assigned in function 'split'`. With a named output,
`return result` fails with `cannot return a value from a function with no return type`.

## Calls

| Where                | Example                                  | Arguments                                                        |
| -------------------- | ---------------------------------------- | ---------------------------------------------------------------- |
| Flow                 | `tank_pt -> scale(k=6.895)`              | Upstream fills the first trigger. The parentheses fill the rest. |
| Expression in a flow | `(median3(pt_1, pt_2, pt_3)) -> tank_pt` | By position: inputs, then triggers.                              |
| Function body        | `scale(6.895, v)`                        | By position: inputs, then triggers.                              |

In a flow, a bare `name(...)` is a function instance. Put an expression call in
parentheses. It reads each channel in its arguments:

```arc channels="pt_1, pt_2, pt_3, tank_pt" bodies="median3"
func median3() {a f64, b f64, c f64} f64 {
    if (a - b) * (c - a) >= 0.0 {
        return a
    } else if (b - a) * (c - b) >= 0.0 {
        return b
    }
    return c
}

(median3(pt_1, pt_2, pt_3)) -> tank_pt
```

A function can call itself. The compiler finds some recursion that never ends, such as
`circular function call: f -> f`, but not all of it.

## Stateful variables

A variable declared with `$=` keeps its value from one call to the next. Each call site
in a flow keeps its own state:

```arc channels="fast_count, slow_count" bodies="counter"
import time

func counter() i64 {
    count $= 0
    count = count + 1
    return count
}

time.interval(period=100ms) -> counter() -> fast_count
time.interval(period=1s) -> counter() -> slow_count
```

To learn when the state goes back to its first value, see
[entering a stage](/reference/control/arc/execution-model#entering-a-stage). Do not
declare `$=` variables in a function that a different function body calls. The two
functions can share state (known bug).

## Built-in functions

### len

`len(x) i64` returns the number of samples in a series, or the number of bytes in a
string. Call it in a function body only. In a flow, it fails with
`function 'len' cannot be used as a flow statement. Call it inside a func block instead: len()`.

```arc
func last() {data series f64} f64 {
    return data[len(data) - 1]
}
```
