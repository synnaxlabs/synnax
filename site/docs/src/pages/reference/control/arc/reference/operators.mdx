## Arithmetic

| Operator | Operation | Example  | Result |
| -------- | --------- | -------- | ------ |
| `+`      | Add       | `3 + 2`  | `5`    |
| `-`      | Subtract  | `5 - 2`  | `3`    |
| `-`      | Negate    | `-x`     |        |
| `*`      | Multiply  | `3 * 4`  | `12`   |
| `/`      | Divide    | `10 / 4` | `2`    |
| `%`      | Remainder | `10 % 3` | `1`    |
| `^`      | Power     | `2 ^ 8`  | `256`  |

- Integer `/` truncates toward zero: `-10 / 3` is `-3`. `10.0 / 4.0` is `2.5`.
- `%` takes integers only. A float `%` fails with `float modulo not yet implemented`.
- `^` is right-associative: `2 ^ 3 ^ 2` is `2 ^ 9`.
- Arc has no bitwise operators. `&` fails with `token recognition error at: '&'`.

### Division by zero

A float division by zero gives `+Inf`, `-Inf`, or `NaN`. An integer `/` or `%` by zero
is a runtime error, and the compiler does not check for it. See
[errors while it runs](/reference/control/arc/execution-model#errors-while-it-runs).

## Comparison

| Operator | Operation             | Example  | Result  |
| -------- | --------------------- | -------- | ------- |
| `==`     | Equal                 | `3 == 5` | `false` |
| `!=`     | Not equal             | `3 != 5` | `true`  |
| `<`      | Less than             | `3 < 5`  | `true`  |
| `>`      | Greater than          | `3 > 5`  | `false` |
| `<=`     | Less than or equal    | `3 <= 5` | `true`  |
| `>=`     | Greater than or equal | `3 >= 5` | `false` |

A comparison gives a `bool`. `<`, `>`, `<=`, and `>=` take numbers only. `==` and `!=`
also take `str` and `bool`.

Comparisons do not chain. Arc uses only the first two operands of a chain of `<`, `>`,
`<=`, and `>=`, or of `==` and `!=`. `1.0 < x < 3.0` compiles, but it tests only
`1.0 < x`. With `a` equal to `1`, `a == 1 == 5` is `true`. Write `x > 1.0 and x < 3.0`.

<Divider.Divider x />

## Logical

| Operator | Operation | Example          | Result  |
| -------- | --------- | ---------------- | ------- |
| `and`    | And       | `true and false` | `false` |
| `or`     | Or        | `false or true`  | `true`  |
| `not`    | Not       | `not true`       | `false` |

Logical operators take `bool` only. `x and true` with an `f64` `x` fails with
`cannot use f64 in and operation`. On single values, `and` and `or` stop when the left
side gives the result, so the right side does not run:

```arc bodies="ratio_high"
func ratio_high(a i64, b i64) bool {
    return b != 0 and a / b > 10
}
```

## Strings

`+` joins two strings. `==` and `!=` compare them. Other operators fail, for example
`cannot use str in - operation`. To join a number and a string, cast the number with
`str(x)` or use a
[format string](/reference/control/arc/reference/syntax#format-strings).

<Divider.Divider x />

## Series

Arithmetic, comparison, and logical operators work on a series one element at a time.
The other operand is a series of the same length or a single value. On a series, `and`
and `or` evaluate both sides. See
[series](/reference/control/arc/reference/types#series).

## Precedence

From highest to lowest:

| Level | Operators                | Associativity |
| ----- | ------------------------ | ------------- |
| 1     | `x[i]`, `x[a:b]`, `f(x)` | Left          |
| 2     | `^`                      | Right         |
| 3     | `-` (negate), `not`      | Right         |
| 4     | `*`, `/`, `%`            | Left          |
| 5     | `+`, `-`                 | Left          |
| 6     | `<`, `>`, `<=`, `>=`     | Left          |
| 7     | `==`, `!=`               | Left          |
| 8     | `and`                    | Left          |
| 9     | `or`                     | Left          |

`^` binds tighter than a `-` on its left: `-2 ^ 2` is `-(2 ^ 2)`, which is `-4`. Write
`(-2) ^ 2` for `4`. Use parentheses to change the order.

## Operand types

Both sides of an operator must have the same type. Arc does not convert one type to
another:

| Expression                   | Result                                                                             |
| ---------------------------- | ---------------------------------------------------------------------------------- |
| `x + y`, `x i32` and `y f64` | `type mismatch: cannot use i32 and f64 in + operation`                             |
| `a + b`, `a u8` and `b i32`  | `type mismatch: cannot use u8 and i32 in + operation`                              |
| `f64(x) + y`                 | `f64`                                                                              |
| `x * 2`, `x f32`             | `f32`. The literal takes the type of `x`.                                          |
| `x * 2.5`, `x i32`           | `type mismatch in * operands must be compatible: float is not compatible with i32` |

To mix types, cast one side. See [casts](/reference/control/arc/reference/types#casts).

## Truthiness

Before `=>`, a number is true when it is not zero. A `str` is true when it is not empty.
A number before `=>` or in an `if` condition gives a warning:

```text
numeric conditions are deprecated; use an explicit comparison like x != 0
```

In an `if`, a number works only when its type has 32 bits or less. An `i64`, `u64`,
`f32`, or `f64` condition compiles with the warning, then fails to load with
`cannot pop the operand for 'if': type mismatch: expected i32, but was f64`. A bare
`x := 5` is an `i64`, so `if x` fails too. This is a known bug. Always compare
explicitly: `if x != 0`, `start_cmd == 1 => fill`.
