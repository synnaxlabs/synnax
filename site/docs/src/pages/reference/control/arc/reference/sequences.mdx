A sequence runs its steps in order, one step at a time. Newlines or commas separate the
steps.

```text
sequence = "sequence" name? "{" step* "}"
```

```arc channels="start_cmd, press_vlv_cmd, tank_pt" bodies="press"
import time

sequence press {
    1 -> press_vlv_cmd
    tank_pt > 300 => next
    time.wait(duration=10s)
    0 -> press_vlv_cmd
}

start_cmd == 1 => press
```

To learn when a step moves on and when a sequence stops, see
[steps of a sequence](/reference/control/arc/execution-model#steps-of-a-sequence).

## Steps

| Step          | Example                                     |
| ------------- | ------------------------------------------- |
| Write         | `1 -> press_vlv_cmd`                        |
| Wait          | `time.wait(duration=10s)`                   |
| Gate          | `tank_pt > 300 => next`, or `tank_pt > 300` |
| Stage         | `stage hold { ... }`                        |
| Sequence      | `sequence { ... }`                          |
| Assignment    | `target = 400.0`                            |
| Function call | `notify()`                                  |

A step that is not a stage or a sequence moves on when the last node of the step outputs
a true value. When that node has no output, the step moves on after the node runs
without an error. A write always moves on. A wait moves on when its time is up. To learn
more, see
[steps of a sequence](/reference/control/arc/execution-model#steps-of-a-sequence).

<Note.Note variant="warning">
  Known bug: a step whose output is not true stalls the sequence. Examples are a
  function step whose output is 0 and an assignment such as `x = 0.0`.
</Note.Note>

A [stage](/reference/control/arc/reference/stages) or a nested sequence can have a name.
Other steps of the same sequence can move to a named step with `=> name`. A step with no
name is reached only in order.

Do not put an abort stage right after a write, a wait, or a gate. See
[steps of a sequence](/reference/control/arc/execution-model#steps-of-a-sequence).

Starting a sequence with an empty body fails with `sequence 'press' has no steps`.

## Starting a sequence

| Sequence             | Starts                                                     |
| -------------------- | ---------------------------------------------------------- |
| Named, top level     | When a flow targets it, such as `start_cmd == 1 => press`. |
| Anonymous, top level | When the automation starts.                                |
| Nested               | When its parent sequence or stage reaches it.              |

A flow that starts a top-level sequence can be at the top level, or in a step of a
different sequence. From a step, it stops the whole top-level sequence or stage that
holds the transition, then starts the target in the same cycle. From the top level, it
stops nothing. A running target does not restart, except when a transition inside it
targets itself.

Several flows can start the same sequence. Each flow can activate it when its condition
is true and the sequence is not already running.

## Sequence variables

A variable declared in a sequence is not a step. All the steps of the sequence can read
it. To learn when it goes back to its first value, see
[entering a stage](/reference/control/arc/execution-model#entering-a-stage).

```arc channels="start_cmd, remote_start_cmd, press_vlv_cmd, tank_pt" bodies="press"
sequence press {
    target := 300.0
    1 -> press_vlv_cmd
    tank_pt > target => next
    0 -> press_vlv_cmd
}

start_cmd == 1 or remote_start_cmd == 1 => press
```

Set a sequence variable with `=` or with a flow, such as `tank_pt -> peak`. Compound
assignment fails: `compound and indexed assignment to a variable are not yet supported`.
