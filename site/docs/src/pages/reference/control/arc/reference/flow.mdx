A flow statement connects two or more nodes with `->` or `=>`. Values move from left to
right. To learn when a flow runs, see the
[execution model](/reference/control/arc/execution-model#cycles).

```text
flow     = node (operator node)+
operator = "->" | "=>"
```

```arc channels="tank_pt, tank_pt_kpa" bodies="scale"
func scale(k f64) {v f64} f64 {
    return v * k
}

tank_pt -> scale(k=6.895) -> tank_pt_kpa
```

## Operators

| Operator | Passes                      | Example                     |
| -------- | --------------------------- | --------------------------- |
| `->`     | Each new value              | `tank_pt -> scale(k=6.895)` |
| `=>`     | Each new value that is true | `tank_pt > 500 => vent`     |

A `=>` after a non-boolean value gives the warning
[W2000](/reference/control/arc/reference/errors#w2000). For when a transition fires, see
[conditions and transitions](/reference/control/arc/execution-model#conditions-and-transitions).

<Divider.Divider x />

## Sources

The first node of a flow is its source.

| Source                              | Example                                                                       |
| ----------------------------------- | ----------------------------------------------------------------------------- |
| Channel                             | `tank_pt -> tank_pt_copy`                                                     |
| Expression, function calls included | `(ox_pt + fuel_pt) / 2.0 -> avg_pt`, `(median3(pt_1, pt_2, pt_3)) -> tank_pt` |
| Literal                             | `1 -> press_vlv_cmd`                                                          |
| Variable                            | `target -> setpoint_cmd`                                                      |
| Function instance                   | `time.interval(period=1s) -> tick`                                            |

An expression source reads each channel in it. A literal source runs once when the
automation starts, or each time its stage starts. See
[entering a stage](/reference/control/arc/execution-model#entering-a-stage).

## Sinks

The last node of a flow is its sink. A function instance can also be in the middle of a
flow.

| Sink                        | Example               | Effect                                                                |
| --------------------------- | --------------------- | --------------------------------------------------------------------- |
| Channel                     | `-> press_vlv_cmd`    | Writes the value to the channel.                                      |
| Variable                    | `-> peak`             | Sets a variable of the enclosing sequence or stage.                   |
| Function instance           | `-> scale(k=6.895)`   | Passes the value to the first trigger of the function.                |
| Stage or sequence           | `=> vent`             | Starts the stage or the sequence.                                     |
| `next`                      | `=> next`             | Ends the stage, and its sequence moves to the next step.              |
| Routing table               | `-> { ... }`          | Runs an entry for each output. See [routing tables](#routing-tables). |
| Anonymous stage or sequence | `=> sequence { ... }` | Starts an anonymous stage or sequence.                                |

- A top-level variable is not a sink:
  `invalid assignment: cannot reassign top-level variable 'peak'`.
- A function name without parentheses is not a sink:
  `channel expected: f is not a channel`. Write `f()`.
- `=> name` finds a stage or sequence with that name in the enclosing sequences, from
  the innermost out, then at the top level. A stage of a different sequence is not
  found: `undefined symbol: name`.
- Each flow that names a top-level stage or sequence starts its own copy, with its own
  state. The copy runs inside the stage or sequence that holds the flow, and stops when
  the holder stops. A name with no flow in front, such as `vent` on its own line, is the
  same as `true => vent`. See
  [conditions and transitions](/reference/control/arc/execution-model#conditions-and-transitions).
- `-> name` starts a stage or sequence on each new value, also a false one. `=> name`
  starts it only on a true value.
- A stage or sequence with [parameters](#stage-and-sequence-parameters) starts with a
  call, such as `=> fill(tank_pt, press_vlv_cmd)`.
- `next` outside a stage or sequence fails with
  `invalid transition target: 'next' used outside of a stage or sequence`.

## Input values

Parentheses after a function name set its inputs, by name or by position. The opening
parenthesis must touch the name. Do not mix the two forms in one pair of parentheses.
Values by position fill the parameters in order, and skip the trigger that the flow
feeds.

An input value is a literal, a variable, or an expression. A variable or an expression
is read each time the function fires. A `chan T` parameter takes a channel name.

```arc channels="tank_pt, tank_pt_kpa, tick" bodies="scale"
import time

gain := 6.895

func scale(k f64, out chan f64) {v f64} {
    out = v * k
}

tank_pt -> scale(k=gain, out=tank_pt_kpa)
time.interval(1s) -> tick
```

`k` is a value input and `out` is a channel input. The flow feeds each `tank_pt` value
into the trigger `v`.

For required parameters and defaults, see
[inputs](/reference/control/arc/reference/functions#inputs).

## Stage and sequence parameters

A named top-level stage or sequence can take parameters, written as the
[inputs of a function](/reference/control/arc/reference/functions#inputs). A stage or
sequence is called with parentheses only if it has parameters. A stage or sequence with
no parameters has no parentheses in its declaration or its call.

```arc channels="fill_a_cmd, fill_b_cmd, abort_cmd, tank_a_pt, tank_b_pt, press_a_vlv_cmd, press_b_vlv_cmd, vent_vlv_cmd" bodies="fill, open, close, vent"
sequence fill(pressure chan f32, valve chan bool, limit f32 = 300) {
    stage open {
        true -> valve
        pressure > limit => next
    }
    stage close {
        false -> valve
    }
}

stage vent(valve chan bool) {
    true -> valve
}

fill_a_cmd => fill(tank_a_pt, press_a_vlv_cmd)
fill_b_cmd => fill(pressure=tank_b_pt, valve=press_b_vlv_cmd, limit=500)
abort_cmd => vent(vent_vlv_cmd)
```

Each call site is its own instance with its own state, in the same way that each call
site of a function keeps its own
[state](/reference/control/arc/reference/functions#stateful-variables). The two `fill`
calls run at the same time, each with its own channels and limit. The nested stages
`open` and `close` read the parameters of `fill`.

## Routing tables

### Output routing

A routing table after a function with named outputs runs the entry of each output that
fires. Each entry is `output: flow`. Commas between entries are necessary: a newline
alone is a parse error. Use `->` in front of the table. A `=>` fails with
`invalid flow operator: '=>' cannot feed a routing table, use '->'`.

```arc channels="tank_pt, vent_vlv_cmd"
tank_pt > 500.0 -> select() -> {
    true: 1 -> vent_vlv_cmd,
    false: 0 -> vent_vlv_cmd
}
```

### Case bodies

Each entry is a full flow, such as `true: 1 -> vent_vlv_cmd`, or an anonymous stage or
sequence. The output starts the entry, but its value does not pass into the entry. An
entry with only a target fails with
`invalid routing table: routing entry must be a full statement, e.g. 'true: true => next' to transition or 'true: false -> some_chan' to send false`.

An anonymous stage or sequence has no name.

```arc channels="tank_pt, vent_vlv_cmd"
import time

tank_pt > 500.0 -> select() -> {
    true: sequence {
        1 -> vent_vlv_cmd
        time.wait(duration=2s)
        0 -> vent_vlv_cmd
    }
}
```

### Custom routing

Any function with named outputs can drive a routing table. Set one output in the
function body, then route each output by name. See
[outputs](/reference/control/arc/reference/functions#outputs).

```arc channels="tank_pt, alarm_cmd" bodies="band"
func band(limit f64) {v f64} (low u8, high u8) {
    if v > limit {
        high = 1
    } else {
        low = 1
    }
}

tank_pt -> band(limit=500.0) -> {
    low: 0 -> alarm_cmd,
    high: 1 -> alarm_cmd
}
```
