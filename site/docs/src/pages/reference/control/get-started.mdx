Synnax gives you two ways to control hardware. An operator can command actuators from a
schematic with [manual control](/reference/control/manual). A control sequence runs the
commands for you. Use control sequences to automate hardware operations, such as a valve
that opens when a pressure drops below a limit.

When more than one operator or sequence writes to the same channel,
[control authority](/reference/control/authority) decides which one has control.

<Divider.Divider x />

## Control sequence types

**[Arc](/reference/control/arc/introduction)** is the Synnax automation language for
hardware control. Arc is reactive: you declare what occurs when data changes, and you do
not write polling loops. Arc has a visual graph mode and a text mode. Arc automations
run on the [Driver](/reference/hardware), next to the hardware, and are fast enough for
real-time control. You write, start, and stop Arc automations in the Synnax Console.

<Edition.Enterprise>

**[Python](/reference/control/python/get-started)** lets you write any software you
need, with access to all of the Python ecosystem. Python sequences run externally and
communicate with Synnax over the network. The network adds latency, so the timing of
control loops is less predictable. Use Python when you need maximum flexibility. Use Arc
when you need consistent, low-latency control.

With Synnax Enterprise, Arc also runs on a
[standalone Driver](/reference/enterprise/driver/install?platform=ni-linux-rt),
including on NI Linux Real-Time.

</Edition.Enterprise>

## How control sequences work

Control sequences read data from a set of input [channels](/reference/channels), do a
computation, and write data to a set of output channels.

Arc uses a reactive model. When a channel updates, Arc runs the computations that depend
on it:

```arc channels="press_vlv_cmd, pt_471"
// Open the valve when pressure is below threshold, close it otherwise
func bang_bang{threshold f64} (pressure f64) bool {
    return pressure < threshold
}

pt_471 -> bang_bang{threshold=100.0} -> press_vlv_cmd
```

This sequence has no hardware configuration. Acquisition rates, scaling, and other
hardware details stay in [tasks](/reference/hardware/tasks), separate from the sequence.
Thus you can move and change hardware without a change to the control sequence.
