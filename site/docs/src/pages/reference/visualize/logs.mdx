A log shows each new value of its channels as one line of text. Use a log to follow
operator notes, the states of an automation, and slow sensors. A log can show channels
of any data type, including text and JSON.

When a log opens, it shows the last 10,000 stored values of each channel, then each new
value. A virtual channel stores no values, so its log shows only values that arrive
while the log is open.

<Divider.Divider x />

## Create a log

1. Click <Icon.Add /> in the tab bar, or press **Ctrl+T** (**Cmd+T** on macOS).
2. Select **Log**.
3. Click **Configure channels**, then click **Add channel** and select a channel.

You can also run the "Create log" command from the
[command palette](/reference/get-started/ui-overview#search-and-command-palette). In the
channels toolbar, double-click a virtual channel to open it in a log.

## Add channels

1. Press **V** to open the component toolbar, then select the **Channels** tab.
2. Click **Add channel** and select a channel.
3. Optional: set an **Alias** to show in place of the channel name, and a color.

A number channel also has **Notation** and **Precision** settings. A `timestamp` channel
has a timestamp format and a **Time zone**. To remove a channel and its lines, move the
pointer over the icon before the channel name, then click <Icon.Close />.

## Pause and copy lines

Click <Icon.Pause /> (**Pause scrolling**) or press **H** to stop the log from
scrolling. New lines still arrive. Scroll up to pause too. To resume, click <Icon.Play
/> or scroll back to the newest line.

Scroll up to see older lines. When you get near the oldest line, the log reads older
stored values.

To copy lines, drag across them, or press **Ctrl+A** (**Cmd+A** on macOS) to select all.
Then press **Ctrl+C**, or right-click and select **Copy**.

## Set what each line shows

On the **Properties** tab of the component toolbar:

| Field               | Default | Description                                                  |
| ------------------- | ------- | ------------------------------------------------------------ |
| Show timestamps     | On      | Shows the time of day of the sample.                         |
| Timestamp precision | 0       | The number of decimal places of the seconds, from 0 to 3.    |
| Time zone           | Local   | The time zone of the line times, day rows, and copied dates. |
| Show channel names  | On      | Shows the channel name, or its alias, before the value.      |

The timestamp is the time of the sample from the channel's index. Lines show in the
order of these times, across all channels. A virtual channel has no index, so its lines
show the time that the Console received the value.

A row with the date, such as `Wed, Nov 4, 2026`, shows above the first line of each day,
and the top of the log always shows the day of the lines below it. Copied lines start
with the date as `YYYY-MM-DD`.

## Logs in code

A script can make logs for a test and set up their channels before an operator opens
them. The Synnax Python client creates, retrieves, renames, and deletes logs. Each log
belongs to a [project](/reference/visualize/projects) or to a range:

```python
project = client.projects.create(name="Hotfire")
log = client.logs.create(name="Operator notes", project=project.key)

log = client.logs.retrieve(key=log.key)
logs = client.logs.retrieve(projects=project.key)

client.logs.rename(log.key, "Hotfire notes")
```

To edit the channels of a log, pass the key of the log and the key of the channel:

```python
notes = client.channels.retrieve("operator_notes")
pressure = client.channels.retrieve("tank_pressure")
pressure_2 = client.channels.retrieve("tank_pressure_2")
time = client.channels.retrieve("event_time")

client.logs.add_channel(log.key, notes.key)
client.logs.add_channel(log.key, pressure.key)
client.logs.set_channel_alias(log.key, pressure.key, "Tank pressure")
client.logs.set_channel_color(log.key, pressure.key, "#3774D0")
client.logs.set_channel_notation(log.key, pressure.key, "scientific")
client.logs.set_channel_precision(log.key, pressure.key, 2)
client.logs.swap_channel(log.key, pressure.key, pressure_2.key)
client.logs.remove_channel(log.key, notes.key)

client.logs.add_channel(log.key, time.key)
client.logs.set_channel_timestamp_format(log.key, time.key, "ISO")
client.logs.set_channel_timestamp_time_zone(log.key, time.key, "UTC")
```

A precision of `None` shows each value as it arrives. An empty alias shows the channel
name. `swap_channel` keeps the position and settings of the channel that it replaces. An
add does nothing when the log already shows the channel. The other channel edits do
nothing when the log does not show the channel.

To set [what each line shows](#set-what-each-line-shows), and to delete the log:

```python
client.logs.set_timestamps_hidden(log.key, False)
client.logs.set_timestamp_precision(log.key, 3)
client.logs.set_time_zone(log.key, "UTC")
client.logs.set_channel_names_hidden(log.key, True)

client.logs.delete(log.key)
```

## Limits

- A log holds up to 100,000 lines at a time, and it reads others as you scroll, so you
  can reach every stored value. The scrollbar shows your place in time across all stored
  values. A log of only virtual channels shows your place in the lines held.
- A virtual channel stores no values, so its removed lines do not come back.
- Select all covers only the lines held, not every stored value.
- On an HTTP address, the browser Console copies plain text, and the browser can refuse
  a very large copy. The Console then shows an error.
- A value with more than one line of text shows as several lines.
- A value wider than the log wraps. Copied lines stay in one piece.

## Troubleshooting

### The log says "No data received yet"

<Problem.Body>
<Problem.Cause>

The channels have no stored values, and nothing has written to them since the log
opened.

</Problem.Cause>
<Problem.Fix>

Check that a task, a script, or an Arc automation writes to the channels.

</Problem.Fix>
</Problem.Body>
