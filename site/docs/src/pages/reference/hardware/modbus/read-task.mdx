A Modbus read task reads coils and registers from one Modbus server into channels. For
example, it can record a tank level from holding registers 0 and 1 of a PLC at 10 Hz.

Before you start, you need a
[connected server](/reference/hardware/modbus/connect-server).

<Divider.Divider x />

## Registers and coils

A read task reads four types of data, each with its own address range:

| Console label        | Modbus name      | Function code | Value                         |
| -------------------- | ---------------- | ------------- | ----------------------------- |
| **Coil**             | Coil             | 01            | 0 or 1                        |
| **Discrete**         | Discrete input   | 02            | 0 or 1                        |
| **Holding register** | Holding register | 03            | A number, in 1 to 4 registers |
| **Register**         | Input register   | 04            | A number, in 1 to 4 registers |

A register holds 16 bits. An 8-bit or 16-bit value uses one register, and an 8-bit value
is the low byte. A 32-bit value uses two registers, and a 64-bit value uses four. The
**Data type** of the channel sets the size.

For each type, the Driver reads all addresses from the lowest to the highest in one
request. One request can hold at most 125 registers or 2000 coils or discrete inputs.

The Driver timestamps each read with the computer clock. See
[timing](/reference/hardware/tasks#timing).

### Byte and word order

By default, the Driver reads the low word of a 32-bit or 64-bit value first. Many
devices send the high word first. If the values look wrong, set `words_swapped` on the
channel. To swap the two bytes in each register, set `bytes_swapped`.

## Create a Modbus read task

<Client.Tabs exclude={["cpp"]}>
  <Fragment slot="console">

1. In the devices toolbar, right-click the server and select **Create read task**.
2. Set **Sample rate** and **Stream rate**.
3. Click **Add channel**. Select the type, then enter the address. For a register,
   select the **Data type**.
4. Click <Icon.Play /> (**Start**).

The Console creates the channels. For the server `Pump skid PLC`, a `float32` holding
register at address 0 gives `Pump_skid_PLC_holding_register_input_0_f32`, and a coil at
address 3 gives `Pump_skid_PLC_coil_input_3`. The index channel is `Pump_skid_PLC_time`.

  </Fragment>
  <Fragment slot="python">

Python does not create channels. Create them first.

```python
import synnax as sy
from synnax import modbus

dev = client.devices.retrieve(name="Pump skid PLC")
time = client.channels.create(
    name="plc_time", is_index=True, data_type=sy.DataType.TIMESTAMP
)
level = client.channels.create(
    name="tank_level", index=time.key, data_type=sy.DataType.FLOAT32
)
pump_on = client.channels.create(
    name="pump_on", index=time.key, data_type=sy.DataType.UINT8
)

task = modbus.ReadTask(
    name="Pump skid",
    device=dev.key,
    sample_rate=10,
    stream_rate=5,
    channels=[
        modbus.HoldingRegisterReadChannel(
            address=0, data_type="float32", words_swapped=True, channel=level.key
        ),
        modbus.CoilReadChannel(address=3, channel=pump_on.key),
    ],
)
client.tasks.configure(task)
task.start()
```

TypeScript does not create channels. Create them first.

```typescript
import { modbus } from "@synnaxlabs/client";

const [dev] = await client.devices.retrieve({ names: ["Pump skid PLC"] });
const time = await client.channels.create({
  name: "plc_time",
  isIndex: true,
  dataType: "timestamp",
});
const level = await client.channels.create({
  name: "tank_level",
  index: time.key,
  dataType: "float32",
});

const task = await client.tasks.create({
  name: "Pump skid",
  rack: dev.rack,
  type: "modbus_read",
  config: modbus.readConfigZ.parse({
    device: dev.key,
    sampleRate: 10,
    streamRate: 5,
    channels: [
      {
        type: "holding_register",
        address: 0,
        dataType: "float32",
        wordsSwapped: true,
        channel: level.key,
      },
    ],
  }),
});
await task.start();
```

## Task options

| Console label     | Python field           | Default | Notes                                                     |
| ----------------- | ---------------------- | ------- | --------------------------------------------------------- |
| **Modbus server** | `device`               |         | The key of the server.                                    |
| **Sample rate**   | `sample_rate`          | 10 Hz   | How often the Driver reads the server. Up to 50,000 Hz.   |
| **Stream rate**   | `stream_rate`          | 5 Hz    | See [read tasks](/reference/hardware/tasks#read-tasks).   |
| **Data saving**   | `data_saving_disabled` | On      | See [data saving](/reference/hardware/tasks#data-saving). |
| **Auto start**    | `auto_start`           | Off     | Starts the task each time the Driver starts.              |

## Channel reference

Each channel has an `address`, from 0 to 65535, and a `channel`, the Synnax channel that
records the value.

| ------------- | --------------- | ------- | -------------------------------------------------------------------------------------------------- |

|               | `words_swapped` | `false` | Reads the high word first. See [byte and word order](#byte-and-word-order).                        |

|               | `type`          |         | `"holding_register"` or `"input_register"`.                                                        |

## Troubleshooting

### "Illegal data address"

The server does not have one of the addresses in the task. Check the address map of the
device. Some devices count addresses from 1, so try the address minus 1.

### "unsupported data type: ..."

The Console also lists Boolean, Timestamp, and UUID, but the Driver does not support
them. Select a data type from the [channel reference](#channel-reference).

### "Too many data"

The addresses of one type span more than one request can hold. Move the channels closer
together, or split them into two tasks.

### The values are wrong

Set the [byte and word order](#byte-and-word-order) of the channel. Check that the data
type matches the device.

### The task stopped when the connection dropped

The task stops on any connection error. Start the task again when the server is back.

For other problems, see
[Connect a Modbus server](/reference/hardware/modbus/connect-server#troubleshooting) and
[Troubleshoot hardware](/reference/hardware/troubleshooting).
