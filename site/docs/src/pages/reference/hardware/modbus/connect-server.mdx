The Modbus integration reads and writes the coils and registers of Modbus TCP servers,
such as PLCs and remote I/O modules. Modbus RTU and Modbus ASCII are not supported. In
Synnax, a Modbus server is one IP address and port. The
[read task](/reference/hardware/modbus/read-task) and the
[write task](/reference/hardware/modbus/write-task) add the addresses.

## Prerequisites

<Platforms integration="modbus" />

- A running Driver that can reach the server on the network. Synnax Desktop runs one for
  you.

## Connect a server

<Client.Tabs>
  <Fragment slot="console">

1. In the [devices toolbar](/reference/hardware/devices#devices-toolbar), click
   <Icon.Add /> (**Connect device**), then select **Modbus TCP server**. You can also
   run the "Connect Modbus server" command.
2. Enter a name for the server.
3. In **Host**, enter the IPv4 address of the server, such as `192.168.1.20`.
4. In **Port**, enter the port of the server. The default is `502`.
5. In **Connect from**, select the Driver that connects to the server. If only one
   running Driver has Modbus enabled, the Console selects it for you.
6. If the device sends its bytes or words in a different order, turn on **Swap bytes**
   or **Swap words**. See
   [byte and word order](/reference/hardware/modbus/read-task#byte-and-word-order).
7. Click **Connect**.

The Console connects to the server before it saves it. If the connection fails, the
dialog shows the error and keeps your entries.

<Video id="device-drivers/modbus/connect-server/modbus-connect" />

  </Fragment>
  <Fragment slot="python">

```python
from synnax import modbus

rack = client.racks.retrieve_embedded_rack()
device = client.devices.create(
    modbus.Device(
        name="Pump skid PLC",
        host="192.168.1.20",
        port=502,
        location="192.168.1.20:502",
        rack=rack.key,
        configured=True,
    )
)
```

Python does not test the connection. Pass the key of a rack, or the device has no
Driver. Pass `configured=True`, or the Console asks you to configure the server.

After you connect a server, the Driver connects to it again every few seconds and shows
the result as the server status in the devices toolbar. See
[device statuses](/reference/hardware/devices#statuses).

## Connection options

| Console label | Python field | Default | Notes                                                  |
| ------------- | ------------ | ------- | ------------------------------------------------------ |
| Host          | `host`       |         | An IPv4 address. Hostnames, such as `localhost`, fail. |
| Port          | `port`       | `502`   | The TCP port. Python has no default.                   |
| Connect from  | `rack`       |         | The Driver that connects to the server.                |
| Swap bytes    | `swap_bytes` | Off     | Swaps the two bytes in each register.                  |
| Swap words    | `swap_words` | Off     | Puts the high word first in 32-bit and 64-bit values.  |

**Swap bytes** and **Swap words** set the default for every register channel of the
server. A channel can override them. The Driver always sends unit ID 255. There is no
option to change it.

## Troubleshooting

### Connect fails with a hostname

The Driver accepts only IPv4 addresses. Enter the address of the server. For a server on
the same computer as the Driver, enter `127.0.0.1`.

### Connect fails with "Connection refused" or a timeout

Check the address and the port. Make sure that the server allows Modbus TCP connections
from the computer that runs the Driver.

### The server connects but does not answer requests

The server, or the gateway in front of it, needs a unit ID other than 255. The Driver
cannot send a different unit ID.

For other problems, see
[Troubleshoot hardware](/reference/hardware/troubleshooting#failed-to-reach-device-or-failed-to-reach-server).
