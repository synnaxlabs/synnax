An OPC UA read task reads the values of nodes on a server at a fixed rate and records
them in channels. For example, it can record the tank pressures and pump speeds of a PLC
50 times a second. The Driver times each read in software.

Before you start, you need a
[connected OPC UA server](/reference/hardware/opc-ua/connect-server).

<Divider.Divider x />

## Node IDs

Each channel of the task reads one node. A node ID names the namespace of the node and
its identifier, in one of these forms:

| Form                                       | Example                                  |
| ------------------------------------------ | ---------------------------------------- |
| `nsu=<namespace URI>;<type>=<identifier>`  | `nsu=urn:example:plant;s=Tank1.Pressure` |
| `ns=<namespace index>;<type>=<identifier>` | `ns=2;s=Tank1.Pressure`                  |
| `<type>=<identifier>`                      | `i=2258`, a node in namespace 0          |

| Type | Identifier       | Example                                       |
| ---- | ---------------- | --------------------------------------------- |
| `i`  | A number         | `ns=2;i=1001`                                 |
| `s`  | A string         | `ns=2;s=Tank1.Pressure`                       |
| `g`  | A GUID           | `ns=2;g=09087e75-8e5e-499b-954f-f2a9603db28a` |
| `b`  | Bytes, in base64 | `ns=2;b=M/RbKBsRVkePCePcx24oRA==`             |

The browser in the Console fills node IDs in the `nsu=` form. A server can give a
namespace a different index when it restarts, but the URI stays the same. In a URI,
write `;` as `%3B` and `%` as `%25`. The Driver ignores the case of the prefix and the
type, so it also accepts `NS=2;S=Tank1.Pressure`.

## Create an OPC UA read task

<Client.Tabs>
  <Fragment slot="console">

1. In the devices toolbar, right-click the server and select **Create read task**.
2. Set **Sample rate** and **Stream rate**.
3. In the **Browser**, expand the folders of the server.
4. Drag the variables to read into **Channels**. You can select more than one.
5. Click <Icon.Play /> (**Start**).

The Console creates a channel for each node, named from the browse name of the node. To
choose a name, edit the name of the channel before you start. The Console also creates
an index channel named `<server>_time_for_<task>`, unless one of the channels already
has an index or you [use server timestamps](#use-server-timestamps).

<Video id="hardware/opc-ua/read-task" />

  </Fragment>
  <Fragment slot="python">

Python does not create channels. Create an index channel and a channel for each node
first.

```python
import synnax as sy
from synnax import opcua

server = client.devices.retrieve(name="Line 1 PLC")
time = client.channels.create(
    name="plc_time", is_index=True, data_type=sy.DataType.TIMESTAMP
)
pressure = client.channels.create(
    name="tank_1_pressure", index=time.key, data_type=sy.DataType.FLOAT64
)

task = opcua.ReadTask(
    name="Line 1 PLC read",
    device=server.key,
    sample_rate=50,
    stream_rate=25,
    channels=[
        opcua.ReadChannel(channel=pressure.key, node_id="NS=2;S=Tank1.Pressure")
    ],
)
client.tasks.configure(task)
task.start()
```

Always pass `sample_rate` and `stream_rate`. In Python they default to 10 Hz and 5 Hz,
not to the Console defaults.

  </Fragment>

TypeScript does not create channels. Create an index channel and a channel for each node
first.

```typescript
import { opcua } from "@synnaxlabs/client";

const [server] = await client.devices.retrieve({ names: ["Line 1 PLC"] });
const time = await client.channels.create({
  name: "plc_time",
  isIndex: true,
  dataType: "timestamp",
});
const pressure = await client.channels.create({
  name: "tank_1_pressure",
  index: time.key,
  dataType: "float64",
});

const task = await client.tasks.create({
  name: "Line 1 PLC read",
  rack: server.rack,
  type: "opc_read",
  config: opcua.readConfigZ.parse({
    device: server.key,
    sampleRate: 50,
    streamRate: 25,
    channels: [{ channel: pressure.key, nodeId: "NS=2;S=Tank1.Pressure" }],
  }),
});
await task.start();
```

## Read arrays

Some servers buffer fast samples in an array node. To read the arrays:

1. Turn on **Array sampling**.
2. Set **Array size** to the number of values in each array.

The Driver then reads each node `Sample rate / Array size` times a second, and spreads
the timestamps of the values evenly over the read period. **Sample rate** must be equal
to or more than **Array size**. Each array must have exactly **Array size** values, or
the Driver drops the frame and shows a warning. **Stream rate** does not apply in array
mode.

<Divider.Divider x />

## Read structure fields

Some nodes hold a structure, such as a motor with a speed, a state, and a position. A
channel can read one field of the structure:

1. In the **Browser**, expand the structure node. The browser shows the fields of its
   type, and the fields of each nested structure.
2. Drag the fields into **Channels**.

The Console names each channel `<node>.<field>`, such as `Motor.Speed`. The channels of
one node share one read, so their values come from the same moment. The task reads the
definition of the type from the server each time it connects. If the server does not
give the definition, the task shows "Received bad values" for the fields of that type.

In Python and TypeScript, set `field` to the path of the field from the node, with `.`
between names, such as `Position.Y`. Put `&` before a `.` or a `&` that is part of a
name: `a&.b` is the field `a.b`.

Array sampling cannot read structure fields. A write task cannot write to a field, so
the Console does not add fields to a write task.

<Divider.Divider x />

## Use server timestamps

By default, the Driver gives the values of each read the time halfway through the read
request. To use the time from the server instead:

1. Add a node with a DateTime value, such as the source time of the PLC, to the task.
2. Turn on **Use as index** for that channel.

The Driver then uses the value of that node as the timestamp of every channel in the
task. Only one channel can be the index.

<Divider.Divider x />

## Bad values

The server sends a status with each value. The task records a value with a Good or an
Uncertain status. For an Uncertain value, it also shows the warning "Received uncertain
values" with the name of the channel.

The task does not record a Bad value. A node that does not exist and a value that the
Driver cannot convert are Bad values too. The task shows the warning "Received bad
values" with the name of the channel and the status, such as `BadSensorFailure`, and
keeps running. When the value becomes good again, the task records it.

By default, a Bad value skips the sample for every channel on the same index. Turn on
**NaN fill** to write `NaN` for a float channel instead, so that the other channels keep
their samples. A line plot shows `NaN` as a gap. A Bad value of a channel that is not a
float still skips its index.

<Divider.Divider x />

## Outages

A read task keeps running when the server or the network goes down. It shows "Failed to
read data" and tries again at most 5 seconds apart. A task can also start while the
server is off. Before each new connection, the task gets the connection settings of the
server again, so a corrected endpoint or password takes effect without a restart.

## Task options

| Console label  | Python field           | Default                 | Notes                                                                           |
| -------------- | ---------------------- | ----------------------- | ------------------------------------------------------------------------------- |
| OPC UA server  | `device`               |                         | The key of the server.                                                          |
| Sample rate    | `sample_rate`          | 50 Hz (10 Hz in Python) | Reads per second. At most 10,000.                                               |
| Stream rate    | `stream_rate`          | 25 Hz (5 Hz in Python)  | Frames per second sent to the Core. At most the sample rate. Not in array mode. |
| Array sampling | `array_mode`           | Off                     | See [read arrays](#read-arrays).                                                |
| Array size     | `array_size`           | 1                       | Values in each array node.                                                      |
| NaN fill       | `nan_fill_enabled`     | Off                     | See [bad values](#bad-values).                                                  |
| Data saving    | `data_saving_disabled` | On                      | See [data saving](/reference/hardware/tasks#data-saving).                       |
| Auto start     | `auto_start`           | Off                     | Starts the task each time the Driver starts.                                    |

TypeScript uses the same fields in camel case, such as `sampleRate`. See
[timing](/reference/hardware/tasks#timing). When a task has more nodes than the server
accepts in one request, the Driver splits each read into smaller requests.

## Channel reference

The table shows the Console label of each setting, with its Python field under it.

| Setting                                | Default   | Notes                                                                            |
| -------------------------------------- | --------- | -------------------------------------------------------------------------------- |
| Channel name <small>`name`</small>     | Empty     | The name of the channel that the Console creates.                                |
| <small>`channel`</small>               |           | The key of the channel that records the values.                                  |
| Node ID <small>`node_id`</small>       |           | See [node IDs](#node-ids).                                                       |
| <small>`field`</small>                 | Empty     | The field of a structure node. See [structure fields](#read-structure-fields).   |
| Node name <small>`node_name`</small>   | Empty     | The browse name. For display only.                                               |
| <small>`data_type`</small>             | `float32` | The data type of the channel that the Console creates.                           |
| Use as index <small>`is_index`</small> | Off       | Shows only for a DateTime node. See [server timestamps](#use-server-timestamps). |
| Enabled <small>`disabled`</small>      | Off       | A disabled channel is not read.                                                  |

### Data types

The Console creates each channel with the data type of its node:

| OPC UA type | Synnax data type |
| ----------- | ---------------- |
| Boolean     | `boolean`        |
| SByte       | `int8`           |
| Byte        | `uint8`          |
| Int16       | `int16`          |
| UInt16      | `uint16`         |
| Int32       | `int32`          |
| UInt32      | `uint32`         |
| Int64       | `int64`          |
| UInt64      | `uint64`         |
| Float       | `float32`        |
| Double      | `float64`        |
| String      | `string`         |
| DateTime    | `timestamp`      |
| Guid        | `uuid`           |
| ByteString  | `bytes`          |
| Enumeration | `int32`          |

A channel can have a different data type than its node. The Driver converts each value
to the data type of the channel, and a value that does not fit is a
[bad value](#bad-values).

## Troubleshooting

<Problem.List>

<Problem.Item message={"Invalid NodeId format"}>
<Problem.Cause>

The node ID is not in a form that the Driver accepts.

</Problem.Cause>
<Problem.Fix>

Write the node ID in one of the forms in [node IDs](#node-ids).

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Received bad values"}>
<Problem.Cause>

The server sent a Bad status for a node, the server has no namespace with the URI of the
node, or the Driver could not convert its value. The description names each channel and
the reason. For example, `BadNodeIdUnknown` means that the server has no node with that
ID. See [bad values](#bad-values).

</Problem.Cause>
<Problem.Fix>

For `BadNodeIdUnknown` or a missing namespace, drag the node from the **Browser** again.
For a conversion error, check the data type of the node.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Received uncertain values"}>
<Problem.Cause>

The server is not sure that a value is correct, such as a last usable value of a sensor.
The task records the value.

</Problem.Cause>
<Problem.Fix>

Check the device that the server reads the node from.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Failed to read data"}>
<Problem.Cause>

The task lost the connection to the server. It tries again until the server answers. See
[outages](#outages).

</Problem.Cause>
<Problem.Fix>

Check the
[server connection](/reference/hardware/opc-ua/connect-server#troubleshooting).

</Problem.Fix>
</Problem.Item>

<Problem.Item message={["OPC UA array for ... is too small", "... is too large"]}>
<Problem.Cause>

An array node has a different number of values than **Array size**.

</Problem.Cause>
<Problem.Fix>

Set **Array size** to the length of the array.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Channel ... already exists as ..."}>
<Problem.Cause>

Another task already reads the node into that channel.

</Problem.Cause>
<Problem.Fix>

Move the channels to one task.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Failed to browse OPC UA nodes"}>
<Problem.Cause>

The Driver could not browse the server.

</Problem.Cause>
<Problem.Fix>

Check the
[server connection](/reference/hardware/opc-ua/connect-server#troubleshooting).

</Problem.Fix>
</Problem.Item>

</Problem.List>

For other problems, see [Troubleshoot hardware](/reference/hardware/troubleshooting).
