An OPC UA server makes the values of a PLC or a SCADA system available as nodes. In
Synnax, an OPC UA server is one endpoint with its login and security settings. The
[read task](/reference/hardware/opc-ua/read-task) and the
[write task](/reference/hardware/opc-ua/write-task) add the nodes.

<Divider.Divider x />

## Prerequisites

<Platforms integration="opcua" />

- A running Driver that can reach the server on the network. Synnax Desktop runs one for
  you.

## Connect a server

<Client.Tabs>
  <Fragment slot="console">

1. In the devices toolbar, click <Icon.Add /> (**Connect device**), then select **OPC UA
   server**. You can also run the "Connect OPC UA server" command.
2. Enter a name for the server.
3. In **Endpoint**, enter the address of the server, for example
   `opc.tcp://192.168.1.50:4840`.
4. In **Connect from**, select the Driver that connects to the server. If only one
   running Driver supports OPC UA, the Console selects it for you.
5. If the server needs a login, enter the **Username** and the **Password**.
6. Set the [security](#security).
7. Click **Connect**.

The Console asks the Driver to connect to the server before it saves the server. If the
test fails or takes more than 10 seconds, the dialog shows the error and keeps your
entries.

```python
from synnax import opcua

rack = client.racks.retrieve_embedded_rack()
device = client.devices.create(
    opcua.Device(
        name="Line 1 PLC",
        endpoint="opc.tcp://192.168.1.50:4840",
        location="opc.tcp://192.168.1.50:4840",
        rack=rack.key,
    )
)
```

Python does not test the connection. Pass the key of a rack, or the device has no
Driver.

## Security

In the **Security** section, the **Mode** and the **Policy** protect the connection
between the Driver and the server. Set them to values that the server accepts.

- **Mode** -> **None**, **Sign**, or **Sign and encrypt**.
- **Policy** -> the algorithms. The field shows when the mode is not **None**. When you
  change the mode from **None**, the Console selects **Basic 256-bit with SHA-256**.
  Select a deprecated policy only when the server supports no other policy.
- **Client certificate** and **Client private key** -> the certificate that the Driver
  sends to the server, and its key. The fields show when the mode is not **None**.

In Python and TypeScript, set a policy other than `"None"` when the mode is not
`"None"`. With the policy at `"None"`, the Driver does not load the certificates, even
when the mode is `"Sign"`.

The certificate and key are file paths on the computer that runs the Driver:

- In Synnax Desktop, the Console and the Driver run on the same computer, so the file
  picker gives a correct path.
- When the Driver runs on a different computer, the picker gives a path on your
  computer. Set the paths in Python or TypeScript instead.
- The Console in a web browser cannot pick files. Set the paths in Python or TypeScript.

The private key must not have a password. The server reads the application URI of the
Driver from the URI in the client certificate. Without a client certificate, the URI is
`urn:synnax.opcua.client`.

The Driver accepts every server certificate. The **Server certificate** field has no
effect.

The Driver logs in to the server as an anonymous user, or with the **Username** and
**Password** when you enter one of them. It cannot log in with a user certificate.

## Connection options

| Console label      | Python field         | Default                    | Notes                                                                                   |
| ------------------ | -------------------- | -------------------------- | --------------------------------------------------------------------------------------- |
| Connect from       | `rack`               |                            | The key of the rack that runs the Driver.                                               |
| Endpoint           | `endpoint`           | `opc.tcp://localhost:4840` | Required in Python.                                                                     |
| Username           | `username`           | Empty                      | Empty for an anonymous login.                                                           |
| Password           | `password`           | Empty                      |                                                                                         |
| Mode               | `security_mode`      | None                       | `"None"`, `"Sign"`, or `"SignAndEncrypt"`.                                              |
| Policy             | `security_policy`    | None                       | `"None"` goes only with the mode `"None"`. See [security policies](#security-policies). |
| Client certificate | `client_cert`        | Empty                      | A path on the Driver computer.                                                          |
| Client private key | `client_private_key` | Empty                      | A path on the Driver computer. No password.                                             |
| Server certificate | `server_cert`        | Empty                      | Has no effect.                                                                          |

In TypeScript, the fields are in `properties.connection` in camel case, such as
`securityMode`, `clientCertificate`, and `serverCertificate`.

### Security policies

| Console label                  | Value                     |
| ------------------------------ | ------------------------- |
| Basic 256-bit with SHA-256     | `"Basic256Sha256"`        |
| AES 128-bit with SHA-256       | `"Aes128_Sha256_RsaOaep"` |
| AES 256-bit with SHA-256       | `"Aes256_Sha256_RsaPss"`  |
| Basic 256-bit (deprecated)     | `"Basic256"`              |
| Basic 128-bit RSA (deprecated) | `"Basic128Rsa15"`         |

## Troubleshooting

<Problem.List>

<Problem.Item message={"Failed to reach server"}>
<Problem.Cause>

The Driver checks each server every 5 seconds. The status shows "Failed to reach server"
when the Driver cannot connect. The description shows the reason.

</Problem.Cause>
<Problem.Fix>

1. Check the **Endpoint**, including the port.
2. Make sure that the computer that runs the Driver can reach the server.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"The Driver paused new connections to the server after too many failed attempts in a row."}>
<Problem.Cause>

The Driver failed to connect three times in a row, so it waits 5 seconds before it tries
again.

</Problem.Cause>
<Problem.Fix>

1. Fix the cause of the first error.
2. Try again.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Failed to configure encryption"}>
<Problem.Cause>

The Driver could not use the certificate, the key, or the policy.

</Problem.Cause>
<Problem.Fix>

1. Make sure that the paths are correct on the computer that runs the Driver.
2. Remove the password from the private key.
3. Select a policy that the server supports.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"The certificate is not trusted."}>
<Problem.Cause>

The server rejected the client certificate.

</Problem.Cause>
<Problem.Fix>

Add the client certificate to the trust list of the server.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"The URI specified in the ApplicationDescription does not match the URI in the certificate."}>
<Problem.Cause>

The URI in the client certificate is different from the URI that the server expects.

</Problem.Cause>
<Problem.Fix>

Create a certificate whose URI matches the server configuration.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"User does not have permission to perform the requested operation."}>
<Problem.Cause>

The server rejected the **Username** or the **Password**. Some servers show "The user
identity token is valid but the server has rejected it." for the same cause.

</Problem.Cause>
<Problem.Fix>

Enter a **Username** and a **Password** that the server accepts.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"The user identity token is not valid."}>
<Problem.Cause>

The server does not accept an anonymous login.

</Problem.Cause>
<Problem.Fix>

Enter a **Username** and a **Password**.

</Problem.Fix>
</Problem.Item>

</Problem.List>

For other problems, see [Troubleshoot hardware](/reference/hardware/troubleshooting).
