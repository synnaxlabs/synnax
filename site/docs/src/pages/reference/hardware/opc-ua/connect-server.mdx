An OPC UA server makes the values of a PLC or a SCADA system available as nodes. In
Synnax, an OPC UA server is one endpoint with its login and security settings. The
[read task](/reference/hardware/opc-ua/read-task) and the
[write task](/reference/hardware/opc-ua/write-task) add the nodes.

<Divider.Divider x />

## Prerequisites

<Platforms integration="opcua" />

- A running Driver that can reach the server on the network. Synnax Desktop runs one for
  you.

## Connect a server

<Client.Tabs>
  <Fragment slot="console">

1. In the [devices toolbar](/reference/hardware/devices#devices-toolbar), click
   <Icon.Add /> (**Connect device**), then select **OPC UA server**. You can also run
   the "Connect OPC UA server" command.
2. Enter a name for the server.
3. In **Endpoint**, enter the address of the server, for example
   `opc.tcp://192.168.1.50:4840`.
4. In **Connect from**, select the Driver that connects to the server. If only one
   running Driver has OPC UA enabled, the Console selects it for you.
5. If the server needs a login, enter the **Username** and the **Password**.
6. Set the [security](#security).
7. Click **Connect**.

The Console asks the Driver to connect to the server before it saves the server. If the
test fails or takes more than 10 seconds, the dialog shows the error and keeps your
entries.

<Video id="device-drivers/opc-ua/connect-server/connect-server" />

  </Fragment>
  <Fragment slot="python">

```python
from synnax import opcua

rack = client.racks.retrieve_embedded_rack()
device = client.devices.create(
    opcua.Device(
        name="Line 1 PLC",
        endpoint="opc.tcp://192.168.1.50:4840",
        location="opc.tcp://192.168.1.50:4840",
        rack=rack.key,
    )
)
```

Python does not test the connection. Pass the key of a rack, or the device has no
Driver.

## Security

In the **Security** section, the **Mode** and the **Policy** protect the connection
between the Driver and the server. Set them to values that the server accepts.

- **Mode** -> **None**, **Sign**, or **Sign and encrypt**.
- **Policy** -> the algorithms. When you change the mode from **None**, the Console
  selects **Basic 256-bit with SHA-256**. Select a deprecated policy only when the
  server supports nothing newer.

The other security fields show when the mode is not **None**. In Python and TypeScript,
set a policy other than `"None"` when the mode is not `"None"`. With the policy at
`"None"`, the Driver does not load the certificates, even when the mode is `"Sign"`.

### Client certificate

The Driver sends a certificate to the server. Select one of these:

- **Driver certificate** -> the default. Each Driver makes its own certificate, and all
  the servers that the Driver connects to get the same one. The dialog shows its
  thumbprint and its expiry date.
- **Files on the Driver computer** -> the paths of a certificate and a private key on
  the computer that runs the Driver. Use this when your site issues its own
  certificates. The key must not have a password, and the certificate must hold the
  application URI of the Driver.

Most servers reject a certificate that they do not know, and keep it in a list of
rejected certificates. To make the server trust the Driver certificate:

1. Click **Connect**. The test fails with "Server rejected the Driver certificate".
2. On the server, find the Driver certificate in the rejected list. Make sure that its
   thumbprint is the same as the one in the dialog, then trust it.
3. Click **Connect** again.

If the server has no rejected list, click **Download** to save the certificate as a DER
file, then add the file to the trust list of the server. For a server that needs PEM,
convert the file that you downloaded, here `driver.der`:

```bash
openssl x509 -inform der -in driver.der -out driver.pem
```

The Driver certificate is valid for 3 years. 60 days before it expires, the Driver makes
the next certificate and keeps using the current one. Once a day, the Driver connects to
each secured server with the next certificate, so a server that does not trust it yet
adds it to its rejected list. Trust it there, or download it from the dialog, where it
shows as **Next certificate**. The Driver uses the next certificate when all the servers
accept it, or when the current one expires.

**Regenerate** replaces the certificate of the Driver with a new one. Use it only when
the private key is no longer safe. All the servers must then trust the new certificate.

### Server certificate

Each server has a certificate, and a device trusts one server certificate. The Driver
connects only to a server that sends the trusted certificate.

- In the dialog, the first **Connect** fails with "Server certificate not trusted". The
  dialog shows the certificate that the server sent, with its subject, thumbprint, and
  expiry date. Make sure that the thumbprint is the same as the one the server shows,
  then click **Trust**. The dialog saves the certificate and connects again.
- A device made in Python or TypeScript without a server certificate trusts the
  certificate that the server sends on the first connection. The Driver saves that
  certificate to the device.
- When the server gets a new certificate, the device shows "Server certificate not
  trusted". Open the device, compare the new thumbprint, and click **Trust**.

### Validate server certificate

**Validate server certificate** is on by default. Turn it off only to troubleshoot a
connection. When it is off, the Driver accepts any server certificate, and the device
shows the warning "Connected without certificate validation". Turn it on again when you
finish.

### Login

The Driver logs in to the server as an anonymous user, or with the **Username** and
**Password** when you enter one of them. It cannot log in with a user certificate.

## Connection options

| Console label               | Python field                      | Default                    | Notes                                                                                   |
| --------------------------- | --------------------------------- | -------------------------- | --------------------------------------------------------------------------------------- |
| Connect from                | `rack`                            |                            | The key of the rack that runs the Driver.                                               |
| Endpoint                    | `endpoint`                        | `opc.tcp://localhost:4840` | Required in Python.                                                                     |
| Username                    | `username`                        | Empty                      | Empty for an anonymous login.                                                           |
| Password                    | `password`                        | Empty                      |                                                                                         |
| Mode                        | `security_mode`                   | None                       | `"None"`, `"Sign"`, or `"SignAndEncrypt"`.                                              |
| Policy                      | `security_policy`                 | None                       | `"None"` goes only with the mode `"None"`. See [security policies](#security-policies). |
| Certificate file            | `client_cert`                     | Empty                      | A path on the Driver computer. Empty, with an empty key, uses the Driver certificate.   |
| Private key file            | `client_private_key`              | Empty                      | A path on the Driver computer. No password.                                             |
| Server certificate          | `server_cert`                     | Empty                      | The trusted certificate as PEM. Empty trusts the certificate of the first connection.   |
| Validate server certificate | `certificate_validation_disabled` | `False`                    | The switch shows the opposite value.                                                    |

In TypeScript, the fields are in `properties.connection` in camel case, such as
`securityMode`, `clientCertificate`, `serverCertificate`, and
`certificateValidationDisabled`.

### Security policies

| Console label                  | Value                     |
| ------------------------------ | ------------------------- |
| Basic 256-bit with SHA-256     | `"Basic256Sha256"`        |
| AES 128-bit with SHA-256       | `"Aes128_Sha256_RsaOaep"` |
| AES 256-bit with SHA-256       | `"Aes256_Sha256_RsaPss"`  |
| Basic 256-bit (deprecated)     | `"Basic256"`              |
| Basic 128-bit RSA (deprecated) | `"Basic128Rsa15"`         |

## Troubleshooting

<Problem.List>

<Problem.Item message={"Failed to reach server"}>
<Problem.Cause>

The Driver checks each server every 5 seconds, unless a task on the server got a reply
since the last check. The status shows "Failed to reach server" when the Driver cannot
connect. The description shows the reason.

</Problem.Cause>
<Problem.Fix>

1. Check the **Endpoint**, including the port.
2. Make sure that the computer that runs the Driver can reach the server.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"The Driver paused new connections to the server after too many failed attempts in a row."}>
<Problem.Cause>

The Driver failed to connect three times in a row, so it waits 5 seconds before it tries
again. Each further failure doubles the wait, up to 30 seconds. A successful connection
resets it.

</Problem.Cause>
<Problem.Fix>

1. Fix the cause of the first error.
2. Try again.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Failed to configure encryption"}>
<Problem.Cause>

The Driver could not use the certificate, the key, or the policy.

</Problem.Cause>
<Problem.Fix>

Select a policy that the server supports.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Server certificate not trusted"}>
<Problem.Cause>

The server sent a certificate other than the one that the device trusts, or the device
trusts no certificate yet.

</Problem.Cause>
<Problem.Fix>

1. Open the device and click **Connect**.
2. Make sure that the thumbprint in the dialog is the same as the one the server shows.
3. Click **Trust**.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Server rejected the Driver certificate"}>
<Problem.Cause>

The server does not trust the client certificate.

</Problem.Cause>
<Problem.Fix>

Trust the certificate on the server. See [client certificate](#client-certificate).

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Server certificate expired"}>
<Problem.Cause>

The certificate of the server is not valid at the current time.

</Problem.Cause>
<Problem.Fix>

1. Renew the certificate of the server.
2. Open the device, click **Connect**, and trust the new certificate.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Failed to read client certificate"}>
<Problem.Cause>

The Driver could not use the files in **Certificate file** and **Private key file**.

</Problem.Cause>
<Problem.Fix>

1. Make sure that the paths are correct on the computer that runs the Driver.
2. Make sure that the key belongs to the certificate.
3. Remove the password from the private key.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Failed to load the Driver certificate"}>
<Problem.Cause>

The Driver could not read, make, or save its certificate.

</Problem.Cause>
<Problem.Fix>

1. Make sure that the Driver can write to its data directory.
2. Restart the Driver.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Connected without certificate validation"}>
<Problem.Cause>

**Validate server certificate** is off, so the Driver accepts any server certificate.

</Problem.Cause>
<Problem.Fix>

Turn on **Validate server certificate** when you finish troubleshooting.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Server does not trust the next certificate"}>
<Problem.Cause>

The Driver certificate expires soon, and the server does not trust the next one yet.

</Problem.Cause>
<Problem.Fix>

Trust the next certificate on the server before the date in the description. See
[client certificate](#client-certificate).

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"The URI specified in the ApplicationDescription does not match the URI in the certificate."}>
<Problem.Cause>

The URI in the certificate file is different from the URI that the server expects.

</Problem.Cause>
<Problem.Fix>

Create a certificate whose URI matches the server configuration.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"User does not have permission to perform the requested operation."}>
<Problem.Cause>

The server rejected the **Username** or the **Password**. Some servers show "The user
identity token is valid but the server has rejected it." for the same cause.

</Problem.Cause>
<Problem.Fix>

Enter a **Username** and a **Password** that the server accepts.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"The user identity token is not valid."}>
<Problem.Cause>

The server does not accept an anonymous login.

</Problem.Cause>
<Problem.Fix>

Enter a **Username** and a **Password**.

</Problem.Fix>
</Problem.Item>

</Problem.List>

For other problems, see [Troubleshoot hardware](/reference/hardware/troubleshooting).
