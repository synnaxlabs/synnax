[EtherCAT](https://www.ethercat.org/) is a fieldbus that runs on a standard Ethernet
port. The Driver is the EtherCAT master: it finds each module on the network and reads
and writes the process data of the module, which EtherCAT calls PDOs. Before a task can
use a module, you configure it.

<Divider.Divider x />

## Prerequisites

<Platforms integration="ethercat" />

- An Ethernet port on the computer that runs the Driver, cabled to the first module. Use
  a port for EtherCAT only, and do not connect it to a switch or to your office network.
- Packet capture software:
  - **Windows** -> install [Npcap](https://npcap.com/#download) with **WinPcap
    API-compatible Mode** turned on. Without this mode, the Driver cannot find Npcap.
  - **macOS** -> nothing to install. macOS includes libpcap.

<Edition.Enterprise>

On Linux, a standalone Driver needs the file `libpcap.so`. On Debian and Ubuntu, install
the `libpcap-dev` package. If the
[IgH EtherCAT Master](https://etherlab.org/en_GB/ethercat) kernel module is loaded, the
Driver uses it instead.

</Edition.Enterprise>

<Divider.Divider x />

## Network interface access

EtherCAT sends raw Ethernet frames, so the Driver needs direct access to the network
interface.

| Platform                    | What the Driver needs                                                                                                      |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Linux service               | Nothing. The service has raw Ethernet access and IgH access.                                                               |
| Linux, embedded in the Core | Run the Core as root. Without IgH, you can also start the Core from a systemd unit with `AmbientCapabilities=CAP_NET_RAW`. |
| NI Linux Real-Time          | Nothing. The service runs as root.                                                                                         |
| Windows                     | [Npcap](https://npcap.com/#download).                                                                                      |
| macOS                       | Root access, because only root can open the packet capture devices (`/dev/bpf*`).                                          |

The Core's Docker image runs as a user without these permissions, so its embedded Driver
cannot run EtherCAT tasks.

<Edition.Enterprise>

To start the Driver on Linux by hand, run it as root or give it the access that the
service has. Without IgH, the Driver needs the raw Ethernet capability:

```bash
sudo setcap cap_net_raw+ep /usr/local/bin/synnax-driver
```

With IgH, the Driver needs access to the master device (`/dev/EtherCAT0`) instead.
`sudo synnax-driver install` gives this access to the `synnax` group, so add your user
to that group, then log in again:

```bash
sudo usermod -aG synnax $USER
```

<Note.Note variant="info">
  A service installed by an older Driver does not have these permissions. To update it,
  run `sudo synnax-driver install` again.
</Note.Note>

</Edition.Enterprise>

## How the Driver finds modules

The Driver looks for EtherCAT modules on each Ethernet port every few seconds. A module
shows in the [devices toolbar](/reference/hardware/devices#devices-toolbar) under its
Driver:

- **Name** -> the name stored in the module, such as `EL3102`, or "EtherCAT Slave
  \<position\>".
- **Location** -> the port and the position of the module on the network, such as
  `en5.Slot 2`.

The Driver gets the PDOs of a module from a built-in catalog of Beckhoff and Dewesoft
modules, then from the module itself. If it cannot find them, the status of the module
reads "Failed to discover PDOs", and its description gives the reason. To scan again,
[restart the Driver](/reference/hardware/troubleshooting#restart-the-driver). A module
that the scan cannot read is not supported yet. Manual channels on that module read
wrong values.

## Configure a device

<Client.Tabs>
  <Fragment slot="console">

1. In the devices toolbar, right-click the module and select **Configure**. You can also
   click **Configure** in the "New slave connected" notification.
2. Enter a name, then click **Next**.
3. Enter an [identifier](/reference/hardware/devices#identifiers), then click **Save**.

Configure each module that a task uses.

<Video id="device-drivers/ethercat/configure-device/ethercat-configure" />

  </Fragment>
  <Fragment slot="python">

Find modules and list their PDOs:

```python
for module in client.devices.retrieve(makes=["ethercat"]):
    props = module.properties
    print(module.name, props["network"], props["position"])
    for pdo in props["pdos"]["inputs"]:
        print("  in ", pdo["name"], hex(pdo["index"]), pdo["sub_index"], pdo["data_type"])
    for pdo in props["pdos"]["outputs"]:
        print("  out", pdo["name"], hex(pdo["index"]), pdo["sub_index"], pdo["data_type"])
```

Configure modules in the Console.

  </Fragment>
  <Fragment slot="typescript">

Find modules and list their PDOs:

```typescript
for (const module of await client.devices.retrieve({ makes: ["ethercat"] })) {
  const { network, position, pdos } = module.properties;
  console.log(module.name, network, position, JSON.stringify(pdos));
}
```

Configure modules in the Console. TypeScript returns device properties in camel case.

  </Fragment>
</Client.Tabs>

## Disable a device

Disable a module to leave it out of the network, for example when it is not cabled yet.

<Client.Tabs>
  <Fragment slot="console">

1. In the devices toolbar, right-click the module and select **Disable**. To disable
   several modules, select them first.
2. The status changes to "Device disabled".

The change applies the next time a task on that port starts. To use the module again,
right-click it and select **Enable**.

  </Fragment>
  <Fragment slot="python">

```python
module = client.devices.retrieve(key="<module key>")
module.properties["enabled"] = False
client.devices.create(module)
```

  </Fragment>
  <Fragment slot="typescript">

```typescript
const module = await client.devices.retrieve({ key: "<module key>" });
module.properties.enabled = false;
await client.devices.create(module);
```

  </Fragment>
</Client.Tabs>

## Device properties

| Property                      | Meaning                                                     |
| ----------------------------- | ----------------------------------------------------------- |
| `name`                        | The name stored in the module.                              |
| `vendor_id`, `product_code`   | The vendor and model of the module, as numbers.             |
| `revision`, `serial`          | The revision and serial number of the module, as numbers.   |
| `network`                     | The port of the module, such as `en5`. With IgH, `igh:0`.   |
| `position`                    | The position on the network. Starts at 1, or at 0 with IgH. |
| `enabled`                     | `false` when the module is [disabled](#disable-a-device).   |
| `pdos.inputs`, `pdos.outputs` | The PDOs of the module. See below.                          |

Each PDO has a `name`, an `index` and a `sub_index` (its CoE address), a `bit_length`,
and a `data_type`. TypeScript uses the same fields in camel case, such as `subIndex`.

## Troubleshooting

### No modules show in the devices toolbar

1. Check the cable from the port to the first module, and the power to the modules.
2. Make sure that no other program uses the port.
3. Install the packet capture software in the [prerequisites](#prerequisites), then
   [restart the Driver](/reference/hardware/troubleshooting#restart-the-driver).

### "EtherCAT is unavailable because a required packet capture library is not installed"

A task shows this message when the Driver cannot load the packet capture software.
Follow the [prerequisites](#prerequisites), then
[restart the Driver](/reference/hardware/troubleshooting#restart-the-driver).

### "device ... expected at position ... not found on bus"

The network changed after you created the task. A module moved, or the Driver does not
find it. Check the cables, then edit the channels of the task to use the modules that
are on the network now.

For other problems, see [Troubleshoot hardware](/reference/hardware/troubleshooting).
