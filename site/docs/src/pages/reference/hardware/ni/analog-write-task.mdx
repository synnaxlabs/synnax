An NI analog write task writes the values of command channels to the analog outputs of
one NI device. For example, a setpoint on a schematic can drive a proportional valve
from `ao0` of a USB-6343.

Each output has a command channel and a
[state channel](/reference/hardware/tasks#write-tasks). Each command writes the last
value of every output of the task in one call.

Before you start, you need a
[configured device](/reference/hardware/ni/configure-device).

## Create an NI analog write task

<Client.Tabs>
  <Fragment slot="console">

1. In the devices toolbar, right-click the device and select **Create analog write
   task**.
2. Set **State update rate**.
3. Click **Add channel**. In **Source**, select the **Port**.
4. In **Signal**, select the **Channel type**, then set its fields. See the
   [channel reference](#channel-reference).
5. Click <Icon.Play /> (**Start**).

The Console creates the channels. For a device with the identifier `dev1`, port 0 gives
the command channel `dev1_ao_0_cmd` with the index `dev1_ao_0_cmd_time`, and the state
channel `dev1_ao_0_state` with the index `dev1_ao_state_time`.

  <Fragment slot="python">

Python does not create channels. Create them first.

```python
import synnax as sy
from synnax import ni

dev = client.devices.retrieve(key="<device key>")
state_time = client.channels.create(
    name="dev1_ao_state_time", is_index=True, data_type=sy.DataType.TIMESTAMP
)
state = client.channels.create(
    name="valve_setpoint_state",
    index=state_time.key,
    data_type=sy.DataType.FLOAT32,
)
cmd_time = client.channels.create(
    name="valve_setpoint_cmd_time", is_index=True, data_type=sy.DataType.TIMESTAMP
)
cmd = client.channels.create(
    name="valve_setpoint_cmd", index=cmd_time.key, data_type=sy.DataType.FLOAT32
)

task = ni.AnalogWriteTask(
    name="Valve setpoint",
    device=dev.key,
    channels=[
        ni.AOVoltageChannel(
            port=0,
            min_val=0,
            max_val=10,
            cmd_channel=cmd.key,
            state_channel=state.key,
        )
    ],
)
client.tasks.configure(task)
task.start()
```

Python creates the task on the embedded Driver of the Core. For a device on another
Driver, use the Console or TypeScript.

  </Fragment>

```typescript
import { ni } from "@synnaxlabs/client";

const dev = await client.devices.retrieve({ key: "<device key>" });

  name: "Valve setpoint",

  type: "ni_analog_write",
  config: ni.analogWriteConfigZ.parse({
    device: dev.key,
    channels: [
      {
        type: "ao_voltage",
        port: 0,
        minVal: 0,
        maxVal: 10,
        cmdChannel: cmd.key,
        stateChannel: state.key,
      },
    ],
  }),
});
await task.start();
```

## Task options

| Console label     | Python field           | Default | Notes                                                     |
| ----------------- | ---------------------- | ------- | --------------------------------------------------------- |
| Device            | `device`               |         | The key of the device.                                    |
| State update rate | `state_rate`           | 10 Hz   | Up to 50,000 Hz in the Console.                           |
| Data saving       | `data_saving_disabled` | On      | See [data saving](/reference/hardware/tasks#data-saving). |
| Auto start        | `auto_start`           | Off     | Starts the task each time the Driver starts.              |

### Custom scaling

Channels with **Custom scaling** convert the raw value before the Driver writes it. In
the Console, the options are in the **Scale** section of the channel. In code, set
`custom_scale` to one of these scales:

| Console option | Python class      | Fields                                                                                                                         |
| -------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| None           | `NoneScale`       | No scaling. This is the default.                                                                                               |
| Linear         | `LinearScale`     | **Slope** (`slope`, 1) and **Y-intercept** (`y_intercept`, 0).                                                                 |
| Map            | `MapScale`        | **Pre-scaled min** and **max** to **Scaled min** and **max** (`pre_scaled_min`, `pre_scaled_max`, `scaled_min`, `scaled_max`). |
| Polynomial     | `PolynomialScale` | **Forward coefficients** (`forward_coeffs`) and **Reverse coefficients** (`reverse_coeffs`), from c0 up.                       |
| Table          | `TableScale`      | **Pre-scaled** and **Scaled** pairs (`pre_scaled_vals`, `scaled_vals`). A CSV file can fill them.                              |

Every scale except **None** also has **Prescaled units** (`pre_scaled_units`, `Volts`)
and **Scaled units** (`scaled_units`).

## Troubleshooting

<Problem.List>

<Problem.Item symptom={"The outputs stop changing after a command."}>
<Problem.Cause>

A command was outside the **Range** of its channel. NI-DAQmx rejects it with no message,
and because each command writes every output, all later commands fail too. The state
channels still show the commands that were not written.

</Problem.Cause>
<Problem.Fix>

Send a value inside the range to that channel. The task then writes again.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Port ... has already been used on another channel"}>
<Problem.Cause>

Two channels use the same port.

</Problem.Cause>
<Problem.Fix>

Change the port of one of them.

</Problem.Fix>
</Problem.Item>

</Problem.List>

For other problems, see
[Configure an NI device](/reference/hardware/ni/configure-device#troubleshooting) and
[Troubleshoot hardware](/reference/hardware/troubleshooting).
