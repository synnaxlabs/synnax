An NI analog read task reads the analog inputs of NI devices into channels. Each channel
has a type, such as voltage, current, thermocouple, or bridge, and NI-DAQmx converts the
signal to the units of that type. For example, one task can record pressure transducers
on an NI 9205 and thermocouples on an NI 9211 in the same chassis.

Before you start, you need
[configured devices](/reference/hardware/ni/configure-device).

<Divider.Divider x />

## Channels and timing

Each channel reads one port of one device. A task can use the modules of one chassis,
and all of them must be on the same Driver. The task samples every channel on the device
clock, at the **Sample rate**. See [timing](/reference/hardware/tasks#timing).

Only one running task can use the analog inputs of a module. A second task on the same
module fails to start with an NI-DAQmx error that says the resource is reserved.

## Create an NI analog read task

<Client.Tabs>
  <Fragment slot="console">

1. In the devices toolbar, right-click a device and select **Create analog read task**.
2. Set **Sample rate** and **Stream rate**.
3. Click **Add channel**. In **Source**, select the **Device** and the **Port**.
4. In **Signal**, select the **Channel type**, then set its fields. See the
   [channel reference](#channel-reference).
5. Click <Icon.Play /> (**Start**).

The Console creates the channels. For a device with the identifier `dev1`, port 0 gives
`dev1_ai_0`, and the built-in temperature sensor gives `dev1_ai_temp`. Each device has
an index channel, such as `dev1_ai_time`.

<Video id="hardware/ni/analog-read-task" />

  </Fragment>
  <Fragment slot="python">

Python does not create channels. Create them first.

```python
import synnax as sy
from synnax import ni

dev = client.devices.retrieve(key="<device key>")
time = client.channels.create(
    name="dev1_ai_time", is_index=True, data_type=sy.DataType.TIMESTAMP
)
pressure = client.channels.create(
    name="tank_pressure", index=time.key, data_type=sy.DataType.FLOAT32
)

task = ni.AnalogReadTask(
    name="Tank sensors",
    device=dev.key,
    sample_rate=1000,
    stream_rate=25,
    channels=[
        ni.AIVoltageChannel(
            port=0, min_val=-10, max_val=10, channel=pressure.key
        ),
    ],
)
client.tasks.configure(task)
task.start()
```

Python creates the task on the embedded Driver of the Core. For a device on another
Driver, use the Console or TypeScript. If you open the task in the Console and click
**Start**, the Console replaces your channels with its own.

  </Fragment>
  <Fragment slot="typescript">

TypeScript does not create channels. Create them first.

```typescript
import { ni } from "@synnaxlabs/client";

const dev = await client.devices.retrieve({ key: "<device key>" });
const time = await client.channels.create({
  name: "dev1_ai_time",
  isIndex: true,
  dataType: "timestamp",
});
const pressure = await client.channels.create({
  name: "tank_pressure",
  index: time.key,
  dataType: "float32",
});

const task = await client.tasks.create({
  name: "Tank sensors",
  rack: dev.rack,
  type: "ni_analog_read",
  config: ni.analogReadConfigZ.parse({
    sampleRate: 1000,
    streamRate: 25,
    channels: [
      {
        type: "ai_voltage",
        device: dev.key,
        port: 0,
        minVal: -10,
        maxVal: 10,
        channel: pressure.key,
      },
    ],
  }),
});
await task.start();
```

If you open the task in the Console and click **Start**, the Console replaces your
channels with its own.

## Tare channels

Tare sets the current value of a channel to zero. The task must be running.

1. In the channel list, click **Tare** on a channel. To tare several channels, select
   them, right-click, and select **Tare**.
2. The values of those channels start from zero.

<Divider.Divider x />

## Task options

| Console label | Python field           | Default | Notes                                                                    |
| ------------- | ---------------------- | ------- | ------------------------------------------------------------------------ |
| Sample rate   | `sample_rate`          | 10 Hz   | Up to 1,000,000 Hz in the Console. Each device has a minimum.            |
| Stream rate   | `stream_rate`          | 5 Hz    | Up to 20,000 Hz. See [read tasks](/reference/hardware/tasks#read-tasks). |
| Data saving   | `data_saving_disabled` | On      | See [data saving](/reference/hardware/tasks#data-saving).                |
| Auto start    | `auto_start`           | Off     | Starts the task each time the Driver starts.                             |

## Channel reference

Every channel has a `channel`, the Synnax channel that records the value, a `device`,
the key of the device (**Device**), and a `port` (**Port**). The built-in temperature
sensor has no port. In Python, a channel with no `device` uses the `device` of the task.

Each table shows the Console label of a setting, with its Python field under it. The
**Notes** column lists the values that code uses, such as `MetersPerSecondSquared`. The
Console shows the same values as symbols, such as m/s². Every type except the
temperature types also has **Custom scaling**.

### Custom scaling

Channels with **Custom scaling** convert the raw value before the Driver writes it. In
the Console, the options are in the **Scale** section of the channel. In code, set
`custom_scale` to one of these scales:

| Console option | Python class      | Fields                                                                                                                         |
| -------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| None           | `NoneScale`       | No scaling. This is the default.                                                                                               |
| Linear         | `LinearScale`     | **Slope** (`slope`, 1) and **Y-intercept** (`y_intercept`, 0).                                                                 |
| Map            | `MapScale`        | **Pre-scaled min** and **max** to **Scaled min** and **max** (`pre_scaled_min`, `pre_scaled_max`, `scaled_min`, `scaled_max`). |
| Polynomial     | `PolynomialScale` | **Forward coefficients** (`forward_coeffs`) and **Reverse coefficients** (`reverse_coeffs`), from c0 up.                       |
| Table          | `TableScale`      | **Pre-scaled** and **Scaled** pairs (`pre_scaled_vals`, `scaled_vals`). A CSV file can fill them.                              |

Every scale except **None** also has **Prescaled units** (`pre_scaled_units`, `Volts`)
and **Scaled units** (`scaled_units`).

The device cannot sample that slowly.

</Problem.Cause>
<Problem.Fix>

Raise the **Sample rate** to at least the minimum in the description.

</Problem.Fix>
</Problem.Item>

<Problem.Item symptom={"The task does not start, with an error that says the resource is reserved."}>
<Problem.Cause>

Another running task uses the analog inputs of the same module.

</Problem.Cause>
<Problem.Fix>

Stop the other task, or move its channels into this task.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Port ... has already been used on another channel on the same device"}>
<Problem.Cause>

Two channels use the same port of one device.

</Problem.Cause>
<Problem.Fix>

Change the port of one of them.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"No device provided for channel ..."}>
<Problem.Cause>

A Python channel has no `device`, and the task has no `device` either.

</Problem.Cause>
<Problem.Fix>

Set one of them.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"The network cannot keep up with the stream rate."}>
<Problem.Cause>

The Driver cannot send the samples fast enough. The task shows "Failed to read data",
with this text in the description.

</Problem.Cause>
<Problem.Fix>

Lower the **Stream rate**, so that each batch holds more samples.

</Problem.Fix>
</Problem.Item>

</Problem.List>
