An MQTT write task publishes a message each time a value is written to a command
channel. Use it to send setpoints and commands to devices that listen on MQTT topics. It
can also command [Sparkplug B](/reference/hardware/mqtt/sparkplug#command-tags) tags.
Before you start, [connect an MQTT broker](/reference/hardware/mqtt/connect-broker).

The task has no state channels and no data saving option. To confirm a command, read the
value back from the device with a [read task](/reference/hardware/mqtt/read-task).

## Targets

A target is one topic and one command channel. Each value written to the command channel
publishes one message to the topic:

- **Pointer** -> where the value goes in a JSON payload, such as `/position`. An empty
  pointer sends the bare value as the whole payload, with no other fields.
- **Output type** -> the value goes out as a number, a string, or a boolean. The list
  shows only what the data type of the channel allows. The **Enum mapping** of each type
  writes a label in place of a matching value, such as `OPEN` for `1`.
- **Additional fields** -> the same fields in each payload. A static field adds a fixed
  value, and a generated field adds a new UUID or the current time.

With the pointer `/position`, a static field `/source`, and a generated UUID at `/id`, a
command of 42 publishes:

```json
{ "position": 42, "source": "synnax", "id": "6f1c2e3a-..." }
```

## Create an MQTT write task

<Client.Tabs exclude={["typescript"]}>
  <Fragment slot="console">

1. In the devices toolbar, right-click the broker and select **Create write task**. You
   can also run the "Create MQTT write task" command.
2. Click **Add targets**. Select a topic, then select the field that carries the command
   value. For a topic that publishes rarely, click **Add a topic by name**.
3. Click **Add** _N_ **targets**. Each field becomes a target.
4. Select a target to set its **Pointer** and **Output type**. To add fields to the
   payload, click **Static** or **Generated** under **Additional fields**.
5. Click <Icon.Play /> (**Start**).

The Console creates a command channel for each target.

  <Fragment slot="python">

Python does not create channels. Create the command channel and its index first.

```python
import synnax as sy
from synnax import mqtt

broker = client.devices.retrieve(name="Plant broker")
cmd_time = client.channels.create(
    name="valve1_cmd_time", is_index=True, data_type=sy.DataType.TIMESTAMP
)
cmd = client.channels.create(
    name="valve1_cmd", index=cmd_time.key, data_type=sy.DataType.FLOAT64
)

task = mqtt.WriteTask(
    name="Valve 1 commands",
    device=broker.key,
    targets=[
        mqtt.PlainWriteTarget(
            topic="plant/valve1/set",
            channel=mqtt.FloatChannelField(pointer="/position", channel=cmd.key),
            fields=[
                mqtt.StaticWriteField(
                    pointer="/source", json_type="string", value="synnax"
                ),
                mqtt.GeneratedWriteField(pointer="/id", generator="uuid"),
            ],
        )
    ],
)
client.tasks.configure(task)
task.start()
```

## When the broker is down

The task never holds a command back for later. If the broker is not connected when a
command arrives, the task drops the command and shows a warning. A command that waited
out an outage would reach the device long after the operator sent it, which is not safe.
The warning also shows while no command arrives, so you can see the outage before you
send one.

## Target reference

A target has these settings:

| Setting                                           | Default       | Notes                                                       |
| ------------------------------------------------- | ------------- | ----------------------------------------------------------- |
| Topic <small>`topic`</small>                      |               | The topic to publish to. No wildcards.                      |
| Quality of service <small>`qos`</small>           | At least once | At most once (0), at least once (1), or exactly once (2).   |
| Retain <small>`retained`</small>                  | Off           | Asks the broker to keep the message for later subscribers.  |
| Pointer <small>`channel.pointer`</small>          | Empty         | Empty sends the bare value as the whole payload.            |
| Output type <small>`channel.type`</small>         | Number        | Number, string, or boolean. Other data types write as such. |
| Time format <small>`channel.time_format`</small>  |               | Required for a `timestamp` command channel.                 |
| Channel <small>`channel.channel`</small>          |               | The command channel.                                        |
| Enum mapping <small>`channel.enum_values`</small> | None          | Maps channel values to the labels written in their place.   |

The data type of the command channel sets which types it can be written as:

| Channel data type | Output type (`channel.type`)                        |
| ----------------- | --------------------------------------------------- |
| Float             | **Number** (`float`), **String**, or **Boolean**    |
| Signed integer    | **Number** (`integer`), **String**, or **Boolean**  |
| Unsigned integer  | **Number** (`unsigned`), **String**, or **Boolean** |
| `boolean`         | **Boolean**, **Number** (`unsigned`), or **String** |
| `timestamp`       | `timestamp`, in its time format                     |
| `string`          | **String**                                          |
| `json`            | `json`, as its JSON value                           |
| `uuid`            | `uuid`, as a string                                 |
| `bytes`           | `bytes`, as base64 text                             |

Each type has its own enum mapping, with values of that type. **Boolean** writes a
nonzero value as the label of `true`.

An additional field has these settings:

| Setting                                  | Default  | Notes                                      |
| ---------------------------------------- | -------- | ------------------------------------------ |
| Pointer <small>`pointer`</small>         |          | Where the value goes.                      |
| JSON type <small>`json_type`</small>     | Number   | Static fields only. The type of the value. |
| Value <small>`value`</small>             |          | Static fields only. The fixed value.       |
| Generator <small>`generator`</small>     | UUID     | Generated fields only. UUID or timestamp.  |
| Time format <small>`time_format`</small> | ISO 8601 | Generated timestamps only.                 |

In code, a target is `PlainWriteTarget`, and its command channel is a `ChannelField`
such as `FloatChannelField`, named for its kind. The additional fields are
`StaticWriteField` and `GeneratedWriteField`.

## Troubleshooting

<Problem.List>

<Problem.Item message={"broker is not connected"}>
<Problem.Cause>

The connection to the broker is down, so the task drops each command that arrives. The
Core connects again on its own, and the warning clears when the connection returns.

</Problem.Cause>
</Problem.Item>

<Problem.Item message={"targets: the task has no enabled targets"}>
<Problem.Cause>

The task has no targets, or each target is disabled.

</Problem.Cause>
<Problem.Fix>

Add a target, or enable one.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"target ...: channel ... does not exist"}>
<Problem.Cause>

The command channel of a target was deleted.

</Problem.Cause>
<Problem.Fix>

Remove the target, then add it again with **Add targets**. The Console creates a new
command channel when you start the task.

</Problem.Fix>
</Problem.Item>

</Problem.List>

For problems with the connection, see
[Connect an MQTT broker](/reference/hardware/mqtt/connect-broker#troubleshooting).
