A channel is a collection of time-ordered samples from one source. The source is usually
a sensor. A channel can also hold actuator commands, status codes, calculated values,
log messages, or other time-ordered data. All data that you plot, record, or control in
Synnax goes through channels.

<Divider.Divider x />

## Channels in the Console

The [channels toolbar](/reference/get-started/ui-overview#channels) shows all of the
channels in Synnax. Double-click a channel to add it to the open line plot, or to a new
line plot. A virtual channel that is not calculated opens in a log. Right-click a
channel to rename, group, or delete it. To make a channel yourself, see
[create channels](/reference/channels/create).

You do not usually create channels by hand. When you configure a
[read task](/reference/hardware/tasks#read-tasks), Synnax creates an index channel and a
data channel for each input. A [write task](/reference/hardware/tasks#write-tasks)
creates a command channel for each output, and a state channel for outputs that report
back.

## Samples

A sample is one value recorded at one point in time. Most samples are sensor readings,
such as a temperature or a pressure. A sample can also be an actuator command, a status
code, or any other value of a declared data type.

Synnax stores the samples written to a channel, and it streams them live at the same
time. A sensor that records 25 samples per second (25 Hz) writes to a channel. A line
plot shows each sample when it arrives, and you can query the same samples later.

Channels are comparable to **tags** in a time-series database such as
[InfluxDB](https://www.influxdata.com/) or a SCADA system such as
[Ignition](https://inductiveautomation.com/). A system can have hundreds or thousands of
channels, one for each data source.

## Channel types

Synnax has three types of channels. **Index** channels store only timestamps. **Data**
channels store values, such as sensor readings, and use an index channel to find them by
time. **Virtual** channels stream values live and do not store them.

### Index channels

An **index** channel (or _index_) holds the timestamps for one or more data channels.
Index channels always have the `timestamp` data type. Their samples are ordered `int64`
nanosecond UTC timestamps.

An index channel works like the index of a book. To find the samples of a data channel
in a time range, Synnax first finds the timestamps in the index channel. Then it gets
the samples at those positions from the data channel.

### Data channels

Data channels store telemetry samples. They hold sensor readings, actuator commands,
calculated values, or other time-ordered points.

Each data channel has one data type. Most data channels store fixed-width numbers, such
as floats or integers. A data channel can also store strings, JSON values, or raw bytes.

Each data channel has one index channel, which Synnax uses to find samples by time. Many
data channels can share one index channel.

### Virtual channels

Virtual channels stream values live. Synnax does not store their values, and they have
no index channel. Use a virtual channel for a value that only live views need, and that
you do not need to query by time later.

To store strings, logs, JSON values, or binary data, use a data channel with the
`string`, `json`, or `bytes` data type.

## Calculated channels

A calculated channel computes its values from other channels with an Arc expression.
Synnax calculates the values when you read the channel, and does not store them.
[Calculated channels](/reference/channels/calculated) shows how to create one.

## Channel fields

Each channel has the fields below.
[Create channels](/reference/channels/create#channel-parameters) lists all of the
parameters you can set when you create a channel.

#### Key

A number that Synnax gives to the channel when you create it. The key identifies the
channel, and you cannot change it.

#### Name

A human-readable name for the channel. Most people find channels by name. Synnax lets
two channels have the same name, but we recommend unique names.

#### Data type

Each channel has one data type for all of its samples. Index channels always have the
`timestamp` data type. Data channels can have any of these types:

| Data type   | Description                                                                  | Size     |
| ----------- | ---------------------------------------------------------------------------- | -------- |
| `boolean`   | Boolean value                                                                | 1 byte   |
| `int8`      | Signed 8-bit integer                                                         | 1 byte   |
| `int16`     | Signed 16-bit integer                                                        | 2 bytes  |
| `int32`     | Signed 32-bit integer                                                        | 4 bytes  |
| `int64`     | Signed 64-bit integer                                                        | 8 bytes  |
| `uint8`     | Unsigned 8-bit integer                                                       | 1 byte   |
| `uint16`    | Unsigned 16-bit integer                                                      | 2 bytes  |
| `uint32`    | Unsigned 32-bit integer                                                      | 4 bytes  |
| `uint64`    | Unsigned 64-bit integer                                                      | 8 bytes  |
| `timestamp` | 64-bit nanosecond UTC integer                                                | 8 bytes  |
| `float32`   | 32-bit floating point                                                        | 4 bytes  |
| `float64`   | 64-bit floating point                                                        | 8 bytes  |
| `uuid`      | [Universally Unique IDentifier](https://www.rfc-editor.org/rfc/rfc9562.html) | 16 bytes |
| `string`    | UTF-8 string                                                                 | variable |
| `json`      | JSON value                                                                   | variable |
| `bytes`     | Raw byte sequence                                                            | variable |
