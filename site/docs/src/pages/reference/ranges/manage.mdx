## Create a range

<Client.Tabs client:load exclude={["cpp"]}>

  <Fragment slot="console">

{/* prettier-ignore-start */}

To open the create dialog, do one of these steps:

- Click create (<Icon.Add />) in the ranges toolbar.
- Run the `Create range` command from the
  [search and command palette](/reference/get-started/ui-overview#search-and-command-palette).
- Select a region of a [line plot](/reference/visualize/line-plots#select), right-click
  it, and select `Create range from selection`.

{/* prettier-ignore-end */}

Enter a name. A new range starts now and has no end, so it is in progress. Use the
timeline to change the start or end time. You can also set a parent range and labels.

Click `Save to Core` to store the range in Synnax. Click `Save locally` to keep the
range only in this Console. The ranges toolbar marks a local range with an `L`. To store
it later, right-click it in the ranges toolbar and select `Save to Core`.

<Video client:only="react" id="client/ranges/create" />

  </Fragment>

  <Fragment slot="python">

To create a range, use the `client.ranges.create` method:

```python
import synnax as sy

# Create a range with a specific time interval
start = sy.TimeStamp("2023-02-12 12:30:00")
end = sy.TimeStamp("2023-02-12 14:30:00")

my_range = client.ranges.create(
    name="My Range",
    time_range=sy.TimeRange(start=start, end=end),
    retrieve_if_name_exists=True,  # Return the existing range instead of a duplicate
)

# Or use the convenience span_range method
start = sy.TimeStamp.now()
my_range = client.ranges.create(
    name="My Range",
    time_range=start.span_range(sy.TimeSpan.HOUR * 2),
)
```

  </Fragment>

  <Fragment slot="typescript">

To create a range, use the `client.ranges.create` method:

```typescript
import { TimeRange, TimeSpan, TimeStamp } from "@synnaxlabs/client";

// Create a range with a specific time interval
const start = new TimeStamp("2023-02-12 12:30:00");
const end = new TimeStamp("2023-02-12 14:30:00");

const range = await client.ranges.create({
  name: "My Range",
  timeRange: new TimeRange(start, end),
  // No retrieveIfNameExists option in TypeScript
});

// Or use the convenience span method
const start = TimeStamp.now();
const range = await client.ranges.create({
  name: "My Range",
  timeRange: start.span(TimeSpan.hours(2)),
});
```

  </Fragment>
</Client.Tabs>

### Create child ranges

[Child ranges](/reference/ranges#child-ranges) divide a range into smaller intervals.

<Client.Tabs client:load exclude={["cpp"]}>

  <Fragment slot="console">

{/* prettier-ignore-start */}

Set the parent range in the create dialog. You can also right-click a range in the
ranges toolbar or the range explorer and select `Create child range`, or click create
(<Icon.Add />) in the child ranges section of the [range overview](#range-overview).

{/* prettier-ignore-end */}

<Video client:only="react" id="client/ranges/create-child" />

  </Fragment>

  <Fragment slot="python">

The most convenient way is the `create_child_range` shorthand on a parent `Range`:

```python
child_range = parent_range.create_child_range(
    name="My Child Range",
    time_range=sy.TimeRange(start=start, end=end),
)
```

You can also pass the parent `Range` directly to `client.ranges.create` via the `parent`
keyword. This form works for one or many children:

```python
child_range = client.ranges.create(
    name="My Child Range",
    time_range=sy.TimeRange(start=start, end=end),
    parent=parent_range,
)
```

To create many children in one call, set `parent` on each `Range`:

```python
client.ranges.create([
    sy.Range(name="Child A", time_range=tr_a, parent=parent_range),
    sy.Range(name="Child B", time_range=tr_b, parent=parent_range),
])
```

  </Fragment>

  <Fragment slot="typescript">

Pass the parent `Range` directly on the child being created. This form works for one or
many children:

```typescript
const childRange = await client.ranges.create({
  name: "My Child Range",
  timeRange: new TimeRange(start, end),
  parent: parentRange,
});
```

Or set `parent` on each range when batching:

```typescript
await client.ranges.create([
  { name: "Child A", timeRange: trA, parent: parentRange },
  { name: "Child B", timeRange: trB, parent: parentRange },
]);
```

  </Fragment>
</Client.Tabs>

## Find a range

### Range explorer

{/* prettier-ignore-start */}

The range explorer lists all the ranges in Synnax. To open it, click open range explorer
(<Icon.Explore />) in the ranges toolbar, or run the `Open range explorer` command from
the search and command palette.

In the range explorer, you can:

- Search for a range by name.
- Filter the list by label.
- Click a range to open its [range overview](#range-overview).
- Click the stage icon of a range to start, complete, or reopen it.
- Hold <Icon.Keyboard.Shift />, <Icon.Keyboard.Control /> (Windows), or
  <Icon.Keyboard.Command /> (macOS) and click to select more than one range.
- Right-click a range to rename, favorite, or delete it, or to create a child range.

{/* prettier-ignore-end */}

### Favorites

{/* prettier-ignore-start */}

The ranges toolbar shows your favorite ranges. A range that you create is a favorite.
To add a range to your favorites, click the star (<Icon.StarOutlined />) beside it in
the range explorer or on its range overview. You can also right-click it in the range
explorer and select `Favorite`. To remove a range from the ranges toolbar, right-click
it and select `Unfavorite`.

{/* prettier-ignore-end */}

### Active range

The active range is the range that the Console uses for
[channel aliases](/reference/channels/manage#channel-aliases) and
[snapshots](#snapshots). To make a range active, click it in the ranges toolbar, or
right-click it and select `Set as active range`. To clear it, right-click the active
range and select `Clear active range`.

<Divider.Divider x />

## Range overview

The range overview shows all the information about one range. To open it, do one of
these steps:

- Click the range in the range explorer.
- Right-click the range in the ranges toolbar and select `View details`.
- Right-click a range annotation on a line plot and select `View details`.

The range overview has these parts:

- **Name**: Click the name to change it.
- **Parent**: A child range shows a link to its parent range.
- **Timeline**: Click the stage to start, complete, or reopen the range. Click the start
  or end time to change it.
- **Labels**: Add or remove [labels](#labels).
- **Child ranges**: Lists the child ranges. Click create (<Icon.Add />) to add one.
- **Metadata**: Lists the [metadata](#metadata) of the range.
- **Snapshots**: Lists the [snapshots](#snapshots) of the range.

The Console saves each change at once.

{/* prettier-ignore-start */}

To download the data of the range, click download as CSV (<Icon.CSV />). See
[export data](/reference/ranges/export) for the steps.

{/* prettier-ignore-end */}

<Edition.Enterprise>

The range overview also has buttons that copy a link to the range and copy Python or
TypeScript code that retrieves the range.

</Edition.Enterprise>

## Retrieve ranges

### Single

Retrieve a range by its name or key. Synnax will raise a `NotFoundError` if the range
does not exist, and a `MultipleFoundError` if multiple ranges with the given name exist.

<Client.Tabs client:load exclude={["cpp","console"]}>

  <Fragment slot="python">

```python
# By name
my_range = client.ranges.retrieve(name="My Range")

# By key
my_range = client.ranges.retrieve(key=my_range.key)
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
// By name
const myRange = await client.ranges.retrieve("My Range");

// By key
const myRange = await client.ranges.retrieve(myRange.key);
```

  </Fragment>
</Client.Tabs>

### Multiple

Retrieve multiple ranges by passing a list of names or keys. When retrieving multiple
ranges, Synnax will not raise an error if a range cannot be found. Instead, the missing
range will be omitted from the returned list.

<Client.Tabs client:load exclude={["cpp","console"]}>

  <Fragment slot="python">

```python
# By name
my_ranges = client.ranges.retrieve(names=["My Range", "My Other Range"])

# By key
my_ranges = client.ranges.retrieve(keys=[my_range.key, my_other_range.key])

# By search term
ranges = client.ranges.search("Hotfire")
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
// By name
const myRanges = await client.ranges.retrieve(["My Range", "My Other Range"]);

// By key
const myRanges = await client.ranges.retrieve([myRange.key, myOtherRange.key]);

// By search term
const ranges = await client.ranges.retrieve({ searchTerm: "Hotfire" });
```

  </Fragment>
</Client.Tabs>

### Child

If a range has child ranges, you can retrieve them directly from the parent range.

<Client.Tabs client:load exclude={["cpp","console"]}>

  <Fragment slot="python">

```python
child_ranges = my_range.children
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
const childRanges = await myRange.retrieveChildren();
```

  </Fragment>
</Client.Tabs>

### Parent

Navigate up the hierarchy by retrieving a child range's parent.

<Client.Tabs client:load exclude={["cpp","console"]}>

  <Fragment slot="python">

<Note.Note variant="info">
  Retrieving a parent range is not directly supported in Python.
</Note.Note>

  </Fragment>

  <Fragment slot="typescript">

```typescript
const parentRange = await myRange.retrieveParent();
```

  </Fragment>
</Client.Tabs>

## Update a range

<Client.Tabs client:load exclude={["cpp"]}>

  <Fragment slot="console">

Right-click the range in the ranges toolbar or the range explorer and select `Rename`.
To change the time range or labels, edit them in the [range overview](#range-overview).

  </Fragment>

  <Fragment slot="python">

Call `client.ranges.create` with the `key` of the range to update. You can change the
name, time range, or color.

```python
import synnax as sy

# First, retrieve the range you want to update
my_range = client.ranges.retrieve(name="My Range")

# Update the range by providing its key and new values
updated_range = client.ranges.create(
    key=my_range.key,  # Specify the key to update existing range
    name="My Updated Range",  # New name
    time_range=sy.TimeRange(
        start=sy.TimeStamp("2023-02-12 13:00:00"),
        end=sy.TimeStamp("2023-02-12 15:00:00"),
    ),
    color="#00FF00",  # New color
)
```

  </Fragment>

  <Fragment slot="typescript">

Call `client.ranges.create` with the `key` of the range to update. You can change the
name, time range, or color.

```typescript
import { TimeRange, TimeStamp } from "@synnaxlabs/client";

// First, retrieve the range you want to update
const myRange = await client.ranges.retrieve("My Range");

// Update the range by providing its key and new values
const updatedRange = await client.ranges.create({
  key: myRange.key, // Specify the key to update existing range
  name: "My Updated Range", // New name
  timeRange: new TimeRange(
    new TimeStamp("2023-02-12 13:00:00"),
    new TimeStamp("2023-02-12 15:00:00"),
  ),
  color: "#00FF00", // New color
});
```

  </Fragment>
</Client.Tabs>

<Note.Note variant="warning" className="compact">
  In code, an update replaces all the properties of the range. Include every property
  that you want to keep. If no range has the `key`, Synnax creates a new range with that
  key.
</Note.Note>

## Metadata

[Metadata](/reference/ranges#metadata) keys and values are text. In code, cast each
value to the type that you need.

### Set

<Client.Tabs client:load exclude={["cpp"]}>

  <Fragment slot="console">

{/* prettier-ignore-start */}

In the metadata section of the [range overview](#range-overview), click create
(<Icon.Add />). Enter a key and a value, then click the check (<Icon.Check />). To
change a value, click it and type the new value.

{/* prettier-ignore-end */}

<Video client:only="react" id="client/ranges/set-metadata" />

  </Fragment>

  <Fragment slot="python">

```python
my_range = client.ranges.retrieve(name="My Range")

# Set a single key/value pair
my_range.meta_data.set("part_number", "12345")

# Another way to set a single key/value pair
my_range.meta_data["part_number"] = "12345"

# Set multiple key/value pairs
my_range.meta_data.set({
    "part_number": "12345",
    "test_configuration": "Test 1",
    "test_result": "123.45",
})
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
const myRange = await client.ranges.retrieve("My Range");

// Set a single key/value pair
await myRange.kv.set("part_number", "12345");

// TypeScript only supports the set() method
// (no bracket syntax)

// Set multiple key/value pairs
await myRange.kv.set({
  part_number: "12345",
  test_configuration: "Test 1",
  test_result: "123.45",
});
```

  </Fragment>
</Client.Tabs>

### Get

<Client.Tabs client:load exclude={["cpp"]}>

  <Fragment slot="console">

The metadata section of the [range overview](#range-overview) lists every key and value.
Click the copy button beside a value to copy it.

  </Fragment>

  <Fragment slot="python">

```python
my_range = client.ranges.retrieve(name="My Range")

# Retrieve a single key
part_number = my_range.meta_data["part_number"] # Or use .get("key")

# Retrieve multiple keys
metadata = my_range.meta_data.get(["part_number", "test_configuration"])

# List all metadata
all_metadata = my_range.meta_data.get([])
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
const myRange = await client.ranges.retrieve("My Range");

// Retrieve a single key
const partNumber = await myRange.kv.get("part_number");

// Retrieve multiple keys
const metadata = await myRange.kv.get(["part_number", "test_configuration"]);

// List all metadata
const allMetadata = await myRange.kv.list();
```

  </Fragment>
</Client.Tabs>

```python
my_range = client.ranges.retrieve(name="My Range")
```

```typescript
const labels = await myRange.retrieveLabels();

await myRange.removeLabel(label.key);
```

## Read from a range

A range lets you read data without exact time boundaries.

<Client.Tabs client:load exclude={["cpp"]}>

  <Fragment slot="console">

Right-click a range in the ranges toolbar and select `Add to new plot`. When a line plot
is open, select `Add to active plot` to add the range to it. See
[line plots](/reference/visualize/line-plots) for more.

  </Fragment>

  <Fragment slot="python">

```python
my_range = client.ranges.retrieve("My Interesting Test")

# Read data from a single channel
data = my_range.my_precise_tc.read()

# Read data from multiple channels
frame = my_range.read(["my_precise_tc", "my_precise_pt"])

# Python allows direct use of channel names as properties
celsius = my_range.my_precise_tc - 273.15
```

  </Fragment>

  <Fragment slot="typescript">

```typescript
const myRange = await client.ranges.retrieve("My Interesting Test");

// Read data from a single channel
const data = await myRange.read("my_precise_tc");

// Read data from multiple channels
const frame = await myRange.read(["my_precise_tc", "my_precise_pt"]);

// Convert from Kelvin to Celsius
const celsius = data.map((v) => v - 273.15);
```

  </Fragment>
</Client.Tabs>

### Read by alias

Once you've set an [alias](/reference/channels/manage#channel-aliases), you can access
the channel using that alias.

<Client.Tabs client:load exclude={["cpp","console"]}>

  <Fragment slot="python">

Python allows you to access aliased channels directly as properties:

```python
burst_test = client.ranges.retrieve(name="Oct 10 Burst Test")

# Access by alias as a property
data = burst_test.tank_pressure

# Or use dictionary syntax
data = burst_test["tank_pressure"]

# Regex returns a list of matching channels
tank_channels = burst_test["^tank"]
```

  </Fragment>

  <Fragment slot="typescript">

TypeScript requires resolving the alias to a channel key first:

```typescript
const burstTest = await client.ranges.retrieve("Oct 10 Burst Test");

// Resolve alias to channel key, then read
const channelKey = await burstTest.resolveAlias("tank_pressure");

// Then read by channel key
const data = await burstTest.read(channelKey);

// Or read directly by original channel name
const data2 = await burstTest.read("daq_analog_input_1");
```

  </Fragment>
</Client.Tabs>

## Write to a range

Writing to a range removes the burden of needing to correctly align the timestamps for
different channels. The write will assume that the timestamp of the first sample is the
start of the range.

<Client.Tabs client:load exclude={["cpp","console"]}>

  <Fragment slot="python">

```python
my_range = client.ranges.retrieve("My Interesting Test")

temperatures = [55, 55.1, 55.7, 57.2, 58.1, 58.9, 59.1, 59.2, 59.3]
pressures = [100, 100.1, 100.7, 102.2, 103.1, 103.9, 104.1, 104.2, 104.3]

my_range.write({
    "my_precise_tc": temperatures,
    "my_precise_pt": pressures,
})
```

  </Fragment>

  <Fragment slot="typescript">

<Note.Note variant="info">Writing to ranges is not supported in TypeScript.</Note.Note>

  </Fragment>
</Client.Tabs>

## Delete a range

Deleting a range also deletes its child ranges. It does not delete the data of the
channels in the range.

<Client.Tabs client:load exclude={["cpp"]}>

  <Fragment slot="console">

Right-click the range in the ranges toolbar or the range explorer and select `Delete`.

<Image client:only="react" id="client/ranges/delete" />

  </Fragment>

  <Fragment slot="python">

Delete a range by passing its key to the `client.ranges.delete` method.

```python
# Delete a single range
client.ranges.delete(my_range.key)

# Delete multiple ranges
client.ranges.delete([my_range.key, my_other_range.key])
```

  </Fragment>

  <Fragment slot="typescript">

Delete a range by passing its key to the `client.ranges.delete` method.

```typescript
// Delete a single range
await client.ranges.delete(myRange.key);

// Delete multiple ranges
await client.ranges.delete([myRange.key, myOtherRange.key]);
```

  </Fragment>
</Client.Tabs>

## Range parameters

<Edition.Enterprise>

The client libraries accept these parameters when they create or update a range.

| Parameter                                                 | Type                                                  | Required | Default                                        | Description                                                                                                     |
| --------------------------------------------------------- | ----------------------------------------------------- | -------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `name`                                                    | string                                                | Yes      | -                                              | Human-readable name for the range                                                                               |
| <Client.Var client:load py="time_range" ts="timeRange" /> | [`TimeRange`](/reference/client/time-types#timerange) | Yes      | -                                              | Time interval spanned by the range (start must be ≤ end)                                                        |
| `color`                                                   | string                                                | No       | `""`                                           | Hex color code for identifying the range in visualizations (e.g., `"#FF0000"`)                                  |
| `key`                                                     | `UUID`                                                | No       | Auto                                           | Unique identifier (automatically generated by Synnax if not provided)                                           |
| `parent`                                                  | `Range`                                               | No       | <Client.Var client:load py="None" ts="null" /> | Optional parent range. Pass the parent `Range` itself.                                                          |
| `retrieve_if_name_exists`                                 | boolean                                               | No       | `False`                                        | If `True`, retrieves existing range with same name and time range instead of creating a duplicate. Python only. |

</Edition.Enterprise>
