A range (short for _time range_) is a named time interval that marks an important event
in your data. [Channels](/reference/channels) group samples by their source. Ranges
group samples by time period.

A range has a name, a start time, and an end time. You do not add channels to a range. A
range covers the data of every channel in its time interval.

<Note.Note variant="info" className="compact">
  The interval includes its start and excludes its end.
</Note.Note>

## How teams use ranges

A test operator creates a range for each test run, hotfire, or calibration. The range
records when the run started and ended, and it holds the facts about the run: the part
number, the procedure, and the test parameters.

A test or data engineer uses ranges to find data later. They search for a range by name
or label, plot its data, compare it with other runs, and
[export it as CSV](/reference/ranges/export). They do not have to remember timestamps.

Ranges also mark events outside of tests, such as anomalies, maintenance periods, or
automated control actions. An
[Arc](/reference/control/arc/reference/standard-library/ranges) program can create a
range when a sequence starts and end it when the sequence stops.

## Stages

The Console shows each range in one of three stages. The stage comes from the time range
and the current time:

- **To do**: The range starts in the future.
- **In progress**: The range has started and has not ended. A range with no end time
  stays in progress.
- **Completed**: The range has ended.

When you change the stage of a range in the Console, Synnax changes its start or end
time. For example, when you complete an in-progress range, its end time becomes the
current time.

## Metadata

Metadata records the facts about the events in a range. Common examples are part
numbers, links to procedures, and configuration values.

Metadata is a set of key-value pairs. The key and the value are text. When the value is
a link, the Console shows a button that opens it.

Do not store large data, such as a 250 kB configuration file, as metadata. This can make
Synnax slower. Store a link to the file in cloud storage or a Git repository.

## Labels

Labels put ranges into groups. Use them to show the test stand or assembly line of a
range, the result of a test (success, failure), or any other category that your team
uses. You can filter ranges by label.

<Divider.Divider x />

## Child ranges

Child ranges divide a range into smaller intervals. For example, a campaign range can
cover all the tests on one component, and a child range can mark each test in the
campaign.

A child range uses the channel aliases of its parent. It can set its own alias for a
channel to replace the alias of the parent. When you delete a range, Synnax also deletes
its child ranges.

<Divider.Divider x />

## Channel aliases

An alias is a different name for a channel inside one range. For example, a device has
three analog inputs: `ai_0`, `ai_1`, and `ai_2`. In one test, `ai_0` measures tank
pressure, so you give it the alias `tank_pressure`. In a different test, `ai_0` measures
temperature, so you give it the alias `temperature`.

When you search for a channel in a range, you can use its name or its alias. To set an
alias, see [channel aliases](/reference/channels/manage#channel-aliases).

<Divider.Divider x />

## Snapshots

A snapshot is a copy of a resource that is attached to a range. It records the
configuration of the resource at the time of the range.

The most useful snapshot is of a data acquisition or control
[task](/reference/hardware). A task snapshot keeps calibrations, scale values, and the
physical ports and lines of the task. You can also snapshot a
[schematic](/reference/visualize/schematics#snapshotting-a-schematic) to keep how it
looked during a test.
