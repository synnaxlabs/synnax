### Breaking changes in 0.63

#### Colors

- Label, range, log channel, table cell, panel, and schematic colors are color
  references: a named color, `{ type: "named", key }`, or a fixed color,
  `{ type: "fixed", value }`. The update keeps each stored color as a fixed color. In a
  schematic, these stay color values:
  - the stroke of a toggle, static, or light symbol, such as a valve or a pump
  - the colors that a state draws: the on color of a light, the color of each state of a
    select or a state indicator, and the stroke and fill of each region in the state
    overrides of a custom symbol
  - the redline scale of a value
- TypeScript: these colors hold a reference, and a create or a color change takes one.
  Change `color: "#FF0000"` to `color: { type: "fixed", value: "#FF0000" }`.
- Python: these fields hold a `NamedRef` or a `FixedRef`:
  - `Label.color` and `Range.color`
  - `sy.log.ChannelEntry.color` and `sy.Panel.color`
  - the colors of `sy.table.TextCellConfig` and `sy.table.ValueCellConfig`
  - every other stroke, fill, text, level, and axis color of the schematic `*NodeConfig`
    and `*EdgeConfig` types, such as `TankNodeConfig.fill_color`

  `labels.create(name=..., color=...)`, `ranges.create(...)`, `sy.Range(...)`, and
  `set_color` still take a color, such as `"#FF0000"`, and keep it as a fixed color. A
  model that you build, such as a `sy.Label`, takes a reference: use
  `sy.color.to_ref("#FF0000")`.

- A stale schematic symbol shows a clock indicator and keeps its colors. Schematic
  symbols no longer have a staleness color, and the update removes stored staleness
  colors. In TypeScript, `stalenessColor` on a schematic symbol is a type error. Python
  schematic `*NodeConfig` types drop `staleness_color` with no error. Table cells keep
  their staleness color.

#### Tables

- The staleness timeout of a table value cell is a time span in nanoseconds, not a
  number of seconds. The update converts stored tables. Python:
  `ValueCellConfig(staleness_timeout=5)` fails, so use `5 * sy.TimeSpan.SECOND`.
  TypeScript: `stalenessTimeout: 5` fails, so use `TimeSpan.seconds(5).nanoseconds`.

#### Kafka

- Read tasks in code take an ICD: `kafka.ReadField` is removed, and each record takes an
  `icd` key and its `messages`. The update converts stored tasks.
- Read tasks in code take `topics`: `topic` and `records` move into a list of
  `kafka.ReadTopic(name=..., records=[...])`. Python `kafka.ReadConfig` drops `topic`
  and `records` with no error, so the task holds no topics and fails when it is
  configured. In TypeScript, `topic` and `records` are type errors. The update converts
  stored tasks.
- The `tls` property of a cluster is now `secure`, as on an MQTT broker. Python
  `kafka.Properties(tls=True)` drops `tls` with no error, so the cluster connects
  without TLS. If the cluster also sets `ca_certificate`, a connection to it fails with
  `ca_certificate: requires TLS` instead. In TypeScript, `tls` is a type error. Use
  `secure`. The update renames `tls` on stored clusters.

#### NI

- The `meas_time` of an NI counter frequency or period channel is a time span in
  nanoseconds, not a number of seconds. The update converts stored tasks. In code, a
  fractional value such as `0.001` fails, but a whole number such as `2` passes and
  means 2 ns. Check every `meas_time` and `measTime` in your scripts. Python: use
  `1 * sy.TimeSpan.MILLISECOND`. TypeScript: use `TimeSpan.milliseconds(1).nanoseconds`.

#### Users

- `users.create` takes only a name, a role, and an optional key. It no longer takes a
  username or a password, and the new user cannot log in until it has one. Give it a
  password with `client.auth.passwords.create(username, password, subject=...)` in
  Python or `client.auth.passwords.create({ subject, username, password })` in
  TypeScript. In Python, `users.create(username=..., password=...)` raises `TypeError`.
  A 0.62 client that sends a name gets a user with no password, and one that sends no
  name gets a validation error.
- `users.retrieve` no longer takes `username` or `usernames`. To find a user by
  username, call `client.auth.passwords.retrieve`. `users.change_username` and
  `users.changeUsername` keep their signatures. A 0.62 client gets an error when it
  changes a username or looks up a user by username.
- The API key routes move from `auth/key/*` to `auth/api-key/*`. A 0.62 client gets an
  error when it creates, lists, or deletes an API key.
- The auth client holds one client per credential type: `client.auth.api_keys`
  (`apiKeys` in TypeScript), `client.auth.sessions`, `client.auth.passwords`, and, in
  TypeScript, `client.auth.oidc`. Python `create_key`, `retrieve_keys`, and
  `delete_keys` are now `api_keys.create`, `api_keys.retrieve`, and `api_keys.delete`,
  and `retrieve_sessions` and `delete_sessions` are now `sessions.retrieve` and
  `sessions.delete`. TypeScript moves `createKey`, `retrieveKeys`, `deleteKeys`,
  `retrieveSessions`, `deleteSessions`, `setPassword`, and the OpenID Connect link
  methods the same way.
