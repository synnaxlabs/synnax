### Client connections

The Python and TypeScript clients now choose their connection options in the same way.
See [Connect to a Core](/reference/client/connect).

- **One order for each option** -> each option comes from the argument, then its
  `SYNNAX_*` variable, then its default. `new Synnax({ host: "rig" })` with
  `SYNNAX_API_KEY` set uses that key, so the key stays out of your code.
- **Synnax Desktop from TypeScript** -> `new Synnax()` with no host connects to Synnax
  Desktop, as in Python. Each argument and variable overrides its field. In Deno, run
  with `--allow-sys=homedir --allow-read="$HOME/.synnax" --allow-run --allow-env`.
- **A private CA from TypeScript** -> give the PEM text of the CA certificate in
  `caCert`, or the path of the file in `SYNNAX_CA_CERT`. This works in Node.js and Bun.
  In Deno, start with `--cert <file>` or set `DENO_CERT`.
- **A private CA for the Driver** -> `synnax-driver login --ca-cert <file>` uses TLS
  with that CA and does not ask for `Secure`. See
  [login](/reference/enterprise/driver/cli-reference#login).
- **No tokens in stream URLs** -> in Node.js, Deno, and Bun, the TypeScript client sends
  its session token in the `Authorization` header. A browser sends it in the
  `Sec-WebSocket-Protocol` header.

### Breaking changes in 0.62

#### Clients

- Python: the client needs Python 3.13 or newer. On Python 3.12, `pip install -U synnax`
  keeps the 0.61 client and shows no error. Upgrade Python first.
- TypeScript: `@synnaxlabs/client`, `@synnaxlabs/x`, `@synnaxlabs/freighter`, and
  `@synnaxlabs/alamos` need Node.js 22.12 or newer. npm only shows a warning on an older
  version.
- Python: `sy login` is the only CLI command. `sy ingest`, `sy tsconvert`, and
  `sy check-timing` are removed, and so are the `synnax.io` and `synnax.ingest`
  packages.
- The schematic `*ElementConfig` types are removed. Use the `*NodeConfig` type of a
  symbol, such as `ValveNodeConfig` for `ValveElementConfig`, or the `*EdgeConfig` type
  of a connection, such as `PipeEdgeConfig`.
- The HTTP and MQTT modules no longer export `EnumEntry`, `TimeFormat`, `JSONType`, and
  `GeneratorType`. Import them from `payload`: `from x import payload` in Python, or
  `payload` from `@synnaxlabs/x` in TypeScript.

#### Records that the update deletes

The update to 0.62 deletes:

- every range alias
- every task snapshot, with its statuses and configuration
- every schematic snapshot
- every schematic, line plot, log, table, and panel that a range owns

`synnax update undo` puts back the metadata that the update backed up, these records
included. Metadata changes made after the update are lost. Telemetry stays. See
[go back to an earlier version](/reference/enterprise/upgrade#go-back-to-an-earlier-version).

The client APIs for these records are removed:

- Python: `Range.set_alias`, `Range.snapshots()`, `Channel.alias`, the `range_key`
  argument of `channels.retrieve`, the `snapshot` argument of `tasks.retrieve`, and the
  `snapshot` and `range_key` arguments of `tasks.copy`. `rng["tank_pt"]` and
  `rng.tank_pt` find channels by name only, not by alias.
- TypeScript: the `rangeKey` option of `channels.retrieve`, the alias methods of `Range`
  (`setAlias`, `deleteAlias`, `listAliases`, `resolveAlias`) and of `client.ranges`,
  `Channel.alias`, `Task.snapshot`, `Task.snapshottedTo()`, and the snapshot and range
  arguments of `tasks.copy`.

#### Colors

- Python and TypeScript: a color given as an array of numbers, such as a Python tuple or
  list, has an alpha from 0 to 255, not from 0 to 1. In Python, so does a dict or the
  `a` argument. `(255, 0, 0, 1)` is now almost transparent. Use `(255, 0, 0, 255)` or
  `(255, 0, 0)`. A fraction such as `0.5` is an error. CSS strings such as
  `rgba(255, 0, 0, 1)` still use 0 to 1. The update converts stored colors.
- TypeScript: a color object, such as `{ r, g, b, a }` or `{ rgba255 }`, is an error.
  Use an array or a string.
- Log channel, table cell, panel, and schematic colors are color references: a named
  color, `{ type: "named", key }`, or a fixed color, `{ type: "fixed", value }`. The
  update keeps each stored color as a fixed color. In a schematic, the strokes of
  valves, pumps, and other toggle, static, and light symbols, and the on, state, and
  staleness colors, stay color values.
- TypeScript: these colors hold a reference. Change `color: "#FF0000"` to
  `color: { type: "fixed", value: "#FF0000" }`.
- Python: these fields hold a `NamedRef` or a `FixedRef`:
  - `sy.log.ChannelEntry.color` and `sy.Panel.color`
  - the colors of `sy.table.TextCellConfig` and `sy.table.ValueCellConfig`
  - the stroke, fill, text, level, and axis colors of the schematic `*NodeConfig` and
    `*EdgeConfig` types, such as `TankNodeConfig.fill_color`

  Change `color="#FF0000"` to `color=sy.color.FixedRef(value="#FF0000")`.

#### Arc

- A unit literal keeps its number as written. Before, Arc converted it to the base unit.
  Next to a value with no unit, such as a channel value, `volts > 500mV` compares
  `volts` with 500, not 0.5. See [units](/reference/control/arc/reference/types#units).
- A sequence step that writes to a variable with `->`, such as
  `pressure > 100 -> ready`, completes on the first value, also when the value is false.
  Before, it waited for a true value. To wait for the condition, use `=>`. This sequence
  sets `vent_cmd` only after `pressure` is above 100:

  ```arc
  sequence fill {
      ready := false
      pressure > 100 => ready
      1 -> vent_cmd
  }
  ```

#### Streams

- Python and TypeScript: one write, which is one stream message, can be at most 256 MiB
  after encoding. The Core closes a stream that sends a larger message, with WebSocket
  close code 1009 (message too big). In TypeScript, the writer fails with
  `StreamClosed`. Split a large write into smaller writes. 0.61 had no limit.

#### Client connections

- A CA certificate with no `secure` turns TLS on, in all clients and the Driver. Before,
  the C++ client and the Driver connected without TLS, and Python raised `ValueError`.
- A CA certificate with `secure` set to false from the same source is an error, such as
  `SYNNAX_SECURE=false` with `SYNNAX_CA_CERT`. Remove one of the two.
- `secure` and the CA certificate come as a pair from the first source that sets one of
  them. `secure=True` with no CA certificate uses the CA certificates of the computer,
  even when `SYNNAX_CA_CERT` is set.
- Python: the `SYNNAX_*` variables fill each option that the arguments leave out, also
  when you give a host. Before, a host argument made the client ignore the variables.
  Unset the variables that point to a different Core.
- Python: the client gets the Synnax Desktop API key from its key helper, not from the
  keychain. Update Synnax Desktop and open it.
- Browser clients of 0.62 cannot stream from a 0.61 Core. Upgrade the Core with the
  client.
- Driver: `SYNNAX_DRIVER_SECURE` must be `true`, `false`, `1`, or `0`, in any case.
  Before, a different value, such as `yes`, gave the saved value. Now it is an error, as
  is an empty value. Unset the variable to use the saved value.
- TypeScript: the Freighter `HTTPClient` and `WebSocketClient` take one config object,
  such as `{ endpoint, codec, secure }`, in place of arguments in a fixed order.

#### Driver

- On macOS, when the Driver service is not installed, `sudo synnax-driver login`,
  `start --standalone`, and `clear` fail. They do not use the state directory in the
  home of the user that runs sudo. The error is "Run synnax-driver without sudo. Sudo is
  needed only while the Driver service is installed". `login` fails before it asks for
  the host or the credentials. Run these commands without sudo. On Linux and Windows,
  with the Driver service installed, or with `--state-file`, the commands do not change.
- `--enable-integrations` runs only the integrations it names, as it does on the Core.
  Before, it added them to the ones the Driver already ran. The Driver fails to start
  when `--enable-integrations` and `--disable-integrations` are both given.
- On NI Linux RT, installing the Driver sets `/var/log/synnax-driver.log` to mode
  `0644`, and installing or starting it sets the PID file to `0644` and its directory to
  `755`. Before, any local user could write them. `synnax-driver status` no longer
  writes to the log.

#### Core

- A Core that runs without its embedded Driver, with `--no-driver` or a build without
  the Driver, creates no rack for it. A rack from an earlier start stays with no
  integrations and shows "Driver disabled", and so do its tasks and devices. You can
  delete that rack. When the Driver runs again, the Core uses the stored rack or creates
  a new one.
- The Core fails to start when `--enable-integrations` and `--disable-integrations` are
  both given, also when one comes from a config file and the other from an environment
  variable. Before, it ran the enabled integrations and ignored the disabled list.

#### Scripts

- Python: a task with no rack and no device goes on the embedded rack that runs its
  integration, the part of its type before the first underscore. Before, it went on the
  first embedded rack, so a PagerDuty or Kafka task made this way never ran. With no
  such rack, the call raises `NotFoundError`. `tasks.list()` with no rack lists the
  tasks of every embedded rack, and `retrieve_embedded_rack` takes an integration.
