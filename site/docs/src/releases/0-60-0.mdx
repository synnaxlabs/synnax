Synnax v0.60 comes with Synnax Desktop 1.0: the Console, a Core, and a Driver in one
free app. Install it, log in, and record, plot, and control hardware in minutes.

Line plots now load only the tiles on screen, like a map, so a week of 1 kHz data opens

ten times faster.

A Core now needs a license from the Synnax portal. Read the
[breaking changes](#breaking-changes) before you upgrade.

### Synnax Desktop

<Image
  id="releases/0-60-0/desktop-graphic/d3be34cf37bd"
  extension="webp"
  themed={false}

Synnax Desktop is all of Synnax in one free app on your computer. The Console plots and
controls your system, a Core records its data, and a Driver reads and writes your
hardware. There is no server to set up, and your data stays on your computer.

Install it on macOS or Windows, log in with a free Synnax account, and connect a
LabJack, a Modbus server, or, on Windows, an NI device. No hardware yet? Select **Open
sample project**: an Arc sequence fills a simulated tank to 300 psi, holds it, and vents
it.

Synnax Desktop is for one person on one computer. For a team or for Linux, use
[Synnax Enterprise](/reference/get-started/editions). See
[Install Synnax Desktop](/reference/get-started/install-desktop).

### Tiled line plots

<Video id="releases/0-60-0/line-plots" />

A week of 1 kHz data is 600 million samples. Before, a line plot loaded all of them,
stayed blank until it finished, and drew only some. A one-sample spike showed only by
luck.

Now a line plot works like a map: it loads only the tiles on screen, at the detail of
your zoom. A tile holds the lowest and highest sample of each group of pixel columns, so
every spike is on screen, and each line gets a few thousand points for any range.

- **Zoom in** -> finer data loads, and the coarse data stays until it arrives. Zoom far
  enough to see single samples.
- **Pan past the range** -> the plot loads the data there. <Keys trigger={["Control",
  "MouseLeft"]} /> to go back.
- **Live data** -> streams at full rate and draws the same way as stored data.

For 10 lines of 1 kHz data, a frame of an hour view takes 0.6 ms of CPU time instead of
25 ms.

Two settings in the **Lines** tab replace downsampling:

| Setting     | Options                                                                          | Default |
| ----------- | -------------------------------------------------------------------------------- | ------- |
| Aggregation | **Min/max** draws the lowest and highest sample. **Average** draws the mean.     | Min/max |
| Detail      | **Low**, **Medium**, or **High**: one group per four, two, or one pixel columns. | Medium  |

Existing lines move to Min/max at Medium, or to Average if they had an averaging window.
See [Line plots](/reference/visualize/line-plots).

### Setpoints that show what the device reports

<Hero.Hero inset still="releases/0-60-0/read-back" layout="bleed" palette="blue-pink" />

Setpoint, Text input, and Select symbols now show the last command that anyone sent,
and, in a tray under it, the value the device reports: "I asked for 300 psi" and "the
regulator reads 287.4 psi" in one place. Before, after a reload or in a second Console,
the field showed a value that nobody sent.

**Set** stays blue until the command channel reports the new value, so a write that did
not land stays visible. To add the tray, set **Control** > **State** > **Channel**.

### EtherCAT that recovers on its own

Before, a slave that lost power kept recording its last values. The plot showed a flat
line that looked real, the device stayed green, and you restarted the task.

Now the plot shows a gap, the task shows "Failed to read data", and data resumes when
the slave answers again.

- **Live slave state** -> while a task runs, each slave shows its state, such as
  **Operational** or **Not responding**, in the Devices toolbar.
- **No bus restarts** -> starting or stopping a task no longer stops the others on the
  port.
- **The right entry** -> before, the eight inputs of an EL1008 all read input 1.
- **Better timestamps** -> each sample gets the time of its cycle, from the distributed
  clock when the slaves have one.
- **No root on Linux** -> run `sudo synnax-driver install` again.

See [EtherCAT](/reference/hardware/ethercat/configure-device).

### Faster exports, and TDMS files

Exports now run in the Core as one request. A CSV export of 10 million samples takes 1.8
seconds instead of 17.9. The clients also export TDMS files for NI DIAdem and LabVIEW:

```python
client.read_tdms(tr, ["time", "pressure"], "hotfire.tdms")
```

```typescript
const tdms = await client.readTDMS(tr, ["time", "pressure"]);
```

See [Read data](/reference/client/read-data).

### Sessions that you can end

Delete a user, and their Consoles, scripts, and streams stop at once. Before, their
token worked for up to 24 hours. A password change ends the user's other sessions, and
idle sessions end after 7 days
([`--session-idle-timeout`](/reference/enterprise/cli-reference#start)).

New passwords use Argon2id. The new `--fips` flag uses only PBKDF2, so with it on, users
with a password from v0.59 need a new one.

### A typed Python client

The Python client ships type information, so your editor shows real types and
`mypy --strict` checks your scripts against it. Before, mypy skipped the client. New
filters find resources without their names:

```python
client.channels.retrieve(search_term="pressure", data_types=[sy.DataType.FLOAT32])
client.tasks.retrieve(rack=rack.key, search_term="pump")
```

### Minor improvements and bug fixes

- Status messages now say what happened, and their description gives the cause and the
  fix.
- "Input" is now "Text input", and "String display" is now "Text display".
- Channel search finds every match. Before, it stopped at 100.
- Long recordings no longer draw float32, int32, or string samples at the wrong times
  after a file rollover.
- A rename changes only the name. Before, it could lose the resource's settings.
- The Modbus **Swap bytes** and **Swap words** settings now work.
- HTTP write tasks accept timestamp command channels.
- An Arc step whose last node has no outputs moves to the next step.
- The Python client refreshes expired tokens, and `ctrl.valve = 1` now writes.
- Security updates for wasmtime, open62541, and SOEM.

### Breaking changes

#### Licenses

- A Core without a license refuses every request except login and licensing, and the
  Console shows an activation screen. The 50-channel allowance of Core 0.59.2 is gone.
- The Core refuses the old numeric keys. Get a signed key from the Synnax portal.
- Activate each license before you upgrade. To get a Core 0.59 fingerprint, run "Show
  license info" in the Console. Core 0.60 migrates stored data, so you cannot go back to
  0.59. See [numeric license keys](/reference/enterprise/license#numeric-license-keys).
- A refused `--license-key` or `--license-file` no longer stops the Core. Check the log.
- In Docker, the license is bound to the container's MAC address. Set `--mac-address`
  and keep it the same. See [Docker](/reference/enterprise/license#docker).

#### Core and Console

- Upgrade the Console with the Core. An older Console shows errors instead of the
  activation screen, and cannot change table rows or columns.
- The Core refuses tokens from before the upgrade. Scripts that call the HTTP API with a
  saved token must log in again.
- Tasks, groups, roles, policies, and views need a name. The upgrade names any that have
  none.
- Status text changed. Update scripts that match it.

#### Hardware

- EtherCAT: a channel whose name matches several entries, such as "Input", stops its
  task with "Failed to configure task". Pick its entry in the task. Write task outputs
  go to zero when the task stops.
- Modbus: devices with **Swap bytes** or **Swap words** on now read in swapped order.
  Check their values after the upgrade.

#### Python client

- The client checks the Core's certificate and host name. For `--auto-cert` or your own
  CA, pass `ca_cert="/path/to/ca.crt"` or run `sy login` again.
- Names deprecated in 0.59 are removed: `*Chan` is now `*Channel`, names drop their
  module prefix (`channel.ChannelKey` is `channel.Key`), `synnax.hardware` moves to
  `synnax.ni` and its siblings, and `client.user` is `client.users`.
- `retrieve()` with no arguments on tasks, devices, and racks returns a list.
- `tasks.create()` needs a name, and `Synnax(cache_channels=...)` is removed.
- `open_iterator(downsample_factor=N)` is now `reduction=sy.StrideReduction(factor=N)`.
- `views.create()` takes a `sy.view.RangeView` or `sy.view.StatusView`.
- `Arc.status` is removed. Read the status of the Arc's task.
- EtherCAT `Automatic*Channel`, `Manual*Channel`, and `PDOAddress` are now
  `EntryReadChannel` and `EntryWriteChannel` with `ethercat.find_entry`.
- `TDMSReader` and the `nptdms` dependency are removed.
- Naive `pd.Timestamp` values are UTC, and bare numbers in `remains_true_for(duration=)`
  and `ScheduledCommand(delay=)` are seconds.
- `Bounds.contains` is half-open, `TimeRange` is frozen, and touching ranges no longer
  overlap.

#### TypeScript client

- `client.auth.user` and `retrieveUser()` are now `client.users.current`.
- `client.read({ responseType: "csv" })` is now `client.readCSV(tr, channels)`, with no
  `channelNames`.
- `openIterator(..., { downsampleFactor: N })` is now
  `{ reduction: { variant: "stride", factor: N } }`.
- `Arc.status` and the `includeStatus` option of `arcs.retrieve` are removed.
- `status.fromException(error, heading)` needs the heading.
- `setLineDownsample` and `setLineDownsampleMode` are now `setLineAggregation` and
  `setLineDetail`.
