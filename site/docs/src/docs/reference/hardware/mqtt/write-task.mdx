An MQTT write task publishes a message each time a value is written to a command
channel. Use it to send setpoints and commands to devices that listen on MQTT topics. It
can also command [Sparkplug B](/reference/hardware/mqtt/sparkplug#command-tags) tags.
Before you start, [connect an MQTT broker](/reference/hardware/mqtt/connect-broker).

The task has no state channels and no data saving option. To confirm a command, read the
value back from the device with a [read task](/reference/hardware/mqtt/read-task).

## Message formats

A plain target publishes the JSON payload of one message of an
[interface control document (ICD)](/reference/hardware/icds) to one topic. Each field of
the message sends a command from a command channel, a fixed value, or its
[default](/reference/hardware/icds/reference#defaults).

- **Commands** -> commands written at the same time go out in one payload. A field with
  no new command sends the last command of its channel.
- **First commands** -> the target sends nothing until each field with a channel and no
  default has a command.
- **Dropped commands** -> the task drops a command that its field cannot hold, such as
  NaN in a JSON number or a value outside the min and max of its field, and shows a
  warning.

For a message where `/position` has a command channel, `/source` has the fixed value
`synnax`, and `/id` has a random UUID default, a command of 42 publishes:

```json
{ "position": 42, "source": "synnax", "id": "6f1c2e3a-..." }
```

When you upgrade the Core, it moves the targets of each write task from an earlier
version into a new ICD named after the task, with one message for each target. A static
field becomes a fixed default, and a generated field becomes a current time or random
UUID default.

## Create an MQTT write task

<Client.Tabs exclude={["typescript"]}>
  <Fragment slot="console">

In the Console, a write task commands
[Sparkplug B tags](/reference/hardware/mqtt/sparkplug#command-tags). To publish an ICD
message to a plain topic, create the task in Python. The Console lists the plain targets
of a task with their topic settings.

1. In the devices toolbar, right-click the broker and select **Create write task**. You
   can also run the "Create MQTT write task" command.
2. Click **Add targets**. Select an edge node, then select the tags to command.
3. Click **Add** _N_ **targets**.
4. Click <Icon.Play /> (**Start**).

The Console creates a command channel for each target.

  </Fragment>
  <Fragment slot="python">

Python does not create channels. Create the command channel, its index, and the ICD
first.

```python
import synnax as sy
from synnax import mqtt

broker = client.devices.retrieve(name="Plant broker")
cmd_time = client.channels.create(
    name="valve1_cmd_time", is_index=True, data_type=sy.DataType.TIMESTAMP
)
cmd = client.channels.create(
    name="valve1_cmd", index=cmd_time.key, data_type=sy.DataType.FLOAT64
)

position = sy.icd.FloatJSONField(name="position", pointer="/position")
source = sy.icd.StringJSONField(name="source", pointer="/source")
id_field = sy.icd.UuidJSONField(
    name="id", pointer="/id", default=sy.icd.RandomUUIDDefault()
)
command = sy.icd.Message(
    name="plant/valve1/set",
    payload=sy.icd.JSONPayload(fields=[position, source, id_field]),
)
valve1 = client.icds.create(name="Valve 1", messages=[command])

task = mqtt.WriteTask(
    name="Valve 1 commands",
    device=broker.key,
    targets=[
        mqtt.PlainWriteTarget(
            topic="plant/valve1/set",
            icd=valve1.key,
            message=sy.icd.WriteMessage(
                message=command.key,
                bindings=[
                    sy.icd.ChannelWriteBinding(field=position.key, channel=cmd.key),
                    sy.icd.ValueWriteBinding(
                        field=source.key,
                        value=sy.icd.StringWriteValue(value="synnax"),
                    ),
                ],
            ),
        )
    ],
)
client.tasks.configure(task)
task.start()
```

## When the broker is down

The task never holds a command back for later. If the broker is not connected when a
command arrives, the task drops the command and shows a warning. A command that waited
out an outage would reach the device long after the operator sent it, which is not safe.
The warning also shows while no command arrives, so you can see the outage before you
send one.

## Target reference

A plain target has these settings:

| Setting                                 | Default       | Notes                                                      |
| --------------------------------------- | ------------- | ---------------------------------------------------------- |
| Topic <small>`topic`</small>            |               | The topic to publish to. No wildcards.                     |
| Quality of service <small>`qos`</small> | At least once | At most once (0), at least once (1), or exactly once (2).  |
| Retain <small>`retained`</small>        | Off           | Asks the broker to keep the message for later subscribers. |
| ICD <small>`icd`</small>                |               | The ICD that holds the message.                            |
| Message <small>`message`</small>        |               | The message to publish, and the bindings of its fields.    |

A binding fills one field of the message from a command channel or a fixed value:

| Setting                          | Default | Notes                                                               |
| -------------------------------- | ------- | ------------------------------------------------------------------- |
| Kind <small>`type`</small>       |         | `channel` or `value`.                                               |
| Field <small>`field`</small>     |         | The field to fill.                                                  |
| Channel <small>`channel`</small> |         | Channel bindings only. The command channel whose commands it sends. |
| Value <small>`value`</small>     |         | Value bindings only. The fixed value that it sends.                 |

In code, a plain target is `PlainWriteTarget`, and its message is `icd.WriteMessage`. A
binding to a command channel is `icd.ChannelWriteBinding`, and a binding to a fixed
value is `icd.ValueWriteBinding`.

## Troubleshooting

<Problem.List>

<Problem.Item message={"broker is not connected"}>
<Problem.Cause>

The connection to the broker is down, so the task drops each command that arrives. The
Core connects again on its own, and the warning clears when the connection returns.

</Problem.Cause>
</Problem.Item>

<Problem.Item message={"targets: the task has no enabled targets"}>
<Problem.Cause>

The task has no targets, or each target is disabled.

</Problem.Cause>
<Problem.Fix>

Add a target, or enable one.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"target ...: channel ... does not exist"}>
<Problem.Cause>

The command channel of a target was deleted, or a channel binding of a plain target has
no channel (`channel` is 0).

</Problem.Cause>
<Problem.Fix>

For a Sparkplug B tag, remove the target, then add it again with **Add targets**. The
Console creates a new command channel when you start the task.

For a plain target, start the task in the Console. The Console creates a command channel
for each binding that has no channel, or whose channel was deleted.

</Problem.Fix>
</Problem.Item>

<Problem.Item
  message={[
    "field ...: ... is below the min ...",
    "field ...: ... is above the max ...",
    "field ...: ... decodes to ..., which is below the min ...",
    "field ...: ... decodes to ..., which is above the max ...",
  ]}
>
<Problem.Cause>

A fixed value of a plain target, or the default of a field in the ICD, is outside the
min and max of the field after the scale and offset of the field.

</Problem.Cause>
<Problem.Fix>

Change the fixed value or the default, or change the min or the max of the field in the
ICD.

</Problem.Fix>
</Problem.Item>

</Problem.List>

For problems with the connection, see
[Connect an MQTT broker](/reference/hardware/mqtt/connect-broker#troubleshooting).
