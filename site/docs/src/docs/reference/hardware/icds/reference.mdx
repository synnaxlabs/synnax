their fields, for each message format. It also lists the problems that a check of an ICD
finds.

<Field.Item

### Messages

<Field.List>

<Field.Item id="message-name" label="Name" field="name" type="string" required>
  The name of the message. It is unique in its ICD.
</Field.Item>

<Field.Item
  label="Format"
  field={{ py: "payload", ts: "payload.format" }}
  type="string"
  required
>
  The format of the payload: **JSON**, **Text**, or **Binary**. In Python, the class of
  the payload sets the format: `JSONPayload`, `TextPayload`, or `BinaryPayload`. In
  TypeScript, `format` is `"json"`, `"text"`, or `"binary"`.
</Field.Item>

</Field.List>

### Fields

<Field.List>

<Field.Item id="field-name" label="Name" field="name" type="string" required>
  The name of the field. It is unique in its message. The Console names a new channel
  after it.
</Field.Item>

<Field.Item label="Scale" field="scale" type="number" default="1">
  Multiplies the raw value. It cannot be 0. Only a number field can scale: a binary or
  text field, or a JSON field of a number type. A scaled JSON field needs a float
  channel.
</Field.Item>

<Field.Item label="Offset" field="offset" type="number" default="0">
  Added to the value after the scale. Only a number field can have an offset, and a JSON
  field with an offset needs a float channel.
</Field.Item>

<Field.Item label="Units" field="units" type="string" default='""'>
  The engineering unit of the value, such as `°C`.
</Field.Item>

<Field.Item label="Min" field="min" type="number">
  The smallest value that a write task accepts. Empty leaves the limit to the bits or
  the type of the field. Only a number field can have a min. The Console does not show
  it.
</Field.Item>

<Field.Item label="Max" field="max" type="number">
  The largest value that a write task accepts. It cannot be less than the min. Empty
  leaves the limit to the bits or the type of the field. Only a number field can have a
  max. The Console does not show it.
</Field.Item>

</Field.List>

A JSON message reads one JSON document. An
[MQTT read task](/reference/hardware/mqtt/read-task) reads JSON messages.

### JSON message properties

<Field.List>

<Field.Item label="Match" field="match" type="match rule">
  The rule that selects the documents of the message. **Any document** sets no rule. See
  [match rules](#match-rules).
</Field.Item>

<Field.Item
  id="json-message-fields"
  label="Fields"
  field="fields"
  type="list of JSON fields"
  default="[]"
>
  The values that the document carries.
</Field.Item>

</Field.List>

### JSON field properties

In the Console, the **Options** column of a field opens its **Optional**, **Default**,
and **Enum mapping** settings.

<Field.List>

<Field.Item label="Pointer" field="pointer" type="string" default='""'>
  The [JSON pointer](https://datatracker.ietf.org/doc/html/rfc6901) to the value, such
  as `/motor/speed`. An empty pointer reads the whole document, such as a bare `42.7`. A
  bytes field needs a pointer. Two fields of a message cannot read the same value, and
  one field cannot read a value inside the value of another.
</Field.Item>

<Field.Item label="Type" field="type" type="string" required>
  The type of the value. See [types](#types).
</Field.Item>

<Field.Item
  label="Time format"
  field={{ py: "time_format", ts: "timeFormat" }}
  console="Type"
  type="string"
>
  The encoding of a timestamp: `iso8601`, `unix_sec`, `unix_ms`, `unix_us`, or
  `unix_ns`. The Console sets it with the type, such as **Timestamp (ms)**.
</Field.Item>

<Field.Item label="Default" field="default" console="Optional, Default">
  The value that the task writes when the document has no value. See
  [defaults](#defaults).
</Field.Item>

<Field.Item
  label="Enum mapping"
  field={{ py: "enum_values", ts: "enumValues" }}
  type="list of entries"
  default="[]"
>
  Maps text labels in the document to values. See [enum values](#enum-values).
</Field.Item>

</Field.List>

### Types

| Type                                           | Python class         | New channel | Notes                                            |
| ---------------------------------------------- | -------------------- | ----------- | ------------------------------------------------ |
| Float                                          | `FloatJSONField`     | `float64`   | A number.                                        |
| Signed integer                                 | `IntegerJSONField`   | `int64`     | An integer.                                      |
| Unsigned integer                               | `UnsignedJSONField`  | `uint64`    | An integer of 0 or more.                         |
| Boolean                                        | `BooleanJSONField`   | `uint8`     | `true` or `false`, as 1 or 0. Not a number.      |
| String                                         | `StringJSONField`    | `string`    | A string.                                        |
| JSON                                           | `JSONJSONField`      | `json`      | Any JSON value.                                  |
| UUID                                           | `UuidJSONField`      | `uuid`      | A UUID in a string.                              |
| Bytes (base64)                                 | `BytesJSONField`     | `bytes`     | Base64 text in a string. Needs a pointer.        |
| Timestamp (ISO 8601), (s), (ms), (µs), or (ns) | `TimestampJSONField` | `timestamp` | ISO 8601 text, or Unix time in s, ms, µs, or ns. |

In TypeScript, the `type` of a field is `"float"`, `"integer"`, `"unsigned"`,
`"boolean"`, `"string"`, `"json"`, `"uuid"`, `"bytes"`, or `"timestamp"`.

The **New channel** column gives the data type of a channel that the Console creates for
the field. A float channel also reads signed integer, unsigned integer, and boolean
fields. A signed integer channel also reads unsigned integer and boolean fields, and an
unsigned integer channel also reads boolean fields. The **Data type** menu of a task
lists only the data types that fit.

### Match rules

A topic can carry more than one kind of document. A match rule selects the documents of
a message by the value at one pointer.

<Field.List>

<Field.Item id="match-type" label="Type" field="type" console="Match" type="string">
  The type of the value: **String**, **Signed integer**, **Unsigned integer**,
  **Float**, or **Boolean**. In Python, the class sets the type, such as
  `StringJSONMatch`.
</Field.Item>

<Field.Item id="match-pointer" label="Pointer" field="pointer" type="string">
  The JSON pointer to the value that the rule tests, such as `/type`.
</Field.Item>

<Field.Item id="match-value" label="Value" field="value" required>
  The value that the document must hold at the pointer, such as `status`. A float value
  must be finite.
</Field.Item>

</Field.List>

When a task reads more than one message from a topic:

- **One pointer** -> every rule tests the same pointer.
- **One message for each value** -> two messages cannot match the same value.
- **One message with no rule** -> at most one message has no rule. It reads each
  document that matches no rule.
- **No match** -> the task skips a document that matches no message.

### Defaults

A field of type Float, Signed integer, Unsigned integer, String, Boolean, or Timestamp
can have a default. The task writes the default when the document has no value at the
pointer of the field:

- The document has no value at the pointer.
- The value is `null`, and the channel is not a `json` channel.
- The value is an empty string, and the channel is not a `string`, `bytes`, or `json`
  channel.

The scale and offset apply to a number default. When a field that a task reads has no
default, the task skips each document that has no value for the field.

To set a default in the Console, open the **Options** of the field and select
**Optional**. The Console shows the default of a timestamp field and can remove it, but
only code can set it.

### Enum values

Enum values map text labels in the document to values of the field's type, such as `ON`
to 1 and `OFF` to 0. A field of type Float, Signed integer, Unsigned integer, String, or
Boolean can have enum values. When the document holds a label, the task writes its
value. The scale and offset do not apply to the value.

Each entry has a `label` and a `value`. Each label must be unique in its field, and it
cannot be empty. To add an entry in the Console, open the **Options** of the field and
click **Add mapping**.

## Text messages

A text message reads one line of text.

### Text message properties

<Field.List>

<Field.Item label="Prefix" field="prefix" type="string" default='""'>
  The text that a line starts with to belong to the message. An empty prefix matches
  each line.
</Field.Item>

<Field.Item label="Delimiter" field="delimiter" type="string" default='","'>
  The text that splits a line into items. It cannot be empty.
</Field.Item>

<Field.Item
  id="text-message-fields"
  label="Fields"
  field="fields"
  type="list of text fields"
  default="[]"
>
  The values that the line carries.
</Field.Item>

</Field.List>

### Text field properties

A text field is delimited or tagged. The Console lists them in **Delimited fields** and
**Tagged fields**. In Python, the class is `DelimitedTextField` or `TaggedTextField`. In
TypeScript, `encoding` is `"delimited"` or `"tagged"`.

<Field.List>

<Field.Item label="Position" field="position" type="number" default="0">
  For a delimited field: the index of the item, from 0, after the line is split on the
  delimiter. In `oven,21.4`, position 1 is `21.4`.
</Field.Item>

<Field.Item label="Tag" field="tag" type="string" required>
  For a tagged field: the text that comes just before the value, such as `T=` in
  `T=21.4`.
</Field.Item>

</Field.List>

## Binary messages

A binary message reads the bytes of one frame, such as a CAN frame.

### Binary message properties

<Field.List>

<Field.Item label="Length" field="length" type="number">
  The length of the payload in bytes. Empty means that the length can change. A CAN
  frame carries at most 8 bytes, and a CAN FD frame at most 64.
</Field.Item>

<Field.Item label="Identifier" field="identifier" type="identifier">
  Selects the frames that belong to the message: by **CAN** identifier, or by **Field
  value**. **None** sets no identifier, and each frame belongs to the message.
</Field.Item>

<Field.Item
  id="binary-message-fields"
  label="Fields"
  field="fields"
  type="list of binary fields"
  default="[]"
>
  The values that the frame carries.
</Field.Item>

</Field.List>

A **CAN** identifier has these properties. In Python, the class is `CanIdentifier`.

<Field.List>

<Field.Item label="ID" field="id" type="number" default="0">
  The CAN arbitration identifier. It is at most `0x7FF`, or `0x1FFFFFFF` for an extended
  identifier.
</Field.Item>

<Field.Item label="Mask" field="mask" type="number">
  A bit mask that applies to both identifiers before they are compared. Empty compares
  them exactly.
</Field.Item>

<Field.Item label="Extended ID" field="extended" type="boolean" default="false">
  `true` for a 29-bit extended identifier.
</Field.Item>

<Field.Item label="CAN FD" field="fd" type="boolean" default="false">
  `true` when the message is sent as a CAN FD frame.
</Field.Item>

<Field.Item
  label="Bitrate switch"
  field={{ py: "bitrate_switched", ts: "bitrateSwitched" }}
  type="boolean"
  default="false"
>
  `true` when a CAN FD frame switches to the data bitrate. Only a CAN FD frame can
  switch.
</Field.Item>

</Field.List>

A **Field value** identifier has these properties. In Python, the class is
`FieldIdentifier`.

<Field.List>

<Field.Item id="identifier-field" label="Field" field="field" type="field key" required>
  The integer field of the message that holds the identifier.
</Field.Item>

<Field.Item id="identifier-value" label="Value" field="value" type="number" default="0">
  The raw value that the field must hold.
</Field.Item>

</Field.List>

### Binary field properties

In Python, a binary field is a `BinaryField`.

<Field.List>

<Field.Item
  label="Start bit"
  field={{ py: "start_bit", ts: "startBit" }}
  type="number"
  default="0"
>
  The bit where the field starts, numbered as in a DBC file: the least significant bit
  for a little endian field, and the most significant bit for a big endian field.
</Field.Item>

<Field.Item
  label="Bit length"
  field={{ py: "bit_length", ts: "bitLength" }}
  type="number"
  default="8"
>
  The number of bits in the field, from 1 to 64. A float field has 32 or 64 bits.
</Field.Item>

<Field.Item
  label="Byte order"
  field={{ py: "byte_order", ts: "byteOrder" }}
  type="string"
  default="little_endian"
>
  **Little endian** (`little_endian`) or **Big endian** (`big_endian`).
</Field.Item>

<Field.Item id="binary-type" label="Type" field="kind" type="string" default="unsigned">
  The type of the raw bits: **Unsigned integer** (`unsigned`), **Signed integer**
  (`integer`), or **Float** (`float`).
</Field.Item>

<Field.Item label="Multiplexor" field="multiplexor" type="field key">
  The integer field that selects whether this field is in the frame. Empty means that
  the field is always in the frame.
</Field.Item>

<Field.Item
  label="Multiplex values"
  field={{ py: "multiplex_values", ts: "multiplexValues" }}
  type="list of numbers"
  default="[]"
>
  The raw values of the multiplexor for which the field is in the frame. A field with a
  multiplexor needs at least one value.
</Field.Item>

</Field.List>

Two fields cannot use the same bits, unless their multiplex values keep them out of the
same frame.

## Problems

A check of an ICD finds these problems. A problem under [Properties](#properties) breaks
a rule of the ICD's schema, and Synnax does not save the ICD. The other problems do not
stop a save. The ICD editor marks each problem on its property shortly after an edit. In
code, `client.icds.check` returns the problems of an ICD.

### Properties

<Problem.List>

<Problem.Item message={["name is required", "delimiter is required"]}>
  <Problem.Cause>A required property is empty.</Problem.Cause>
  <Problem.Fix>Give the property a value.</Problem.Fix>
</Problem.Item>

<Problem.Item
  message={[
    "bit length must be less than or equal to 64",
    "bit length must be greater than or equal to 1",
  ]}
>
  <Problem.Cause>A property is out of its range.</Problem.Cause>
  <Problem.Fix>Change the value to one in the range.</Problem.Fix>
</Problem.Item>

<Problem.Item message={["byte order is not valid", "time format is not valid"]}>
  <Problem.Cause>
    A property holds a value that this page does not list for it. Only code can set such
    a value.
  </Problem.Cause>
  <Problem.Fix>Set one of the values that this page lists.</Problem.Fix>
</Problem.Item>

</Problem.List>

### Names and keys

<Problem.List>

<Problem.Item
  message={['duplicate message name "<name>"', 'duplicate field name "<name>"']}

    Two messages of the ICD, or two fields of a message, have the same name.
  </Problem.Cause>
  <Problem.Fix>Rename one of them.</Problem.Fix>
</Problem.Item>

<Problem.Item message={["duplicate message key <key>", "duplicate field key <key>"]}>

### Match rules on a topic

These errors come from the [match rules](#match-rules) of the messages that one topic
reads. A task gives the first three when it deploys, and it does not start. It gives the
last one while it runs, and it skips the document.

<Problem.List>

<Problem.Item message={"messages <a> and <b> both have no match rule"}>
  <Problem.Cause>Two messages of the topic have no rule.</Problem.Cause>
  <Problem.Fix>Give one of the messages a match rule.</Problem.Fix>
</Problem.Item>

<Problem.Item
  message={'messages <a> and <b> match at different pointers "<p>" and "<q>"'}
>
  <Problem.Cause>The rules of two messages test different pointers.</Problem.Cause>
  <Problem.Fix>Give each rule of the topic the same pointer.</Problem.Fix>
</Problem.Item>

<Problem.Item message={"messages <a> and <b> match the same value <value>"}>
  <Problem.Cause>The rules of two messages test for the same value.</Problem.Cause>
  <Problem.Fix>Change the value of one rule.</Problem.Fix>
</Problem.Item>

<Problem.Item message={"the payload matches no message"}>
  <Problem.Cause>
    A document arrived that matches no rule, and each message of the topic has a rule.
  </Problem.Cause>
  <Problem.Fix>
    Add a message for the document, or remove the rule of one message so that it reads
    the documents that match no rule.
  </Problem.Fix>
</Problem.Item>

</Problem.List>
