An HTTP write task sends a request to a web API each time you write a value to a command
channel. For example, a valve on a schematic can send `{"open": 1}` to a pump
controller.

The task has no state channels. To see the value on the server, read it back with an
[HTTP read task](/reference/hardware/http/read-task). Before you start, you need a
[connected HTTP server](/reference/hardware/http/connect-server).

## Request body

The body of each endpoint is the JSON payload of one message of an
[interface control document (ICD)](/reference/hardware/icds). Each field of the message
sends a command from a command channel, a fixed value, or its
[default](/reference/hardware/icds/reference#defaults).

- **Commands** -> request 1 holds the first new command of each channel of the message,
  request 2 holds the second, and so on, in order. So commands to two fields in one
  write go in one request. A field with no new command sends the last command of its
  channel.
- **First commands** -> the endpoint sends nothing until each field with a channel and
  no default has a command.
- **Dropped commands** -> the task drops a command that its field cannot hold, such as
  NaN in a JSON number, and shows a warning.

For a message where `/setpoint` has a command channel, `/unit` has the fixed value
`psi`, and `/id` has a random UUID default, a command of 42 sends this body:

```json
{ "setpoint": 42, "unit": "psi", "id": "6f1c2e3a-..." }
```

When you upgrade the Core, it moves the body of each endpoint of a write task from an
earlier version into a new ICD named after the task. Each endpoint gets one message,
named after its method and path. A static field becomes a fixed default, and a generated
field becomes a current time or random UUID default. A channel with an empty pointer
becomes the one field of its message, so the body is still the value alone.

## Create an HTTP write task

<Client.Tabs>
  <Fragment slot="console">

1. In the devices toolbar, right-click the server and select **Create write task**. You
   can also run the "Create HTTP write task" command.
2. Click **Add endpoint**, then set **Method** (POST, PUT, or PATCH) and **Path**.
3. Click **Add field** for each value in the body, then set its **Name**, **Pointer**,
   and **Type**.
4. A new field sends the commands of a channel. To send a fixed value, select **Value**.
5. Click <Icon.Play /> (**Start**).

The first endpoint creates an ICD named after the task, and each new endpoint adds a
message to it. To send a message of another ICD, select it in **Message format**.

When you start the task, the Console creates a command channel for each field that sends
commands. For a server named "Pump controller", the path `/api/control`, and the field
`setpoint`, it creates `Pump_controller_api_control_setpoint_cmd` and its index
`Pump_controller_api_control_setpoint_cmd_time`. Two endpoints share a command channel
when they send the same field of the same ICD message to the same method and path, in
one task or several. To rename a channel, edit **Channel** after you start.

  </Fragment>
  <Fragment slot="python">

Python does not create channels. Create the command channel, its index, and the ICD
first.

```python
import synnax as sy
from synnax import http

server = client.devices.retrieve(name="Pump controller")
cmd_time = client.channels.create(
    name="pump_setpoint_cmd_time", is_index=True, data_type=sy.DataType.TIMESTAMP
)
cmd = client.channels.create(
    name="pump_setpoint_cmd", index=cmd_time.key, data_type=sy.DataType.FLOAT64
)

setpoint = sy.icd.FloatJSONField(name="setpoint", pointer="/setpoint")
unit = sy.icd.StringJSONField(name="unit", pointer="/unit")
control = sy.icd.Message(
    name="POST /api/control",
    payload=sy.icd.JSONPayload(fields=[setpoint, unit]),
)
pump = client.icds.create(name="Pump controller", messages=[control])

task = http.WriteTask(
    name="Pump controller write",
    device=server.key,
    endpoints=[
        http.WriteEndpoint(
            method="POST",
            path="/api/control",
            icd=pump.key,
            message=sy.icd.WriteMessage(
                message=control.key,
                bindings=[
                    sy.icd.ChannelWriteBinding(field=setpoint.key, channel=cmd.key),
                    sy.icd.ValueWriteBinding(
                        field=unit.key, value=sy.icd.StringWriteValue(value="psi")
                    ),
                ],
            ),
        )
    ],
)
client.tasks.configure(task)
task.start()
```

TypeScript does not create channels. Create the command channel, its index, and the ICD
first.

```typescript
import { http, icd } from "@synnaxlabs/client";

const [server] = await client.devices.retrieve({
  where: { name: { eq: "Pump controller" } },
});
const cmdTime = await client.channels.create({
  name: "pump_setpoint_cmd_time",
  isIndex: true,
  dataType: "timestamp",
});
const cmd = await client.channels.create({
  name: "pump_setpoint_cmd",
  index: cmdTime.key,
  dataType: "float64",
});

const setpoint = icd.floatJSONFieldZ.parse({
  type: "float",
  name: "setpoint",
  pointer: "/setpoint",
});
const unit = icd.stringJSONFieldZ.parse({
  type: "string",
  name: "unit",
  pointer: "/unit",
});
const control = icd.messageZ.parse({
  name: "POST /api/control",
  payload: { format: "json", fields: [setpoint, unit] },
});
const pump = await client.icds.create({
  name: "Pump controller",
  messages: [control],
});

const task = await client.tasks.create({
  name: "Pump controller write",
  rack: server.rack,
  type: "http_write",
  config: http.writeConfigZ.parse({
    device: server.key,
    endpoints: [
      {
        method: "POST",
        path: "/api/control",
        icd: pump.key,
        message: {
          message: control.key,
          bindings: [
            { type: "channel", field: setpoint.key, channel: cmd.key },
            {
              type: "value",
              field: unit.key,
              value: { type: "string", value: "psi" },
            },
          ],
        },
      },
    ],
  }),
});
await task.start();
```

## Endpoint reference

Each table shows the Console label of a setting, with its Python field under it. An
endpoint has these settings:

| Setting                                        | Default | Notes                                                |
| ---------------------------------------------- | ------- | ---------------------------------------------------- |
| Method <small>`method`</small>                 | `POST`  | `POST`, `PUT`, or `PATCH` in the Console.            |
| Path <small>`path`</small>                     |         | Added to the base address of the server.             |
| Query parameters <small>`query_params`</small> | None    | A list of `{parameter, value}`.                      |
| Headers <small>`headers`</small>               | None    | A list of `{name, value}`.                           |
| <small>`disabled`</small>                      | `false` | Leaves the endpoint out of the task.                 |
| Message format <small>`icd`</small>            |         | The ICD that holds the message.                      |
| <small>`message`</small>                       |         | The message to send, and the bindings of its fields. |

A binding fills one field of the message from a command channel or a fixed value. A
field with no binding sends its default.

| Setting                          | Default | Notes                                                               |
| -------------------------------- | ------- | ------------------------------------------------------------------- |
| <small>`type`</small>            |         | `channel` or `value`. **Channel** or **Value** in the Console.      |
| <small>`field`</small>           |         | The field to fill.                                                  |
| Channel <small>`channel`</small> |         | Channel bindings only. The command channel whose commands it sends. |
| <small>`value`</small>           |         | Value bindings only. The fixed value that it sends.                 |

In code, a binding to a command channel is `icd.ChannelWriteBinding`, and a binding to a
fixed value is `icd.ValueWriteBinding`.

## Troubleshooting

<Problem.List>

<Problem.Item message={"Failed to write commands"}>
<Problem.Cause>

A request failed. The description shows the method and the address of each failed
request, and the status code and the response body if the server answered. The task
drops the later commands of that endpoint in the same write. The other endpoints still
send their commands.

- **No answer, or 408, 429, or a 5xx code** -> the task waits, then goes on with the
  next write. The wait pauses all endpoints of the task. After 50 failures in a row, the
  task stops.
- **Other codes, such as a 4xx code** -> the task stops after the other endpoints send
  their commands.

</Problem.Cause>
<Problem.Fix>

Make sure that the server is running and that the Driver can reach it. For a 4xx code,
check the path, the message, and the authentication of the server. Then start the task
again.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"endpoint ... sends no message"}>
<Problem.Cause>

An endpoint has no ICD message, such as an endpoint made in code without `icd` and
`message`. The task does not start.

</Problem.Cause>
<Problem.Fix>

Open the task, select the endpoint, and select a message in **Message format**. In code,
set `icd` and `message` on the endpoint.

</Problem.Fix>
</Problem.Item>

<Problem.Item message={"Skipped invalid command"}>
<Problem.Cause>

A field cannot hold a command, such as NaN in a JSON number. The description names the
endpoint, the message, and the field. The field keeps its last good command.

</Problem.Cause>
<Problem.Fix>

Write a value that the field can hold, or change the type of the field in the ICD.

</Problem.Fix>
</Problem.Item>

</Problem.List>

For problems with a message or its fields, see
[ICD problems](/reference/hardware/icds/reference#problems). For other problems, see
[Troubleshoot hardware](/reference/hardware/troubleshooting).
